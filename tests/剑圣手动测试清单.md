> 自动化已覆盖的部分见 `tests/test_swordsman_resources.gd`（批次1, 75 断言）与
> `tests/test_swordsman_integration.gd`（批次2, 24 断言）。运行：
> `<Godot_console.exe> --headless --path <项目> --script res://tests/<文件>`，退出码 0 = 全过。

> headless 测不了的原因：① 无渲染（动画/飘字/颜色看不到）② MCP 不支持鼠标注入（全游戏鼠标驱动，无法自动点击棋盘/技能）③ 平衡“手感”需人判。

## 一、视觉 / 动画 / 颜色（需开编辑器运行 + 人眼看）

- [ ] 仪表盘剑气行：选中剑圣时显示「剑气 N/10」+「印 心 道 势」，非剑圣单位整行隐藏。
- [ ] 印记颜色：持有印记金色 `(0.88,0.75,0.28)`、未持有灰色 `(0.45,0.46,0.50)`，随获得/清空实时变色。
- [ ] 剑气数值随技能产出/消耗实时刷新（斩击命中 +1、一闪/招架 -1、居合 -6 等）。
- [ ] 槽位替换视觉：满 3 印记时招架槽位**图标/文字变为拔刀**；施放拔刀后变回招架。（逻辑已自动验证，UI 渲染需看）
- [ ] 技能动画表现：斩击、一闪（位移）、居合、拔刀的视觉/打击感。
- [ ] 伤害/命中/暴击飘字（DamagePopup）：居合必暴时是否有暴击表现。
- [ ] 主属性面板（本次修复）：选不同单位时 STR/MAG/DEX/SPD/DEF/RES/LCK/MOV 显示**基础值 + 括号加成**（如剑圣持印记时 `DEX 9 (+2)`、剑气≥7 时 `SPD 8 (+1)`），无加成时只显示基础值。

## 二、交互流程 / 手感（MCP 无鼠标，必须人工点）

- [ ] **完整施放链路**：选剑圣 → 移动 → 选技能 → 选目标 → 结算。重点确认 **施放扣气端到端**（`_execute_skill_action` 全链路；自动化只验了门槛读取 + 扣减原语 + 命中/击杀结算）。
- [ ] 斩击命中后剑气 +1 在实战链路里生效（自动化已验 `_apply_sword_qi_on_hit`，端到端再确认一次）。
- [ ] 居合：消耗 6 气、必中必暴、击杀返 3 气 + 本技能 cd-1、结算得 1 印记 —— 实战连贯体验。
- [ ] 满 3 印记 → 点击招架槽实际发动**拔刀**（180% + 暴击 3.0x），施放后印记清空、槽位变回招架。
- [ ] 技能不可用态：剑气不足/印记不足时按钮禁用 + 提示文案（“剑气不足（需要 X，当前 Y）”“印记不足…”）正确显示。
- [ ] 一闪位移：当前为直线区域近似，**完整位移行为待引擎扩展**——确认现状是否可接受。

## 三、多回合 / AI / 数值平衡（headless 能跑但需长时间观察 + 人判“手感”）

- [ ] 剑气积累节奏：多回合下攒气/用气的循环是否顺手（避免“攒满再打”单一路线）。
- [ ] 心眼速度 +1（剑气≥7）对出手序的实际影响。
- [ ] 印记 +2 属性在实战中的强度体感。
- [ ] 敌方 AI 面对剑圣的行为是否合理。
- [ ] **占位数值手感调**（均在 JSON，改完重跑上面自动化测试即可保证不破坏逻辑）：
  - 印记属性：`swordsman.json` `mark_dex_bonus/mark_lck_bonus/mark_str_bonus = 2`
  - 心眼：`crit_per_qi=1`、`speed_threshold=7`、`speed_bonus=1`
  - 技能气耗：斩击 +1 / 一闪 -1 / 招架 -1 / 居合 -6 返 3 / 拔刀 -2 + 3 印记
  - 拔刀暴击：`crit_damage_bonus=1.5`（→ 3.0x，用户已确认）

## 四、拍板结果（已落实）

1. ✅ **拔刀暴击 3.0x**：用户确认 1.5x 是暴击倍率**初始值**而非上限；拔刀让该次暴击倍率达 300%。已改 `crit_damage_bonus=0.5→1.5`（基础 1.5x + 1.5 = 3.0x）。纯伤害暴击仍固定 1.5x（不吃加成）。
2. ✅ **槽位替换改读 JSON**：`get_visible_skill_id` 不再硬编码技能 ID，改由技能 JSON 的 `slot_swap_trigger`/`slot_swap_target` 驱动（`tactical_manager` 读 JSON 后传入）。为后期多种技能替换 / 印记改写天赋预留柔性。
3. ✅ **主属性面板 = 基础值 + 括号加成**：已改为显示基础值，有加成时附 `(+N)`（印记/心眼/buff 增量）。

### 已顺手优化（已落实）
- ✅ **`mark_cost` 改按量扣减**：`spend_marks(mark_cost)`（默认按印记字典顺序 心→道→势 扣减），不再 `clear_marks()` 全清；拔刀（cost 3）行为不变，为将来部分消耗预留。
- ✅ **印记上限改 JSON 配置**：`swordsman.json` 加 `mark_max`（默认=印记类型数），`is_marks_full` 不再硬编码 3。
