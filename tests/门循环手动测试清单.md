# 门循环手动测试清单（run-loop v0，任务 #6 + #8 Prep）

面向 headless 测不到的像素交互项。逻辑层由 `tests/test_run_scene_flow.gd`（69 断言）、
`tests/test_tactical_inject_smoke.gd`（20 断言，含 HP 继承注入）、
`tests/test_prep_flow.gd`（42 断言：恢复 / HP 继承 / 运输队）、
`tests/test_event_resolver.gd`（61 断言：事件加载 / 各 effect 应用 / 加权抽 outcome / 伏击波次）
覆盖，本清单只列人工目视/点击验证项。

## 前置

- 用 Godot 4.6 编辑器打开项目，运行场景 `res://scenes/roguelite/RunScene.tscn`
  （**不是**主场景 TacticalScene；`project.godot` 的 main_scene 未改动）。
- 固定种子 `RUN_SEED = 20260704`（run_scene.gd 常量）——门组/波次每次运行一致，便于复现。
- 观察控制台日志：每步会打印 `[RunScene] 进入 stage N 战斗` / `掷出 M 扇门` /
  `stage N 结算` / `推进至 stage N` 等。

## A. 门循环主链路（一整幕跑通）

1. [ ] 启动后直接进入 stage 1 战斗（无门选、无门奖励预告），战场为注入清单
       （4 人队伍：swordsman/soldier/archer/cleric）而非测试场景的单剑圣+木桩。
2. [ ] 战斗中调试控制台 `·` 键无效、无「调试 harness」提示标签
       （debug_harness_enabled=false 已由宿主关闭）。
3. [ ] 打赢 stage 1 后出现「胜利」结算 overlay；点 Return 按钮**不重载场景**，
       而是切到门选择界面（Return 在注入模式下被接管为空操作，实际流转由 battle_ended 驱动）。
   - 注：v0 里 battle_ended 在判定胜负时即触发，门选择界面会在结算 overlay 后接管。
4. [ ] 门选择界面显示 **2-3 扇门**（标题「选择下一扇门」+ 横排按钮）。
5. [ ] 每扇门按钮显示：门序号 + 奖励类型（💰金币/⭐经验/🗡装备/💎遗物/❓事件之一）。
6. [ ] 点击任一扇门 → 进入 Prep 界面（「备战 (Prep)」+「确认出发」按钮）。
7. [ ] 点「确认出发」→ 进入下一关战斗（stage 2），战场敌人对应所选门的波次。
8. [ ] 重复 4-7，直到 stage 7 打完：**不出现门选择**，直接进 Prep（Boss 前），
       「确认出发」后进入 stage 8 Boss 战。
9. [ ] 打赢 Boss（stage 8）→ 出现「RUN 通关！」结算画面（金色字 + 最终金币）。
10. [ ] 任一关战斗失败 → 出现「RUN 失败」画面（红字 + 失败 stage）。

        （stat_scale 数值增强生效，如 goblin_melee 基础 HP × 1.35/1.6）。
16. [ ] 普通敌人无词条、无增强（对照组）。

### C1. 词条效果执行器（迭代#13，headless test_affix_effects.gd 23 断言已覆盖）

16a. [ ] **af_vanguard（先手部署 · 已实装）**：携带该词条的敌方单位**首回合**（round 1）
         速度 +2，回合序抢先/闪避提升；round 1 结束（round_ended）后速度回落基础值。
         无该词条单位速度全程不变（对照）。hook：unit.gd get_effective_stat SPD 首回合态。

         无该词条时 ZOC 仍仅相邻生效（对照）。hook：pathfinding.gd `_in_enemy_zoc`。
16c. [ ] **afs_bulwark（壁垒统御 · 已实装）**：只要该敌方阵营存在**存活**的携此词条单位，

         携带者阵亡后光环立即失效。无携带时伤害不变（对照）。

## E. Prep 阶段（任务 #8：HP 继承 + 恢复 + 运输队 + 情报）

前置：门选择后进入「备战 (Prep)」界面。观察控制台的 stage/门日志辅助定位。

### E1. HP 跨关继承（磨损核心）

19. [ ] 首关（stage 1）4 人**满血入场**（战场血条满，无磨损）。
20. [ ] 某关战斗中让某角色掉血但不死 → 打赢进门/Prep → 下一关**该角色不满血入场**
        （血条与上关结束时残血一致，体现磨损跨关继承）。
21. [ ] 某角色战死（HP 归 0）→ 下一关以 **1 血入场**（[占位] v0 无永久死亡）。

### E2. 恢复（Prep 主动动作）

22. [ ] Prep 显示每角色 `HP x/max` + 恢复量预览（`+N`，约 max_hp×50%[占位]，满血者 +0）。
23. [ ] 每角色「恢复/拒绝」切换按钮：默认「恢复」[提案]，点一下切「拒绝」（预览变「拒绝」）。
24. [ ] 点「确认出发」→ 接受恢复的角色下一关入场 HP 已按恢复量提升（clamp 不超 max）。
25. [ ] 拒绝恢复的角色下一关维持磨损 HP（背水流[提案]）。
26. [ ] 有角色未满血且拒绝恢复时，首次点「确认出发」出现橙色提示，**再点一次**才出发。
27. [ ] 多关重复恢复：同角色每次恢复量一致（run 内恒定，只随开局难度档）。

### E3. 运输队 / 装备（v0 仅数据交换，效果不生效[占位]）

28. [ ] Prep「运输队」区显示：选中角色兵器/防具槽 + 遗物 + 运输队装备/遗物库存。
29. [ ] 「操作角色」行切换选中角色，面板刷新为该角色的装备/遗物。
30. [ ] 运输队装备点「装兵器/装防具」→ 移入该角色对应槽；原槽有装备则退回运输队（数量守恒）。
31. [ ] 角色装备点「卸下→运输队」→ 回到运输队库存。
32. [ ] 运输队遗物点「给 <角色>」→ 进角色遗物槽（满 6 槽则无效）；角色遗物点「收回→运输队」回库。
33. [ ] 上述存取仅改数据展示，**战斗数值不变**（装备/遗物效果执行器为后续任务，[占位] 已标注）。

### E4. 查看情报（v0 占位）

34. [ ] Prep 顶部「查看情报」显示下一关地图名 + 波次；精英房显示「💀 精英房」。
35. [ ] 精英房带特殊词条时显示「特殊词条（进房前可见）：<中文名>」；基础词条不显示（相性赌）。
36. [ ] Boss 前 Prep 情报显示「下一关：Boss 战」。

## F. 固定商店（任务 #7：不占门不占关，固定插入两个 Prep）

前置：商店嵌在 Prep 界面顶部（恢复区之上），仅出现在两个固定 Prep。逻辑层由
`tests/test_shop_flow.gd`（50 断言：判定 / 库存 / 买卖 / 金币守恒 / 价格从 config 读）覆盖，
本节只列人工目视/点击验证项。

37. [ ] **幕中商店出现**：stage 4 打完选门后进入的 Prep（下一关 stage 5），顶部出现
        「商店（固定插入：幕中第4关后 + Boss 前…）」区块，列 4 件库存（stock_size[占位]）。
38. [ ] **Boss 前商店出现**：stage 7 打完的 Boss 前 Prep（下一关 stage 8 Boss），同样出现商店区。
39. [ ] **其余 Prep 无商店**：stage 2/3/5/6 打完的 Prep **不显示**商店区（只有恢复 + 运输队 + 情报）。
40. [ ] 每件库存显示：名称 + [kind·品质] + 买入价；「当前金币」实时显示。
41. [ ] **买入金币变动**：金币充足时点「买入」→ 金币减少对应买价，该件进「运输队装备/遗物」，
        并从库存移除（同件不可重复买）。金币不足的件「买入」按钮置灰。
42. [ ] **卖出金币变动**：运输队里的装备/遗物在「卖出（运输队回收）」区列出，点「卖出」→

43. [ ] 买入 → 再卖回同件：金币净减少 = 买价 − 卖价（回收比例损耗），体现经济排水渠。

## G. 事件门（迭代 #12：choices → 加权抽 outcome → 应用 effects → 伏击/推进）

前置：选一扇 ❓事件门 → 「确认出发」进入事件（**不装配普通战斗**，soft-lock 修复保留）。
固定种子 20260704 下事件门是否掷出、抽到哪个 outcome 均可复现。逻辑层由
`tests/test_event_resolver.gd`（61 断言）覆盖，本节只列人工目视/点击验证项。
三个事件：神秘商人 / 废弃矿洞 / 祝福祭坛（`data/events/`）。

45. [ ] 进入事件门后显示事件面板：**标题 + 描述文字**（自动换行）+ 每个 choice 一个按钮
        （按钮文案取自 `choice.text`，如「购买那件稀有装备（花费 120 金币）」）。
46. [ ] 点击某个 choice → 显示**结果面板**：outcome 描述文字 + effect 日志 + 「当前金币」。
47. [ ] **金币变化可见**（神秘商人/废弃矿洞）：花费类 choice 后日志显示「金币 -N（旧→新）」，
        「当前金币」同步减少；获得类显示「金币 +N」并增加。金币不会为负（clamp 0）。
48. [ ] **血量变化可见**（祝福祭坛「献上鲜血」）：选后日志显示「全队献血：按最大生命 20% 扣血」，
        进入下一关时全队 HP 已按扣血入场（最低 1，[占位] 无永久死亡）。
49. [ ] **多分支加权**（废弃矿洞「深入矿洞探索」有 50/30/20 三 outcome）：多次重开不同种子，
        能分别抽到「找到矿石+80」「大丰收+150」「触发伏击」三种结果（概率贴近权重）。
50. [ ] **伏击战斗触发**：矿洞抽中「伏击」outcome → 结果面板按钮变「迎战伏击」→ 点击进入一场
        战斗（`wave_event_mine_ambush`：2 近战哥布林 + 1 弓手），队伍为当前 party（含事件前扣的血）。
51. [ ] **伏击胜利正常推进**：打赢伏击 → 正常结算（固定金币经验）→ 掷下一关门组（与普通关一致），
        不 soft-lock、不卡界面。
52. [ ] **无战斗 outcome 推进**：非伏击 outcome 结果面板按钮为「继续」→ 点击视为无战斗完成，
        直接推进下一关（掷门组），全程不打战斗。
53. [ ] **占位项无声但可见**（buff/item）：祭坛 buff、商人装备等占位 effect 日志明确标「[占位]…未生效/未发放」；
        战斗数值不因这些占位 effect 改变（依赖 buff/装备/遗物系统，后续任务）。

## 已知 v0 限制（非缺陷，后续任务）

- 商店买入/卖出仅数据交换（装备/遗物/potion 效果执行器为后续任务）；potion 暂无库存数据源，
  买卖路径已支持（convoy.potions [占位]），默认库存只出装备/遗物。
- 运输队装备/遗物效果不生效（仅数据交换）——效果执行器为后续任务。
- 战死角色以 1 血复出（[占位] 无永久死亡）；未回填 max_hp 的角色恢复量按占位计算。
- 事件门 effect 中的 buff（run 级增益）与 item（装备/药剂发放）为 [占位]：buff 只记入
  `state.run_buffs` 不真实生效，item 只记日志不发放，均 push_warning 非静默——依赖 buff /
  装备 / 遗物系统（等设计库），后续任务接线。
- 事件 `hp_cost_percent` 按「最大生命」百分比扣血（引擎占位口径），与事件文案「当前生命」的
  差异待正式伤害系统统一。
- 事件门不结算门奖励（只结算固定金币经验），与门模式设计一致；伏击战斗胜利=完成该事件关。
- 结算数值/掉落为 [占位]，UI 未展示明细账本（仅控制台日志）。
- 门选择 / Prep / 结算 overlay 的视觉为功能原型（先功能后美化）。
