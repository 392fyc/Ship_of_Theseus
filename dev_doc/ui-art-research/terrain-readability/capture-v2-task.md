## 修正与必需核验

1. 显式固定用于采集的鼠标与悬停状态；主会话和重建会话使用同一状态，并记录浮窗可见性、文本和坐标。
2. 在最终绘制前固定呈现状态，覆盖实际道具及保留的其他景物；读取全部图像和状态期间不得跨帧。保留正式场景独立重建及实际道具复制替换路径。
3. 区分 `ViewportTexture` 的报告尺寸和 `Image` 的原生尺寸，记录原始 Window、Viewport、拉伸与坐标变换。实际 PNG 必须为请求的原生尺寸；不得裁切、重采样或关闭项目拉伸。
4. Texture 尺寸的判断必须依据该视口种类与实际拉伸关系；不能无条件跳过检查。主/辅助视口的逻辑范围、映射和最终原图仍须一致。
5. 修正全白排除掩膜的来源，记录单位与实际绘制 UI 的保守范围及覆盖面积；保留单位、UI、网格排除和至少三个实际可见实例的门禁，不删除排除项或扩大镜头规避。
6. 保留 12 个角色的同帧原件、逐文件 SHA256、主图与重建图全 RGBA 相等、道具 alpha 与实例 ID 对应、复制路径及排除掩膜检查。失败要先保存已取得的原图、状态与具体尺寸，保留失败门禁。
7. 新测试只覆盖本次悬停状态、冻结顺序、排除范围和尺寸关系的正反例。无窗口运行仅用于编译和结构检查；布局与像素验证交给 Dot。

## 技术来源

Godot 4.6.3 的 [ViewportTexture 源码](https://raw.githubusercontent.com/godotengine/godot/4.6.3-stable/scene/main/viewport.cpp)中，Window 的 `get_size`、`get_width` 和 `get_height` 使用视口尺寸乘拉伸比例；SubViewport 使用视口尺寸。`get_image` 直接读取渲染目标。v2 必须分别保存这些实测字段，不能把接口报告值当作已重采样的图像。

[RenderingServer 文档](https://docs.godotengine.org/en/4.6/classes/class_renderingserver.html)说明 `frame_post_draw` 在视口绘制后发出。独立视口提供渲染目标，像素一致性仍须由完整原图证明。
