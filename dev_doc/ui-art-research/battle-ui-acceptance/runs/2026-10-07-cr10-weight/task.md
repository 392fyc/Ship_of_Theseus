# CR-10 字重与行高追加修正

## 目标与完成条件

在已打包中文字体的基础上，补齐正文与标题字重，并消除回退链造成的文字裁切。CR-10 的完成条件是：字形一致、正文 Regular/Medium 对照完成且选定、行高不裁切、Windows 本机外观验收。本项完成不代表基础战斗 UI 或原 P0/CR-01 Milestone 完成。

用户已将本轮正文 Regular/Medium 的图上选择交由 Codex；该选择与独立实现审查分开记录。云端画面仍只支持内容可读与布局结论。G4 v2 使用的候选早于 CR-10，不用于评价此项字体外观。

## 写入范围

- 中文字体子集生成器、CJK 来源清单、新 Medium/Bold 子集与发行检查。
- 普通主题与 M2 的字体回退、标题映射及技能提示文字呈现；只调整字体排版参数。
- CR-10 运行检查、Windows 字重对照采集工具、受 RichTextLabel 类型变更影响的既有测试。
- `battle-ui-acceptance/cr10/font-packaging.md` 及本运行目录。

保留原许可证字节、所有批准面板坐标和尺寸、字号、冻结剑气数字字体与度量。CR-06、CR-40 行为不在本项实施范围；头像接缝 CR-24、地形可读性问题保持独立状态。不推送、不建 PR。

## 必查用例

1. 固定上游同一提交生成 Regular、Medium、Bold；字节摘要、字符覆盖、许可与发行 `.fontdata` 一致。
2. Windows Compatibility，1280×720、1920×1080、2560×1440；Regular/Medium 各采集常态、技能提示、头像属性卡及伤害预测。
3. 每次 `frame_post_draw` 后取得同一 Image 和状态；整屏与人物栏、Turn Order、技能提示、属性卡、预测浮窗局部逐图绑定。
4. 正文与标题层级可区分，中英文混排字重协调；实际文字无裁切。文字与边框至少留 2/3/4 像素，对应三档原生尺寸。
5. C8 与 C4 一并运行。C4 结果只记录，不能因本项字体通过而改判 CR-24。
6. 独立审查读取准确候选与原始图。审查前不提交，审查后只做本地提交。

## 本地采集边界

新工具复用正式 `courtyard` 10×10 → `TerrainBattleSession` → `TacticalScene` 与 M2 HUD，保留项目拉伸。测试只把一个既有敌方出生点放到合法相邻格，以展开预测文字，并在状态中记录。

采集在 Windows 原生显示服务和本机 GPU 上执行。独立采集副本使用 `no_focus` 与屏幕外窗口；内部 `Viewport.push_input` 展开文字，不调用系统鼠标移动。宿主程序监测采集进程是否成为前台。该批用于 Windows 字体像素及排版，不声称验证物理鼠标、音频或性能。

命令：`run_cr10_windows_weights.ps1 -GodotPath <Godot 4.6.3 控制台版> -OutputDirectory <仓库外新批次目录>`。每个批次保存完整日志、源文件摘要清单、环境、同帧 JSON 和原始 PNG；失败批次保留。
