SoT 战斗 UI — 高清像素材质 最小示例

研究先行 · 第一步「最简单的 UI 材质样式」演示 · 仅核心材质件，不画完整场景

2026-06-30 · 仓库 dev_doc/ui-art-research/ · 设计稿（SVG 模拟像素网格，非实装代码、非栅格素材）

这一张要回答的问题：「高清像素」这套 UI 材质质感，你看着对不对路。
材质三要素都在里面：① 双向斜面 bevel（顶/左受光亮、底/右背光暗，制造立体凿刻感）； ② 抖色 dither（两色棋盘点阵代替平滑渐变，是像素风的灵魂，不糊不拟真）； ③ 金属角钉 + 像素数字字形（统一的颗粒度 / 调色板）。
所有图形按真实像素网格绘制（crispEdges，整数坐标），放大 5–6 倍只为看清像素，游戏内是 1:1 的清爽像素。

五、落到 Godot 的实现现实（关键，影响像素管线）

高清像素 UI 材质，在 Godot 4.6 里有两条实现路，差别正好落在「是否要素材」上——这点和你说的「会影响像素管线」直接挂钩：
  • 路 A · 纯原生绘制 _draw不依赖素材：上面所有 bevel / 角钉 / 抖色 / 分段条 / 占位几何图标，都能用整数坐标 draw_rect 自绘做出来（现有 HPShieldBar/SkillSlot 已是这套画法）。成本=代码量，气质可控；缺点=每个框都要写绘制逻辑，复杂角饰雕花画不动。
  • 路 B · 九宫格贴图 StyleBoxTexture nine-patch需像素素材：真正"有美术味"的像素边框 / 真技能图标 / 复杂角饰，本质是一张张像素贴图——这就进了 Mercury 的像素管线。一套九宫格边框图 + 一套图标集，是 UI 和像素管线的交接点。
建议的分工：框架结构 / 状态逻辑 / 动效 / 资源条 走路 A（SoT 现在就能做、零素材）；真图标 + 高质感边框贴图 + 角饰 + 角色头像立绘 走路 B（列进像素管线需求清单，和角色 sprite 同一套像素气质）。
研究核验补充：① 像素完美不需要 shader，靠导入设置（Nearest 过滤 + 关抗锯齿 + 整数缩放）即可；② 纯 StyleBox 1px 像素描边=零素材可走；想省事也有现成 Pixel UI Theme for Godot（itch.io $5，含 Blood/Leather/Paper 变体，页面明确允许多项目商用）可商用；③ 像素方向整体约 50% 原生 + 50% 素材（像素字 + 像素图标/立绘/角饰走 Mercury 管线）。

六、字体（高清像素的成败手之一）

现状全程 ThemeDB.fallback_font（系统默认，非像素）。高清像素界面必须换像素中文字体，否则汉字"糊"在像素框里最违和。
本页 SVG 里的数字已用手写 3×5 像素字形演示（看技能槽的 1 / 3 / 2、资源条的 7）；汉字无法在 SVG 里临时手绘，仍用系统字渲染（注意它们是平滑的，不算数）。
研究已核验：中文像素字体用 Fusion Pixel Font 融合像素（SIL OFL 1.1，含简体字形，可商用嵌入；CJK 须 12px，8px 汉字难辨）可商用；拉丁字母/键位/数字用 m5x7（公有领域）做多字体 fallback 混排可商用。Ark Pixel 方舟像素是 Fusion 的上游字形库但仍缺大量汉字、不单独用；Zpix 本轮未确认、不推荐。
Godot 导入须：Antialiasing=None、Subpixel Positioning=Disabled、关 Mipmaps、项目 Default Texture Filter=Nearest、字号取整数倍；fallback 链建议存成 .tres 资源（避免重导入被剥离，Issue #92297）。
