# 底部界面联合视觉生产规格

## 1. Milestone VA-6：底部界面联合视觉生产包

### 阶段成果

保持已通过的底部界面信息布局不变，由专用视觉设计组把界面材质、按钮、边框、容器与人物、战棋棋子、地形、特效放在同一视觉系统中联合优化，最终形成可供 Godot 导入的正式 PNG 素材包和完整来源证据。

### 完成条件

- 用户通过联合风格板、完整底部界面两种资源状态图和跨素材同屏图。
- 正式 UI 文件逐一绑定文件名、像素尺寸和 SHA256。
- 每个文件的来源、使用权、父文件和机械处理链可核验。
- 透明通道、无白边、无烘焙文字、NinePatch 拉伸、必要状态和原生尺寸可读性通过独立审查。
- 本 Milestone 不修改 Godot 场景、脚本、Theme 或资源绑定。

## 2. 冻结输入与边界

### 当前布局合同

`dev_doc/skillbar-design/bottom-dashboard-batch-playground.html` 只保留为早期 HTML 布局探索记录，不再作为现行布局权威。当前几何布局在 Penpot 的 `HUD R1 · Components` 与 `HUD R1 · Layouts` 页面维护；本轮只确认组件职责、相对位置、外框大小与响应比例，不冻结第二轮才会设计的内部材质、按钮造型和装饰边框。

底部界面从左至右固定为五个可独立调整的组件：

1. 角色栏；
2. 装备栏，当前只有武器与防具两个槽位；
3. 技能栏；
4. 2×4 的 8 格遗物栏；
5. 结束回合组件。

角色栏常驻头像、职业名、玩家自定义名称、等级、经验、生命值和护盾。职业名与玩家自定义名称合并为单行字段容器，位于等级/经验字段上方，职业名在前、玩家自定义名称在后，样板格式为“剑圣 · fyc”；该行不是悬浮说明文字。超出可用宽度时单行省略，并在头像悬停或键盘聚焦的信息卡中显示完整名称。生命值与护盾使用一个共同外框内的两条状态带，保留各自数值和颜色语义，同时明确两者属于同一类生存状态。其他详细属性同样通过信息卡显示。技能栏外框按 6 个等大技能位确定固定尺寸，后续角色实际拥有的技能数量变化时，只调整框内排列、空位与间距，不再改变技能栏外框尺寸。技能位不预先硬分成主动与被动；被动技能也可能具有主动触发效果，因此所有可触发技能位都必须兼容快捷键和完整按钮反馈。

技能栏上方保留紧凑行动资源横条，并与技能栏及画面中线严格居中。标准行动使用绿色圆点，迅捷行动使用橘黄色三角；默认各有 1 点，显示容量最多 3 点。只绘制角色实际拥有的点数，1—3 点均在各自固定区域内成组居中；未获得的额外点不显示，已经拥有但本回合消耗的点保留位置并切换为暗色空心状态。行动资源不使用“可用”“已用”或资源名称等常驻文字。

移动资源使用青绿色菱形或脚步标识与剩余格数，不使用行动点图形。正常移动时数字逐格减少；完全消耗时显示灰色 0；因标准动作而提前失效时，保留当时剩余数字并把整个移动区灰化，不叠加斜杠或其他覆盖符号；消耗移动资源的技能使其直接进入灰色 0 状态。具体失效原因只在悬停或聚焦说明中显示。

所有角色固定拥有一个全职业通用血瓶。血瓶作为独立按钮放在装备栏内部右上角，不属于武器或防具槽，也不占用技能位或遗物位。本规格只冻结其通用归属、按钮位置和交互入口，不自行规定使用次数、补充方式或冷却规则。

职业资源不占用底部通用栏，也不保留空白占位。剑气、印记等职业专属界面要等其余通用界面稳定后另行设计；不同职业可以采用不同结构，本 Milestone 不制作任何职业资源界面。

布局审查以 1280×720 为 1 倍基准：角色、装备、技能、遗物、结束组件的参考宽度分别为 226、128、476、278、76 像素，组件间距为 8 像素，整行宽 1216 像素、控件外框高 108 像素；左右安全边距各 32 像素，底部安全边距 16 像素。角色栏右列宽 124 像素，职业/名称字段、等级/经验字段、生命/护盾组合字段的相对 y 坐标依次为 13、39、67，高度依次为 18、20、28 像素；三个字段组之间的间距均为 8 像素，整组上下边距均为 13 像素。生命/护盾组合字段内的两条状态带相对角色栏坐标分别为 x=89、y=68、w=122、h=12 与 x=89、y=82、w=122、h=12。技能栏包含 6 个 64×64 槽位，槽间距 8 像素，内部左右留白各 26 像素。遗物栏包含 2×4 个 44×44 正方形槽位，横向间距为 26 像素、纵向间距为 8 像素，254×96 网格在 278×108 外框内居中，左右各留 12 像素、上下各留 6 像素。技能栏与行动资源横条的中心均为 x=640；通用血瓶按钮为 32×32，在装备栏内的相对位置为 x=88、y=8，武器与防具槽的相对 y 坐标为 48。1 倍布局中底栏相对画板 y=596，行动资源横条相对画板 y=556，两者保留 6 像素间隔。1920×1080 与 2560×1440 分别按 1.5 倍和 2 倍等比检查。以上尺寸用于本轮相对几何验收，不是 Godot 中的硬编码值。

审核图中的 `CHARACTER`、`EQUIPMENT`、`WPN`、`ARM` 等英文只用于说明组件职责，不属于正式界面内容，也不参与控件外框的高度计算。组件高度只能由头像、职业/名称行、状态条、装备槽、技能位、遗物槽、血瓶和结束回合按钮等真实控件与必要内边距决定；正式位图不得烘焙这些审核文字。样板中的“剑圣 · fyc”是用于验证排版的运行时动态文字，同样不得烘焙进角色栏底图。

没有明确纵向或横向语义的图标槽和按钮底框必须使用正方形。当前 1 倍基准中，装备槽为 52×52、技能槽为 64×64、遗物槽为 44×44、血瓶按钮为 32×32、结束回合按钮为 52×52。头像框、状态条和行动资源分区具有明确的非正方形语义，不受此规则约束。

棋盘压力检查按最多 20×20 个 64×32 菱形格展示，但 20×20 不是玩法地图上限裁决。压力图允许棋盘延伸到底部界面后方，以直接暴露遮挡；首期不依赖棋盘旋转或缩放解决遮挡，预期通过镜头平移查看被界面覆盖的区域。

结束回合控件保持最右侧单控件和既有功能位置，但允许比提交 `61bd822` 的样板更小；最终外轮廓由 Task 6.2 的组合图锁定，不得因缩小挤占其他分区或降低可辨识性。

不得新增通用道具面板、普通攻击按钮、移动按钮或右下角独立技能按钮。全职业固定血瓶是已批准的单一独立入口，不扩展为其他道具槽。行动资源状态不得依赖“可用”“已用”等文字。

### 本批不做

- 不改变五个通用组件的顺序、数量或行动资源横条位置；不把职业资源重新塞回底部通用栏。
- 不设计任何职业资源界面或职业间通用模板。
- 不设计地图人物血条下方的 Buff/Debuff 样式或位置。
- 不修改行动经济、技能、遗物或职业资源的玩法规则。
- 不重新设计已经通过的剑圣武器数量、四斜向、人物主体中心或格内定位。
- 不生产战斗动画、完整特效动画、粒子系统、完整遗物图标库或其他职业素材库。
- 不进入 Godot 导入。

## 3. 设计组候选探索起点

本节用于给专用设计组建立首轮探索起点，不是已经通过的材质、色值、按钮、边框或容器造型，也不构成用户验收条件。设计组可以在保持统一质感和已冻结布局的前提下调整或替换这些候选语言，并以 Task 6.2 的真实同屏图证明最终方案。

首轮候选从“暗铁、黑紫、克制旧金”出发，沿用已批准人物、棋子、地形和特效的略微精细像素化质感。界面不得混入光滑矢量图标、写实照片纹理或粗大的八倍像素观感。设计组优先检验以下假设：

- 近黑暗铁与低反光黑紫作为主体材质，旧金只承担结构线、连接件、关键轮廓和交互高光。
- 绛红承担人物、物理攻击和危险信息；黯紫承担遗物、神秘和状态信息；冷钢蓝承担移动、护盾等工具信息。
- 所有类型采用左上微亮、右下压暗的统一光照关系。
- 地形保持最低饱和度与对比，人物处于中高信息层级，UI 边界清晰但不压过人物，特效拥有最高瞬时亮度。
- 可以从菱形格、人物服装金边和特效星芒提取“45°断角金线”候选母题；若同屏图显得装饰过重或与其他素材不协调，设计组应收敛或替换该母题。
- 技能按钮可优先尝试方形交互区域与内部菱形视觉核心，但按钮视觉核心的最终轮廓由组合图验收决定，点击区域不得因装饰轮廓缩小。
- 原生尺寸使用细像素簇和 1—2 像素的关键边缘层次；最多使用 2 倍 nearest 辅助诊断，不使用 8 倍图作为视觉验收依据。

起始色板只用于设计组内部试做，不是冻结色值：深黑 `#08090C`、炭紫黑 `#17141C`、旧黄铜 `#9C773D`、绛红 `#732631`、黯紫 `#59366E`、冷骨白 `#D8D0C2`、冷钢蓝 `#708493`。最终颜色及其语义分工必须通过真实同屏图锁定，不能仅凭色板单独定稿。

## 4. 必须联合审核的内容

首张联合风格板必须同时包含：

- 完整五组件底部界面；
- 头像裁切、头像框、等级/经验、生命/护盾和悬浮信息卡；
- 紧凑行动资源横条的满载与消耗状态；
- 固定外框内 6 个技能位的内部排布方案及代表性技能图标；所有可触发技能位都展示可分配快捷键的能力；
- 独立通用血瓶按钮及其常态、悬停、按下和不可用状态；
- 8 个遗物槽中的空槽、占用和悬停代表态；
- 比提交 `61bd822` 样板更紧凑的结束回合按钮，以及其常态、悬停、按下和禁用语义；
- 按实际游戏比例放在 64×32 菱形格上的已批准剑圣棋子；
- 已批准地形与一项静态特效；
- 人物原画作为头像、服装、配色和材质锚点。

人物原画、地形和特效若在本批只承担质感锚点，必须在图中明确标注，不得误记为本批新增的正式生产素材。

## 5. Milestone Tasks

### Task 6.1：冻结输入合同

**输入：** 已通过的 HTML 布局、`assets/prototype/visual_style/sample_manifest.json` v3、五类已批准代表预览、已准入的剑圣 `clean_v2` 棋子和知识库现行视觉裁决。

**产物：** 布局冻结图、部件清单、现行风格约束表、来源台账初稿。

**独立审查：** 核对五个通用组件和行动资源显示模型没有被重新设计；核对角色栏按照“职业名 · 玩家自定义名称”、等级/经验、生命/护盾组合字段的顺序排布，三个字段组之间的间距相等，整组上下边距相等；核对生命与护盾共享外框但仍保留两条独立状态带，职业/名称文字属于动态文字而非烘焙素材；核对职业资源占位已经移除、装备为武器与防具两格、遗物为 8 格、技能栏固定为 6 个技能位；核对装备槽、技能槽、遗物槽、血瓶和结束回合按钮等同类图标容器均为正方形，遗物槽为 44×44，遗物网格左右留白各为 12 像素、上下各为 6 像素，且两排之间保留 8 像素；核对通用血瓶位于装备栏内部右上角但未变成装备槽；核对标准行动、迅捷行动和移动资源的可用、消耗与失效状态符合本节合同，并确认移动失效态只灰化、不出现斜杠；核对 1 倍控件外框高 108 像素，审核文字没有被计入高度；核对 20×20 棋盘只作为布局压力参考，三档分辨率安全边距和比例一致。

**用户验收：** 本轮几何布局经用户通过后不重复送审；只有设计组证明必须改动布局才能完成材质设计时才暂停并提交新裁决。

### Task 6.2：联合风格板

**输入：** Task 6.1 合同与现有批准参考。

**产物：** 主视觉系统板、组件状态板、完整底部界面满载图、完整底部界面消耗图、跨素材同屏图和原生尺寸/NinePatch 检查图。完整界面图使用较小的结束回合按钮，不出现职业资源占位，并为所有可触发技能位展示快捷键兼容状态。

**独立审查：** 核对像素密度、边缘锐度、光照、色彩层级、材质语言、图标可读性，以及白底、透明边缘污染和烘焙文字。确认 UI 没有压过人物和地图，也没有重新设计棋子。

**用户验收：** 用户审核收敛后的主方案。这是 VA-6 第一个必须由用户作出的视觉裁决。

最低审核包文件名：

- `01_combined_visual_system_board_v1.png`
- `02_bottom_dashboard_component_states_v1.png`
- `03_bottom_dashboard_full_state_v1.png`
- `04_bottom_dashboard_consumed_state_v1.png`
- `05_cross_asset_cohesion_scene_v1.png`
- `06_nineslice_and_native_scale_check_v1.png`

审核图必须在当前会话重新发送，同时提供可访问目录。主画面使用 1280×720 原生尺寸，并提供 1920×1080 与 2560×1440 的实际尺寸局部检查。

### Task 6.3：素材来源路线

**默认路线：** 使用 Codex 内置图像生成子会话中的 GPT-Image-2 能力；不得配置、读取或调用外部 API key、SDK、命令行或 HTTP 图像接口。Rika 暂停。内置能力不能满足生成条件时停止并报告，不静默切换工具。

**购买路线：** 只有设计组证明购买素材能显著提升统一质感或生产效率时才制作候选卡，记录商店、作者、价格、许可范围、修改与商业分发条件及适配成本。付款或取得素材前必须由用户明确确认。购买素材成为风格锚点后，本地生成链和联合风格板都要向其重新对齐。

**用户验收：** 只有出现购买候选时需要授权；没有购买候选则继续默认路线。

### Task 6.4：正式 UI 素材生产

**生产范围：** 通用 NinePatch 面板、五个通用组件的边框和角饰、技能按钮必要状态、可复用快捷键角标底框、装备槽与遗物槽必要状态、通用血瓶按钮必要状态、较小结束回合按钮的必要状态、行动资源底框和点位、生命/护盾/经验条及头像框。

人物原画、头像裁切、代表性技能和遗物图标只用于跨素材联合审核，不进入本批正式 UI 框体包。人物与实际内容图标必须分别按角色来源、设计库现行技能和遗物记录建立内容素材批次。

技能按钮至少包含常态、悬停、按下、选中和禁用；具有主动触发效果的被动技能使用同一交互合同，并能表达已分配快捷键。冷却遮罩优先由引擎绘制，不烘焙进位图。快捷键字符、按钮名称、文字和数字全部由 Godot 字体与本地化系统渲染，位图只提供无文字角标底框。

每次生成保留原始输出。本地处理只允许可复现的裁切、透明清理、图集拆分、尺寸转换和调色。每个衍生文件记录父文件 SHA256、处理步骤、输出 SHA256 和像素尺寸。

### Task 6.5：正式文件技术整理与独立审查

**产物：** 无文字透明 PNG、NinePatch 安全边距与不可拉伸区域说明、状态图集或逐态文件、UI 素材清单和最终联合检查图。

**机械检查：** RGBA 与真实透明、无白底和半透明白边、最小/标准/最大尺寸的 NinePatch 无接缝、实际显示尺寸可辨识、过滤方式符合各类型合同、无烘焙文字。UI 的过滤设置不得覆盖已经准入棋子的 Linear 配置。

**独立审查：** 未参与生成和清理的审查者核对布局保持、视觉一致性、状态完整性、技术规格和文件身份。存在要求重新生成的必改项时返回 Task 6.2 或 6.4。

### Task 6.6：用户正式素材准入

会话中展示原生尺寸组合图、满载与消耗状态、角色详情悬停状态、按钮状态对照、NinePatch 拉伸图、目录和精确文件清单。

用户准入需要分别确认：

1. 本批视觉通过；
2. 本批由 Codex 内置图像生成能力产生并经本地机械处理的精确文件，可用于项目、进行修改并随游戏分发；
3. 绑定 SHA256 的精确文件获准进入正式素材目录。

现有五张参考图的授权不自动覆盖本批新文件或衍生文件。

若本批使用第三方购买素材，其使用权依据必须是经核验的原始商业许可；用户确认购买和精确文件准入不替代许可，也不构成第三方权利来源。

## 6. 后续边界：Milestone VA-7

VA-6 完成后才能开始 Godot 底部界面素材导入。进入 VA-7 前必须同时满足：

- 联合风格板、完整状态图和跨素材同屏图已获用户批准；
- 正式 PNG 的视觉批准、来源、使用权、SHA256、尺寸、用途和父文件记录完整；
- NinePatch、透明、按钮状态、原生尺寸可读性和无烘焙文字检查通过；
- 未决职业资源内容、遗物正式内容和 Buff/Debuff 血条样式没有混入本批；
- Godot 版本满足项目要求；存在版本兼容问题时先升级到兼容的 Godot 4.6.x 再验证；
- 导入只接入已通过布局和数据，不借机改变信息结构或玩法规则。

VA-7 应另行制定 Godot 导入实施计划，至少覆盖素材目录与哈希合同、通用组件导入、底部界面数据接入、三档分辨率真实截图、独立审查、用户实机视觉验收、受控发布和合并后核验。
