## 1. 增伤落在哪一层

规则见 N03、T22。设计库 R1.1 把一次伤害拆成几层，同一个数字放进不同的层，结果完全不同：

| 层 | 在 R1.1 中的位置 | 写法示例 | 特性 |
|---|---|---|---|
| 技能威力 | 括号内，与力量或魔力相加，再减防御 | 〔居合〕威力 +5 | 攻低防高时最显著；受防御影响 |
| 技能系数 | 括号外的乘数 | 〔斩击〕系数 +0.2 | 随属性成长放大，防御高时收益被压低 |
| 普通天赋提升 | 各项提升相加，乘 (1 + 提升之和) | 〔斩击〕造成的伤害提升 10% | 同层互相稀释，最拥挤 |
| 总增与总降 | 每一项单独相乘 | 伤害总增 10% | 与其他来源相乘，不被同层稀释；定价按最强的一层对待（推断） |

「特性」一列由 R1.1 的公式推出，示例数值只说明写法。附伤与追加攻击是另外的结算线，见 R1.13–R1.15。

**为什么优先属性联动**：小百分比增伤在最终向下取整后几乎看不见。例：15 级〔斩击〕造成 13 点伤害，提升 5% 仍是 13 点。火纹 if 剑圣的〔流星〕、Engage 戒指的再移动是属性联动的参照；再移动类偏骑士，剑圣的移动类机制绑定速度或〔一闪〕。

**可缩放的属性触点**（属性定义见设计库 R2.1）：

| 属性 | 战斗触点 | 适合缩放的效果 |
|---|---|---|
| 力量／魔力 | 伤害括号内的加法（R1.1） | 伤害、减益幅度 |
| 技巧 | 命中与暴击的基数（R1.2、R1.3）；剑圣签名属性 | 暴击、触发概率、连击 |
| 速度 | 闪避、出手顺序（R1.2、R3.1） | 机动、先攻、回避 |
| 幸运（固定） | 暴击回避、减益抵抗（R1.3、R1.5） | 尾部风险、抗性 |
| 防御／魔防 | 减伤 | 生存 |
| 生命 | 生命值 | 血量阈值类 |

**案例（成长型加收敛）**：〔燕返〕「副手追加命中后以技巧% 的概率再次触发，每成功一次概率 ×0.8（50%→40%→32%）」——绑剑圣签名属性，前期弱后期强，递减自带收敛（N02）。

### 输出类效果的三种结算形态

数值模式回答「怎样成长」，不能代替「在哪个结算单位上生效」。三种形态的结算见设计库 R1.13–R1.15，设计时的取舍：

| 形态 | 作用单位 | 更容易放大的结构 |
|---|---|---|
| 伤害提升 | 技能或攻击自身的原始伤害 | 高基础倍率、较少伤害段 |
| 附伤 | 每个符合条件的直接伤害段各带一次 | 多段、高频、低单段倍率 |
| 追加攻击 | 一次新的独立攻击 | 能稳定满足追加条件的动作或多目标动作 |

评估组合时按 N16 分别计数，不要用提高多段技能自身倍率来掩盖附伤没有按段获益的问题。组合样本充分之后，以〔二天一流〕代表的双刀体系和〔连斩〕代表的多段体系作为两条基线校准其他路线。

## 2. 池的边界

规则见 T02–T05。

- **双刀池**：单刀剑圣做不出来的才算双刀卡。反例：击杀产气、按剑气高低给闪避或先攻——单刀照样成立，应放剑士线通用层。双刀池以〔二天一流〕为硬前置。
- **印记池**：围绕印记的获取方式、当前构成与倾泻结算做文章。印记有心、道、势三种，总量上限 3、战斗清零，是剑圣专属；消耗由〔拔刀〕及其部分升级形态承担。在库的例子：〔离形〕改变构成规则并抬高上限，是可选放大器而不是准入条件；〔万象一刀〕拔刀时按消耗构成逐枚强化；〔残心〕拔刀后补印；〔印心〕获印记时产气并处理同种收益。
- 现行剑圣〔心眼〕按种类读取持有印记并给出百分比属性收益；替代型〔心眼〕升级是否保留这一段，以升级技能的完整效果为准。
- **纳刀印**（由〔离形〕赋予）：持有印记中最后获得的一枚，只在效果明确读取纳刀印时按两枚计算，随最新获得转移。
- 职业继承：下位职业的技能与天赋默认也属于上位职业（设计库 R2.4），设计一张卡前先定它属于哪一层。

## 3. 避开已饱和的维度

规则见 T23。例：剑圣技巧档位为 S，人物基础命中 = 武器命中 + 技巧 × 2，技巧约 35 以上时对常规敌人命中达到上限（R1.2），所以「加命中」对剑圣接近死卡；暴击维度在 60 点剑气时约 47%–64%，尚未饱和，是可以加值的主维度。数字随档位与规则变化，用前按当前记录重算。

## 4. 剑气高低轴

规则见 N07、N08、N20。剑气上限 100 点，以 50 点分为高于 50 点与不高于 50 点两区，这条分界写在设计库剑气资源的定义里。卡可以按剑气处在高区还是低区给不同收益，形成「攒气还是花气」的选择。〔心眼〕属剑士线基座，经 R2.4 继承到剑圣与剑仙；它按剑气给的收益以设计库记录为准，不依赖这条分界。与剑气高低互动、和双刀无关的卡归通用层。

## 5. 命名案例

规则见 W18–W20。

- 剑士线的借鉴池是剑豪题材的游戏、小说、漫画、动漫作品，典故经由作品取材，不做历史考据。
- 字数分布参照剑士线已上架的语料，二、三、四字混合。
- 名字配合机制意象：产气卡的名字要扛得住产气意象；双刀卡往成双、左右、呼应、分合走；效果越通用，名字越要带本线的文化外衣；拿不准时一张卡给 2–3 个候选交用户选。
- 正例：〔死线〕（暴击时技巧/2% 总增伤害）取「看见对方的死线并据此攻击」的意象，灵感来自直死之魔眼一类的作品设定，取核心概念收成两字；它替换的旧名「会心一击」是游戏通用机制词。
- 反例：同一张卡曾拟用「切先」（刀尖，剑道「切先三寸」），出处成立但属武学语汇，按 W19 让位于作品取材。
- 其他案例：〔剑气回荡〕（主副呼应、副手命中回气）、〔燕返〕（佐佐木小次郎的秘剑，与〔二天一流〕的宫本武藏是宿敌，呼应到位）。

## 6. trigger 怎么挑

规则见 T06–T13。

**五段结构**：事件、对象、来源、条件、频次（设计库字段 `trigger_event`、`trigger_object`、`trigger_source`、`trigger_condition`、`trigger_frequency` 与 `trigger_frequency_n`），天赋与装备共用。

| 段 | 形态 | 要点 |
|---|---|---|
| 事件 | 封闭枚举，分持续、回合结构、行动、攻击链、受击链、判定、资源、状态、移动等族 | 新卡必填；取值以设计库 `TriggerEvent` 为准 |
| 对象 | 注册表 id | 只有部分参数化事件带对象槽位，分别指技能、资源、状态、判定注册表 |
| 来源 | 该事件的合法来源集 | 只有部分事件带来源维度，例如攻击链事件取主手或副手 |
| 条件 | 自由文本 | 事件之外的附加前提 |
| 频次 | 限流周期（每次、每单位回合、每轮次、每场）加次数 | 「每次」表示不限流 |

校验口径（`app/models.py` 与 `app/validation/trigger.py`）：空表示不限定，不是错误；填了就必须合法；不带对象或来源槽位的事件填了任何值都报错，出现这种错通常说明事件挑错了。

**挑事件**：先定这张卡挂在哪条链上，再在族内选最贴的一条。事件宽窄决定触发面，触发面决定这张卡值多少，挑事件本身就是定价。带对象槽位的事件尽量填对象，例如「使用技能时」填〔拔刀〕；留空表示任意技能，触发面大得多，定标时别按填了对象的版本算。双刀池的卡多半用到来源段的「副手」。

**攻击链怎么挑**（T09）：施加减益、打标记这类与伤害无关的挂「命中时」；依赖实际伤害数值的挂「造成伤害时」；以前挂「命中后」的效果改挂「命中时」。

**条件段**：回答「在什么前提下」，常见形态有资源阈值（剑气 ≥ N）、剑气高低（写固定点数）、状态在场（「处于〔状态名〕状态」，状态改名或删除前全库检索引用）、自身或目标的属性与生命比较。不重复事件已经表达的信息，不写效果与数值；能用事件加对象表达的不落到条件段。

**频次**：频次是防滥用护栏的主力。周期按效果服务谁来选：只在自己行动时成立的用每单位回合，与敌方行动交织或跨全场统计的用每轮次，一场一次的大件用每场。轮次与单位回合的区别见设计库 R3.1。次数与周期一起定价：「每轮次 2 次」与「每轮次 1 次」是两张不同强度的卡。

**附加触发行**（T07）：授予窗口态的后续效果、对既有机制的持续性改写都不算独立触发点——前者写在被授予的状态与 `effect` 里，后者归「永久生效」主行。附加行存在设计库子表，五段规则与主行相同。当前用例：〔剑气回荡〕〔二天一流〕。

**存量卡**：旧的自由文本 `trigger` 字段仍保留，与五段并存。存量卡 `trigger_event` 为空、只有自由文本属于正常状态，不是错误数据；回填按 P11。

## 7. 出现条件与天赋间关系

规则见 T14。`unlock_trigger` 为空表示正常开放；天赋树落地后格式可演进为坐标等结构化形式。

| 关系类型 | 载体 | 例 |
|---|---|---|
| 解锁型硬前置 | 消费方 `unlock_trigger` 写「前置:X(池)」，设计簇说明写在 `notes` | 〔交刃〕〔燕返〕等双刀卡 |
| 升级型（lv1→lvN） | `levels_json`，每级一个完整草稿对象，lv1 取顶层字段 | 〔剑意澎湃〕lv2 |
| 隐性构筑依赖 | 不标，留给玩家构筑 | 攒气件与耗气件的协同 |

天赋间关系暂不建结构化关联、不进规则表；天赋数量成型后一次性梳理。

## 8. 稀有度示例

规则见 N11–N15、N21。

| 档位 | 示意 | 参照卡 |
|---|---|---|
| 传奇 | 接近回忆，一定程度改变玩法，常为某个池的硬前置 | 〔二天一流〕 |
| 史诗 | 较强数值、新奇小机制或机制联动；只提升〔拔刀〕伤害 25% 这类单一增伤配不上史诗 | 〔交刃〕〔二刀开刃〕〔燕返〕 |
| 稀有、普通 | 以数值为主，偶尔有改善操作的极小机制 | 〔剑气回荡〕（稀有） |
| 独特 | 特殊档，只在特殊事件下产出；天赋侧含义尚未定义 | 暂无 |
| 回忆 | 特殊档，技能升级专用，字段构成与其他档不同 | 见 §9 |

**减冷却的定档**（N15、N21）：冷却缩减改变技能的可用频率和每回合可选的技能，属于行动经济。剑圣的位移技能冷却本来不高，所以这类效果取 −1，或改为加长现有位移技能的冷却。冷却结束只恢复可用性，不额外给行动点（设计库 R3.5）。

**定标的两条路**（N14）：同池同档横向比较，加手算经济验证。设计库没有模拟与评分端点可用。

## 9. 回忆（技能升级）

规则见 M01–M18、P13、P14。回忆的作用只有一件：把某个已有的上位职业基础技能永久升级成同职业的新技能。它与职业强化类天赋不是同一种设计对象：后者的内容落在天赋自己的触发与效果字段，回忆只建立升级关系，完整玩法落在升级后的技能上。

### 回忆的定位

回忆是 SoT 区别于传统战棋的部分，偏肉鸽与暗黑类构筑：每个技能有自己的新形态，新形态再有几个特化方向，类似 WoW 英雄天赋树，用不同加点应对不同场面。普通天赋更接近火纹的角色特性与职业特性，与回忆一起构筑玩法。v1 预计每个基础技能做 2 个回忆供玩家选择，这是内容投入预期，不是容量上限。

### 案例

以下卡片只作方法证据，不借此重开既有裁决，也不把案例数值当作其他技能的定标值。

- 〔化剑为气〕与〔疾风骤雨〕：回忆天赋本身只需说明永久升级关系，完整玩法落在可独立理解的升级技能上。
- 〔裂空〕把单体动作改为多目标；〔连斩〕把一次命中改为由连续命中决定长度的攻击序列。两者都改变了目标或结算结构，并补清了逐目标资源、整次使用、逐刀结算与外部触发次数。只在原技能末尾加收益不构成形态升级（M07）。
- 〔残心〕与〔印心〕：资源获得的时点、对象和重复条件要形成完整命题；〔介错〕：并行资源效果是否叠加要写明；〔破竹〕：阈值判定时点与同层加法放在 `rules`。

### 固定工作集（P13）

1. **记录来源**：读取 live API 与仓库快照，记录 `schema_version`、来源提交、完整 talents 与 skills 集合的规范化 SHA256，确认目标对象在两处语义一致。
2. **筛选材料**：先筛已上架，再按任务允许的状态取材（G02）；用户点名的草稿只是本次待改写的载体（G04）。
3. **枚举兼容对象**：同时查结构化指向（技能对象、升级关系、相关状态链接）、玩家文案（明确点名基础技能的天赋或规则）与通用结算语义（因动作、命中、暴击、伤害段、击杀、资源变化、状态或目标数而作用于基础技能的效果）。只查名字会漏掉通用效果，只查结构字段会漏掉仍写在文本里的关系。
4. **冻结工作表**：每个基础技能、两个回忆载体、两个升级技能载体、相关职业与前置、触发元数据、当前有效的兼容对象各占一行，记录原文和来源，盘点阶段不改写、不评价。

### 双层设计

**第一层：技能形态升级。** 把基础技能逐句拆开，每一句标为「保留」「删除」「改写」或「改换结算结构」，逐项覆盖：动作类别、目标选择、射程、范围与位移；命中、暴击、伤害段与结算单位；标准动作、额外动作、攻击机会及专属资源的取得与消耗；职业机制节奏、前置成本、失败分支与多人环境可靠性；与现有锁定卡、状态条件和通用规则的组合放大。

**第二层：原技能兼容性。** 对工作集里的每个现有效果问：

1. 它依赖的是基础技能的身份，还是某个可能已被改掉的具体形态？
2. 它按一次使用、一次动作、一个目标、一次命中、一段伤害还是一次资源变化计数？
3. 升级后的多目标、多段、自动续击、位移或资源变化会不会把触发次数意外放大？
4. 升级是否删掉了该效果必需的命中、伤害、消耗、状态或目标条件？
5. 继承后会不会出现零代价循环、自触发、互相触发，或已结束的结算被再次打开？
6. 玩家文案能否独立说明结果，现有结构和运行时能否稳定表达？

同一基础技能的两个升级方案可以得出不同结论，不要为了整齐强行统一。

### 兼容性结论与矩阵（M08）

| 结论 | 判据 |
|---|---|
| 默认继承 | 按设计库 R2.5 继续生效，效果依赖的内容在升级后仍存在；写明生效口径，确认没有未声明的次数放大 |
| 明确不继承 | 升级删掉了必要形态，或继承会破坏取舍、造成异常循环或不可接受的次数放大；说明玩法理由以及玩家从何处得知 |
| 统一措辞，不新增结构 | 玩法上应继续生效、现有结构能承载，但当前文案依赖旧形态；改玩家文案或 `rules` 即可 |
| 未来建模需求 | 玩法意图明确，但设计库结构或运行时无法无歧义表达；记录所缺能力和受影响对象，不写成已能继承，也不在当前内容任务中扩建系统 |

每个基础技能一张矩阵，同时比较两个升级方案：

| 现有天赋或规则 | 在原技能上的生效单位 | 升级方案甲 | 甲的结论与理由 | 升级方案乙 | 乙的结论与理由 | 需要的文案或结构动作 | 设计库与 Ship 表达能力 |
|---|---|---|---|---|---|---|---|

### 协作分工

1. **事实盘点**：事实核查者冻结对象、来源版本、审计边界和兼容对象；方案整理者不用被排除的草稿或归档内容补证。
2. **方案设计**：结算分析者完成逐句形态对照与典型回合推演，方案整理者补全两套有明显玩法差异的升级。
3. **独立审查**：结构核查者查字段和载体；反方审查者专查多人环境失效、触发次数膨胀、资源或行动循环、前置成本失真、状态条件含混、递归边界与兼容性漏项。
4. **候选输出分两个实体**：回忆天赋（`id`、`name`、`class_id`、`rarity=回忆`、`upgrade_skill_id`、完整 `effect`，必要的 `rules`、`notes`、tags，不套用职业强化类天赋的触发五段与等级蓝本）；升级技能（`id`、`name`、`class_id`、`upgrade_of`、行动资源、目标模式、射程、范围、位移、`effect`、`rules`、`notes`、tags，未改字段也明确给出，保证能独立导入并完整替换）。
5. **每个候选附带的证明**：单卡作用、优势与代价、多人环境可靠性、触发次数、行动与专属资源、前置成本、组合放大、状态条件、逐句形态对照、删除性检验、典型回合、命中失败与资源不足时的行为、递归边界、兼容性矩阵、可调数值和不得破坏的定标约束。
6. **结构适配性**：逐项标明「已结构化支持」「只能由自由文本表达」「设计库缺口」「Ship 运行时缺口」（P10）。

### 回忆点与节点

- 回忆点获得与分配见 M12；三个 Act 共 5 点是正常流程的最少值，过程中可能额外获得；将来加入 Act 4 时再适配。回忆有专属入口，回忆天赋树在转职后开放，可以随时加点。
- 玩家可以 5 个技能各升一次，也可以专精 1–2 个技能；前者收益低是玩家自己的选择。
- 回忆的扩充方案（类似 Last Epoch 技能树或 Inkbound 升级模板）留待以后，当前不动。

节点方向（M15）的例子：

| 方向 | 含义 | 例子 |
|---|---|---|
| 功能 | 改变攻击形状、选目标或站位，不直接改数值，大部分场景适用 | 〔贯虹〕 |
| 数值补足 | 补技能的短板数值或资源 | 〔凝气〕 |
| 移动 | 出手前后的位移，打完就走 | 〔游刃〕 |
| 单体／破甲 | 强化对单个、高防御目标的打击 | 〔连绵〕 |
| 属性堆叠奖励 | 奖励堆某项属性的玩家 | 〔破限〕 |
| 技能交互 | 与其他技能或印记联动 | 〔圆满〕 |

- 节点方向给普通天赋留挂钩：移动节点配移动后增益类普通天赋，属性堆叠节点配命中、技巧类普通天赋，技能交互节点配〔招架〕、闪避类普通天赋。
- 技能交互难设计，不强行加，并且要顺着回合规则（S14）；例如〔游刃〕与〔一闪〕的交互因违背「移动机会只有一次」被否决。
- 节点质量：避开窄条件配普通加成、节点之间互相抵消、堆数值与自动化、过度复杂的状态机；改动从原版出发，能保留的机制尽量保留。〔不动〕（额外闪避改为等于技巧）与其他节点相比太普通，是「缺乏存在感」的例子。
- 同一技能的互斥回忆，在同一组场景、同一基线、同等投入下比较强弱。
- 状态与资源按 G13 每场战斗开始时为 0；回忆本体给的〔剑痕〕也按此处理。

## 10. 职业强化类天赋

「职业强化类」是本文用来区分工作流的称呼，不是设计库的稀有度或类型枚举：它指回忆以外、以职业本身为强化对象的天赋（T15）。

1. **输入**：目标职业当前有效的职业规则、资源规则、相关的已上架天赋、职业数值档位、相关用户裁决。先写清职业核心机制、已饱和维度和不能扩大的范围。
2. **分工**：事实核查者整理有效材料；方案整理者补全玩法、规则与字段；结构核查者检查字段、触发事件和注册表引用；反方审查者专找永真条件、滥用组合、同质化与低收益属性；整合者只依据证据和用户裁决收敛，不把自己的草案当先例。
3. **候选卡格式**：`class_id`、稀有度建议、名称候选、主触发五段、必要时的附加触发、`effect` 全文、必要的 `rules`、`notes`、tags、出现条件和 `levels_json` 方案。
4. **验证**：说明它强化了哪条职业机制、为何不属通用层、数值的上下界、失败与滥用场景、与当前天赋的重叠程度，以及设计库和 Ship 是否已有消费路径。
5. **数值定稿后**：对最终效果跑经济验证（N14）。

## 11. 普通天赋池的组织

规则见 T16–T22。

- **流派两维**（T19）：输出方向分追加特效与技能威力，两者相反；技能重心有斩击流（靠〔裂空〕或〔连斩〕、放弃〔居合〕）、一闪流、反击流（反击只来自回忆或技能给出的反击）、〔居合〕循环。两维可以组合，例如斩击流加追加特效就是〔连斩〕多段逐段触发。
- **资源加速为什么要配兑现**（T20）：每回合行动资源不变，加速〔居合〕或〔拔刀〕并不提高攻击频率；收益要么来自这些技能的威力被大幅强化，要么来自技能触发的特效本身被频繁利用（例如附伤）。
- **参考来源**：先查 [参考作品索引](../05-Research/references.md) 已有的火纹、XCOM、The Last Spell、永铃回响调研；依赖追击、反击、先手后手的机制不用（T18）。
- **剑圣的防御定位**（N19、M18）：剑圣兼顾物理输出与闪避坦克。基础加闪避与天赋加百分比减伤不自洽，护盾与闪避互补。剑圣不以生存能力著称，防御要控制，不给后续高生存职业开坏头，所以防御类节点优先改成进攻、资源或交互。
