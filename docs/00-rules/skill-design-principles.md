# 技能设计指引(Skill Design Guide)

> **读者 = 设计 SoT 技能的代理。** 本文是三级指引：解释 [设计规则总表](rules.md) S 节（以及 W、N 节中与技能有关的规则），给字段读法与示例，不另立规则；与总表不一致时以总表为准。入口见 [设计规则面索引](design-rules-index.md)。
>
> 相关文档：[技能与射程](../01-Game-Design/skills-and-range.md) · [回合系统](../01-Game-Design/Core-Systems/turn-system.md) · [规则总目录](../01-Game-Design/rules-catalog.md)

## 1. 字段面

设计库技能的字段以设计库模型为准，常用的有：`id`、`class_id`、`name`、`damage_type`、`resource_type`、`skill_type`、`is_projectile`、`cd`、`target_mode`、射程三列（`range_min`、`range_max`、`range_shape`）、作用范围两列（`area_shape`、`area_size`）、`displacement`、`upgrade_of`、伤害条目 `damage_entries`、`effect`、`rules`、`notes`、`tags`。

- 技能没有 trigger 字段，也没有稀有度、`status`、`shelf_state`（S02）。设计天赋时不要照技能的字段面推，反之亦然。
- 伤害条目（S03）：一个技能可以有多条伤害条目，它们是互斥备选，由 `applies_when` 区分；多段用 `segments` 表达。伤害条目之外的效果（状态、资源、位移）怎样落成 Godot 运行数据，等该技能进入 Ship 实装时逐项分析，不从效果文案批量反推。
- `is_projectile`（S04）：是 = 发射一个实体，飞行途中可能被技能、特效或地形阻挡；否 = 点对点直接作用。它与 `damage_type`、`skill_type`、`resource_type` 互不相关。
- `target_mode`（S05）：单位、格子、方向、自身，取值以设计库 `TargetMode` 为准。

## 2. 两个分类维度

- `skill_type` 回答技能**做什么**：攻击、位移、增益、辅助（含治疗）、控制。
- `resource_type` 回答技能**耗哪种每回合行动资源**：标准、迅捷、移动、反应、无。「无」留给完全被动、没有主动触发成本的技能，例如〔心眼〕。
- 行动点、施放时机与冷却怎么结算见设计库 R3.2、R3.3、R3.5；同槽形态替换见 R3.6。默认容量下一个单位回合通常用 1 个移动、1 个标准、1 个迅捷动作，但容量提高后可以继续支付同类行动点，所以技能设计要说明默认容量与扩容后的取舍（S08），不要把「默认 1 点」写成每回合次数上限。

## 3. 射程与作用范围怎么读

- **射程**回答「哪些格可以被选为目标」，以施法者为原点；射程 0 的自身技能射程三列留空。
- **作用范围**回答「选定之后作用到哪些格」，以目标格为原点；「单体」等价于大小 0。
- 例：〔拔刀〕是「选 1 个单位、作用 5 格」；〔一闪〕是「沿一个方向选目标、最远 4 格，受伤格按位移沿途算」。
- **位移类技能**（S06）：作用范围两列统一记为「单体＋0」，表示这两列不按普通范围读；受伤格是从施法者所在格走到落点的沿途格（不含起点、含落点），最远由 `range_max` 决定。设计库的范围预览也是这个口径。
- **位移与「选方向」是两件事**：〔瞬身〕有位移，但 `target_mode` 是单位；〔一闪〕〔连闪〕才是方向。
- 射程与范围的形状枚举以设计库 `RangeShape`、`AreaShape` 为准；在库数据用到哪些形状，以接口查询结果为准。

## 4. 转职分层示例

规则见 S09–S11。

- 剑士（`myrmidon`）的技能是转职前的纯净效果，不含印记；印记是剑圣（`kensei`）专属。剑圣的印记效果做成剑圣自己的条目，不改写剑士版。
- 剑士与剑圣可以各有〔斩击〕〔一闪〕〔招架〕〔居合〕〔心眼〕，靠 `class_id` 与技能 id（如 `myrmidon_zhanji` 与 `kensei_zhanji`）区分。剑圣天赋点名〔斩击〕时指剑圣〔斩击〕。
- 转职时同名技能增加效果或替换原效果都是常规做法。例：剑圣〔斩击〕〔居合〕〔心眼〕保留剑士版原效果并增加印记效果；剑圣〔招架〕把剑士版的防御、魔防加成换成按技巧加闪避；剑圣〔一闪〕与剑士版相同。
- 尚未定：剑士天赋随转职归属剑圣后，它点名的剑士技能是否作用于剑圣同名版本。目前设计库的剑士天赋没有点名基础技能，出现实例时先定。

## 5. 剑士线的资源节奏

规则见 S15、S16、N07–N09。

- 基础配置下剑气花费大于收入，约束的是没有任何投入时的循环；投入后在有利场景里基础技能用得少，是投入的回报。
- 节点要奖励节奏时，可以作用在迅捷或移动技能的冷却上，或提供再移动。
- 威力与系数的分工：威力加在括号里、减防御之前，威力比〔斩击〕高的技能相对〔斩击〕的伤害倍数随等级下降，但对重甲更强；系数在减去防御之后相乘，调节技能巅峰期的强度。
- 「每关卡限定次数」这类计数还没有写进设计库规则表。
- 「奥义」tag 判身份：一条职业线的终极技能整条线只有一个，剑士与剑圣是〔居合〕。〔拔刀〕消耗大、带独立暴击倍率与溅射，但不是终极技能，不挂奥义（S12）。
- 「资源」tag 判据见 W17：〔居合〕消耗的剑气是这一招的成本，不挂；〔斩击〕能让玩家拿到剑气，才挂。
- 具体技能的数值以设计库记录为准，本文不复写。

## 6. 同槽形态与升级

- 回忆升级是永久替换（M01–M05）；按条件占用同一槽位的临时形态不是升级，两个技能仍同时存在，冷却按设计库 R3.6 分别计算。
- 动态显示名可以属于同一个技能身份；多形态可以有不同的动作、目标、射程和冷却。数据模型表达不了一个回忆对应多个条件形态时，在版本化设计检查点里保存真实关系（M10）。
- 图标与快捷键（S18、S19）：〔心眼〕保留眼睛的视觉特征，〔空想剑〕与〔斩击〕用不同图案；〔心眼〕及其替换形态排在〔招架〕与〔居合〕之间，普通状态下〔居合〕为 4，〔空想剑〕转为主动后依次为「〔空想剑〕4、〔居合〕5」。验收时在实际技能栏尺寸下同屏比较，图案非空和按键正确不能代替这一检查。
