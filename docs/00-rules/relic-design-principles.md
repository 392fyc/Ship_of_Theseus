# 遗物设计指引(Relic Design Guide)

> **读者 = 设计 SoT 遗物的代理。** 本文是三级指引：解释 [设计规则总表](rules.md) L 节与 G11，不另立规则；与总表不一致时以总表为准。入口见 [设计规则面索引](design-rules-index.md)。架构权威是 [五层架构共识 v2](../03-decisions/architecture-consensus-v2.md)（L5）。

## 1. 定位

遗物 6 格，局内通过奖励、商店、事件获取，局后清零。它与转职选择强耦合：转职时玩家会看已持有的遗物决定方向。所以设计一件遗物，先想它怎样影响转职与加点决策。

## 2. 两类 archetype

| 类别 | 作用 | 边界 |
|---|---|---|
| 经济类 | 加速经验、属性或天赋点，作用于人物成长 | 只加速职业既有的成长曲线，不改变成长模型本身 |
| 流派类 | 改变职业形态或天赋节点的行为（例如扩散燃烧、即时结算式） | 构筑定义的主力，与重要的天赋节点等价；`effect` 写明改动的机制锚点（L04） |

单件强度要计入它占掉一个遗物槽的机会成本（L03）；具体强度标尺随首批内容一起确立，按 G07 由代理决定并标「推断」。

## 3. 字段现状

- 遗物是全局实体：没有 `class_id`，也没有 tag 关联表；`rarity` 与天赋、装备共用五档，带 `shelf_state` 与 `trashed_at`。
- 羁绊分组（`synergy_categories`）是引擎侧概念，与天赋的 tag 体系不互通，设计库不存它。
- 字段的确切名称以设计库 `/api/relics` 的当前实现为准；在库条数以接口为准。
- 掉落按稀有度分桶（L06）；若实测单轮航程难以凑成羁绊，再评估「同羁绊掉落轻微优先」，目前不做。
- 稀有度第五档「独特」与「唯一／可叠加」的去重机制（L05 不做）是两回事。
