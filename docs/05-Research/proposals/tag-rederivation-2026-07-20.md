## 一、tag 定义的描述规范

### 1.1 先回答用户明确问的那个问题：定义与边界分开写，还是合成一段？

**结论：分成两个字段存，当成一段话写，合并成一段读。** 三件事分开说：

| 层面 | 做法 | 理由 |
|---|---|---|
| **存储** | 保持 `definition` / `boundary` 两个独立字段，并给 `boundary` 加**非空校验** | 现状 13/13 条 boundary 是空字符串。这不是漏填，是这个字段可以被跳过。合成一个字段等于承认「边界写不写随意」，正是用户批评的根源之一 |
| **写作** | 两段必须一次写完、互相不重复、不互相矛盾，合起来算总字数 | 读者永远同时看到两段（渲染时拼成 `{{definition}} ｜边界：{{boundary}}`），分开写会写出两套口径。本轮 13 条里有 3 条（奥义、战棋、增益状态）就是定义句和边界句给出相反答案 |
| **渲染** | 保持现在的合并展示 | 已有两个出口：`talent_detail.html` 的悬浮提示（回忆用）、`fill_assistant_drawer.html` 的纯文本列表（真正决定挂不挂的地方） |

补充一条待前端确认的技术点：三份规范里角度一称 `data-tip` 属性值内的换行会被折叠成空格。若属实，boundary 的分行列点在悬浮提示里会连成一片。**建议前端核实并改成可换行的提示组件**（这是一个小前端改动，不改数据）。抽屉那个出口分行是有效的。

### 1.2 合并后的规范（v1）

#### 句式模板

**definition —— 1 到 2 句**

```
第 1 句（它是什么）：〈游戏里的那个东西〉+〈它怎么运作 / 怎么一眼认出来〉
第 2 句（什么时候挂它）：一张卡只要〈可当场对照的特征，列举优于形容〉，就挂这条。
```

主语必须是游戏里的东西（一套数值、一次位置变化、一段状态、一次攻击）。硬性禁止主语写成「标签」「tag」「本条」。

**boundary —— 分行列点，2 到 4 行，只用四种前缀**

```
不含：〈点名一个真实会被误挂的具体对象〉——〈一句为什么不算〉。          【必填，至少 1 行】
与《X》的分界：〈一句可当场比对的判据〉。                              【存在语义最近的 tag 时必填】
同时挂《X》：〈什么情况下两条都挂〉。                                  【可选】
规则备注：〈必须提醒的结算事实〉（依据 R编号）。                        【可选，只写编号不复述内容】
```

**随词条交付、不写进字段：三卡判定测试**

```
应挂：      〈生产库真卡〉
像但不该挂：〈生产库真卡〉  ← 这一张是全套规范的试金石，挑不出来说明边界没写到位
明显无关：  〈生产库真卡〉
```

#### 合格标准（11 条）

前 9 条是三份规范的交集，第 10、11 条是本轮对抗检验的净产出，三份规范都没有。

| 编号 | 标准 | 判定方法 | 现状踩雷数 |
|---|---|---|---|
| S1 | 不自指 | 检索「标签／tag／机制标签／内容标签／层／本标签」，命中即不合格 | 10/13 |
| S2 | 遮名可读 | 删掉 tag 名及其构词成分后，剩下的字仍指向唯一含义 | 11/13 |
| S3 | 有可观察的游戏动词 | 圈出动词，问「它描述的是棋盘上的事件，还是我在做分类动作」。「是／属于／挂钩／涉及／聚合」不算 | 13/13 |
| S4 | 外延是真子集 | 按字面读，全库大部分卡是否都符合？是则不合格 | 系统、战棋、自动 |
| S5 | 三卡实测 3/3 | 三张全是生产库真卡，且「像但不该挂」那张必须真有误挂风险 | 无一条做过 |
| S6 | 边界非空且点名具体对象 | 能不能从 boundary 里圈出一个专有名词。禁「除上述以外」「视具体情况」 | 13/13 |
| S7 | 点名最近邻 tag | boundary 里出现的 tag 名能在注册表查到，并附一句判据 | 13/13 |
| S8 | 不搬规格 | 无阿拉伯数字、区间、公式、字段名、代码 id。可引术语名与规则编号，不可复述其内容 | 印记（抄了 term 的前半截） |
| S9 | 只陈述当前事实 + 成对非镜像 | 无日期、无「原为 X」「已废弃」；成对 tag 各自独立成立，不得镜像换字 | 增益／负面状态 |
| **S10** | **多特征必须写明合取还是析取** | 定义列了两个以上特征时，写清「全中才算」还是「任一即可」 | 奥义、负面状态、增益状态 |
| **S11** | **判据锚在效果本身** | 不锚在「这一次的运行结果」，也不锚在「卡面用了哪三个字」 | 区域、处决 |

S10 的来源：奥义的对抗检验编出一张「不吃资源、整场限一次的终结技」，定义的三个特征给出两个相反答案；负面状态的定义写「属性被压低，或行动被限制」，把自己举的旗舰样本（毒剑的中毒＝每回合掉血）排除掉了。

S11 的来源：区域的对抗检验编出「打自身周围八格」，同一张卡在周围站 3 人时判「挂」、站 1 人时判「不挂」——tag 是静态贴在卡上的，判据不能随战局翻转；处决的定义写「卡面写了『击杀后……』就挂」，而它自己的旗舰例居合卡面写的是「击杀返还 30 剑气」，根本没有那三个字。

#### 禁止清单（出现即打回重写）

```
机制标签 / 内容标签 / ……类的标签 / 本标签 / 层 / 聚合 / 底层逻辑 /
相关 / 涉及 / 挂钩 / 一类 / 等 / 除上述以外 / 视具体情况判断 /
无阈值程度词（高、强、大量、任意、多种）后面不跟可判定的量化或穷举 /
斜杠并列而不说明两侧是同一件事还是两件事
```

#### 长度预算（我改了三份规范给的数字，理由见 1.3）

```
definition  ≤ 60 汉字（目标）
boundary    ≤ 120 汉字（分行）
两段合计    ≤ 168 汉字（硬上限 ＝ 悬浮提示实测 8 行，超过读者会直接略过）
```

#### 正例（用户给的范式展开）：资源

```
定义：某个职业线独有的一条数值储备，比如剑士线的剑气；由这条职业线自己的技能、
      天赋、遗物条目来产出、花掉、改规矩。一张卡只要动了它的收支，就挂这条。

边界：不含人人都有的通用数值——HP、每回合能走几步能打几次（R3.2），它们不分职业。
      只把剑气当触发条件、不改变它增减的不挂（梯云纵、气贯长虹）。
```

逐条对照：主语是「数值储备」不是「标签」（S1）；删掉「资源」二字仍自足（S2）；「产出／花掉／改规矩」是棋盘上的事件（S3）；点名 HP 与 R3.2 两个真实误挂对象（S6）；引了「剑气」这个术语名但没复述术语表的「0-100 持有型」（S8）。

#### 反例：系统

```
原文：definition =「和游戏底层逻辑挂钩」，boundary =「」（空字符串）
```

九个字，同时违反 S1（隐含主语仍是本标签）、S3（唯一谓语「挂钩」是分类学表态）、S4（伤害结算是底层逻辑，移动也是，全库皆符合）、S6（边界空）。

但这一条真正的教训不在上面四项，而在**名与实指向两个不同的概念**：「底层逻辑」最自然的读法是工程实现层，而按这个读法该挂的（疾如风、起手式，两张都自述需要引擎新做支持）都没挂；真正挂了的两张（二天一流、守破离）是在游戏虚构层改写了一条既定规则。**当初挂 tag 的人心里想的是「改规则」，写下来的却是「挂引擎」。** 这是「意义不明」的最深一层，也是规范 S2/S4 单独抓不到的——它需要拿定义去比对实际挂载卡才能发现。所以三卡判定测试（S5）是不可省的。

### 1.3 三角度分歧处，我采信谁

| 分歧 | 角度一 | 角度二 | 角度三 | 我的采信 |
|---|---|---|---|---|
| **定义长度** | ≤60 字，1-2 句 | 恰好 1 句 ≤40 字 | ≤2 句 | **采角度一的数字 + 角度三的两句结构**。角度一的 60 字是唯一有物理依据的（悬浮提示实测 280px、12px 字号 ≈ 每行 21 汉字）；角度二的 40 字无来源，且单句装不下「它是什么」+「什么时候挂」两件事，硬压会砍掉判定句——而判定句正是这批 tag 最缺的东西 |
| **边界长度** | ≤50 字，合计 ≤110 | 2-4 行分点 | 2-4 行分点 | **改数字，采角度二／三的形态**。理由是数据：13 条成稿里 **12 条突破了 50 字**（唯一没破的是奥义，46 字）。一条 12/13 都做不到的规则不是约束，是摆设。而它们突破的原因高度一致——同时点名排除对象和最近邻 tag，50 字物理上装不下。故把预算改成边界 ≤120、合计 ≤168（168 是角度一自己测出的「读者直接略过」阈值，是真正的失效线） |
| **边界能否写规则编号** | 未表态 | 可以，必须带编号 | 不可以，规则归规则表 | **采角度二**。可以写指针，不可以写副本。指针不会随规则改动失效，副本会——印记的定义抄了 term 表「0-3 离散槽位（心/道/势）」的前半截，术语表一改它就静默失配，这就是副本的代价 |
| **定义里能否出现卡名做正面锚点** | 用了 | 未表态 | 用了 | **有条件采用**。卡名让判据立刻有画面，收益真实；但对抗检验指出两个风险：卡会改名／废弃（介错当前只是「待审阅」），且未读文档的人读不出信息。**规则：定义里最多一个卡名，且必须放在句尾可切除的位置；其余锚点降到边界的示例位** |
| **能否用「指」起手** | 未要求 | 要求 | 未要求 | **不用**。「指」是词条腔，用户要的是人话。用「一张卡只要……就挂这条」这种直接对话的句式 |

### 2.1 逐条新定义 / 新边界

以下文本已吸收对抗检验中我采信的修正。字数为估算，落库前应跑一次机械字数校验。

---

**保留原名 · 改定义（9 条）**

**奥义**（1 处 · 居合）
- 定义：`一条职业线压箱底的那一记：第一次按下去之前得攒大半场的职业资源，一按就奔着一锤定音去，一场战斗基本只按得动一两次。剑圣的居合就是这一记。`
- 边界：`不含攒几下就能再来的爆发招——拔刀打三下就回本、隔两回合又能放。打死人之后能立刻再按一次不影响判定，看的是第一次按下之前要攒多久。这一招能不能顺手斩杀残血跟它无关，那是《处决》管的，两条可以同时挂。`
- 变更理由：原文用「奥义级」解释「奥义」，判据「高消耗、强效果」无阈值且已在活语料里翻车（拔刀消耗整个印记池 + 20 剑气、暴击叠到 ×3.0、带溅射，字面全占却没挂）。新判据换成**首次按下所需的积累**——这里采纳了对抗检验的关键修正：原提案用「回本速度约 2:1」，但居合击杀时返 3 剑气并 cd-1，净成本与拔刀完全一致，判据在它自己的典型场景里会溶掉。
- **如实记录分歧**：对抗检验标了矫枉过正，认为「同时新增资源门槛、伤害量级、使用频率三重硬约束」是本轮任务催生的过紧。我判断在补上「主判据只有一条、其余降为例示」之后过紧消解，但这个判断本身可被推翻。

**反应**（3 处）
- 定义：`起因是敌方或外部来源打到你身上，才会启动的应对；它不占你的回合，也不花你的行动。卡的触发条件写的是别人对你做了什么，就挂这条。`
- 边界：`不含交战里人人本来就会的普通还手——那不是卡给的。不含起因是你自己出手的：主手暴击时、击杀敌人后都不挂。与《自动》可同时挂：自动看用不用你操作，本条看起因是不是别人打你。`
- 变更理由：原文「被攻击/被触发」的「被触发」一支按字面覆盖所有写了 trigger 的卡（10 张条件触发卡全符合，实际只挂 2 张）。采纳两处对抗修正：判据改为**只看起因、不看效果何时兑现**（否则「触发在被打、收益在你进攻」的卡判不了）；兑现口径从「敌人打你」放宽到「敌方或外部来源作用到我方」（十字受的 trigger 原文是「自身回合外受到伤害时」，不是「被攻击时」）。定义里的卡名已按 1.3 的规则删掉。

**区域**（2 处 · **有硬前置，见 D10**）
- 定义：`这张卡打出去时，伤害盖住的是一片连在一起的格子——一条线、一个十字、身边一圈——站在里面的敌人都会挨到。只要打击形状不止一格就算，哪怕这一次里面只站了一个人。`
- 边界：`只盖一个格子、但在那格上连打好几下的不算，那是同一个人挨了多下。只挪自己位置、不伤人的归《位移》。又挪自己又打沿途格子的，两条都挂。不看站位、按条件点名的不算（比如「打所有带某印记的敌人」），那是多目标不是区域。`
- 变更理由：原文三个同义词叠放（区域／范围／area），零信息增量。采纳三处对抗修正，都是实质的：判据从「打中几个人」改为**打击形状**（否则同一张卡在不同战局判定会翻转）；补「连在一起的格子」（否则点名式多目标会被吸进来，tag 失去构筑区分度）；补混合型双挂条款。另按对抗建议**取窄版**，删掉原稿的「或效果」——范围治疗／增益目前零实例，为假想内容立法不划算。

**位移**（2 处）
- 定义：`这张卡当场把自己或目标从这一格挪到另一格：突进、闪身、把敌人击退或拉近都算。就算这一次被挡住没挪成，它的效果本来就是要挪位置，照样算。`
- 边界：`只改「每回合能走几格」的额度不算——那是走多远的预算，人还是自己走的。只拿「本回合走了几格」当触发开关的也不算，走那几格是你自己走的。注意这两条说的是「光有这个不够格」，不是「有这个就不能挂」——走够三格才能放的突进技，突进本身就是位移，照样挂。每回合的常规走位更不算，那不是卡产生的。`
- 变更理由：原文把标签名「位移」逐字拆成「位置移动」再拼回去，是比「攻击」更纯的同语反复。采纳两处对抗修正：排除条款从「按卡的类别排」改为**按理由排**并补防误杀句（否则「走够格数才能放的突进技」被误杀）；边界**不再点名《战棋》**（战棋本身正在重做，点名会连带失效）。另按对抗建议换掉存废论证的主证据——技能侧已有 `skill_type=位移` 三重标记，tag 在技能侧确实冗余；它真正不可替代的理由是**天赋表没有 skill_type 字段，tag 是跨天赋+技能统一检索「挪格」的唯一句柄**。

**攻击**（15 处 · 并列全表第一）
- 定义：`这张卡直接参与你打出的攻击。两种都算：它本身就是一次攻击（斩击、居合），或它改变攻击的结果——打不打得中、暴不暴击、打多少伤害、多打几下。先做铺垫、之后那一击才兑现的，也算。`
- 边界：`不含只改基础属性面板的：力量 +2、技巧 +2 不挂，属性是常驻数值、不在这次攻击的结算里；但直接改命中率、暴击、伤害量的挂——这些数只在你打人那一刻起作用。不含只减自己挨的伤（招架、十字受）；两头都占的按打人那侧挂。不含拿击杀当触发、好处不落在那一击上的，那归《处决》。`
- 变更理由：原文是全表最纯的循环定义。采纳两处对抗修正，都是硬伤：**必须把「加暴击/命中」与「加力量/技巧」显式分开**（两者卡面形态都是「某某 +N」，原边界只写「纯属性平加不挂」会让读者把「暴击 +20」误读进排除项）；**「那一击」必须包含事后兑现**（否则标记-兑现型卡判不了）。同时按对抗建议**撤掉「82% 天赋挂载是假的」这个数字**——那 9 张里有 5 张的 effect 原文本身就带「造成」二字，按常识读法并不与原定义冲突，这是伪精度。
- **如实记录分歧**：对抗检验标了矫枉过正，认为把「攻击」压到「必须对应一次具体击打」是过头，语料现行用法本来就宽。我判断补上「事后兑现」和「暴击/命中平加算」两句后消解。

**资源**（8 处）
- 定义：`某个职业线独有的一条数值储备，比如剑士线的剑气。一张卡只要改变了你手上这条储备的多少，就挂这条：涨得更多、花得更多、能存的上限变了、跟别的东西的兑换比例变了、平时会自然消散的现在不消散了。`
- 边界：`不含人人都有、不分职业的数值——血量、每回合能走几步能打几次（R3.2）。只拿剑气或印记当触发开关、不改变它增减的不挂（梯云纵、气贯长虹）。拿职业资源去换通用数值的仍然挂，因为它花掉了资源。`
- 变更理由：原文的「任意」与用户裁定的「职业自身特有」直接冲突（按字面 HP、MOV、R3.2 的「行动资源」全算，且规则组名就叫「行动资源」，字面撞名）；漏掉了「耗」这一支，导致纯消耗卡（十字受、心眼·彻）按 tag 定义不该挂、按 KB §6 该挂。采纳三处对抗修正：「改换算率」这个行话换成人话；「两条都挂」的悬空指代点名；**撤掉「零反例」这个说法**——守破离是第三类（改印记的获取规则但不改数量），真实分布是 8 张改收支全挂 + 3 张纯只读全不挂 + 1 张第三类，不是干净二分。

**增益状态**（1 处）
- 定义：`给自己或友军挂上一段会自己结束的好处——可能撑几个回合，也可能撑到被用掉一次为止；结束之后就没了。卡面只要给出的正面效果不是永久的，就挂本条。`
- 边界：`不含永久或条件常驻的加成——破竹、气贯长虹这种「条件满足就一直生效」的不挂，它们不进状态栏。与《资源》的区别：资源能攒起来、能自己决定什么时候花掉；这种好处攒不了也花不掉，只会自己结束。与《负面状态》的区别：看效果是好处还是坏处，不看挂在敌我哪一边。`
- 变更理由：原文循环定义，且**漏掉了本条唯一的判据——期限**（这就是它只挂到 1 张卡的直接原因：11 张常驻加成卡全部未挂，靠的是私人默契不是定义）。采纳三处对抗修正：核心判据从「随回合递减」改为「**会自己结束**」（R3.4 原文是「持续减层」，层数不等于回合数；且原写法漏掉计次型）；「负面状态＝加在敌人身上」这个区分标准是错的，改为按效果性质分；**必须显式处理疾如风**（评估者自己点名它是唯一争议卡，却在三卡测试和边界里把它绕开了）。按新定义疾如风应挂，挂载 1→2，见 D9。
- **如实记录分歧**：对抗检验标了矫枉过正，认为为了通过遮名测试把定义压成「随回合递减」这个过窄口径。这条批评我完全采纳，上面的新定义就是按它改的。

**负面状态**（**0 处**）
- 定义：`加在某个单位身上、会一直跟着它的不利效果：属性被压低、更容易受伤、行动被限制，或者每回合持续掉血掉资源。一张卡只要会给目标附上这种效果，就挂这条。`
- 边界：`不含一次性的扣血、扣资源和技能代价——当场结清、不会跟着目标走（回合末 -10 剑气、发动技能付的价码都不挂）。判据只看一件事：这次结算结束后，效果还留在目标身上吗——按回合数计、按次数计、还是只要施法者在场就维持，都算留着。与《增益状态》的分界：看效果是好处还是坏处。`
- 变更理由：原文是从「增益状态」机械复制换两个字得来的，连不适用于负面的「受**加成**的单位」都原样留着——这道残迹反过来证明两条都不是被当成独立定义写的。采纳三处对抗修正，第一条是致命的：**原稿的「属性被压低／行动被限制」二分把自己的旗舰样本排除掉了**（毒剑的中毒是每回合掉血，既不压属性也不限行动），必须补到四类；时长口径从「持续若干回合」改为「会一直跟着它」（覆盖按次数计、按条件维持）；R1.5 的施加判定从判据降为附注（原稿的四条排除例本来就全靠「持续」这一根轴排得掉，R1.5 从头到尾没干活，反而在光环型效果上给出相反答案）。
- **零挂载为什么仍保留**：R1.4 / R1.5 / R2.1 / R3.4 四条 **status=锁定** 的规则已把 debuff 子系统写死（R1.5 是专为它设的独立施加率公式，R2.1 把 LCK 一半的战斗意义挂在它上面）；装备「毒剑」的 notes 明写「命中后附加中毒；demo 阶段未接入减益结算机制」；而 `/api/equipment` 的 22 条记录**根本没有 tags 字段**，毒剑想挂也挂不上。零挂载完全被「内容尚未铺开 + 载体无字段」解释掉，不需要动用「概念没用」这个假设。

### 2.2 用户点名的三条 + 印记，单独展开

#### 【系统】—— 全表最不合格的一条，但不该删

**原文**：`definition =「和游戏底层逻辑挂钩」，boundary = ""`

**用户说它「意义不明」的精确成因，有两层，第二层此前没被抓住：**

第一层是外延等于全集。伤害结算是底层逻辑，移动是底层逻辑，出手序也是——按字面读，全库没有一张卡不符合。一条对全集成立的判据划不出任何集合。

第二层才是根因：**定义指的概念，和两张挂载卡实际体现的概念不是同一个。** 「底层逻辑」在中文里最自然的读法是工程实现层。按这个读法，库里真正「挂钩底层逻辑」的是疾如风（rules 自述「本回合累计移动格数为新增追踪口径，实现方式需引擎侧确认」）和起手式（「战斗开始时为本批新增时机窗口词汇」）——两张都明写需要引擎新做支持，却都**没有**挂系统。反过来，真正挂了的两张在实现上并不特殊，特殊的是它们**在游戏虚构层改写了一条既定规则**：二天一流「失去防具槽，替换为副手武器槽位」，守破离「获得印记时可自选其种类」（默认口径是随机，见拾遗）。

也就是说：挂 tag 的人心里想的是「改规则」，写下来的却是「挂引擎」。任何按定义办事的人都会挂错方向，任何按现有实例模仿的人又找不到定义支撑。前一层的宽泛把这处错位掩盖住了——正因为「底层逻辑」宽到什么都能装，两张按另一套标准挂上去的卡才没显得违和。

**为什么不删**（三问全部指向保留）：
1. 挂它的卡当初想表达什么？不是猜的，是从 effect 原文读出来的：一个改槽位结构，一个改获取方式。其余 19 张天赋无一例外都在既定规则内产收益（加伤害、加暴击、加剑气、位移）。共同点真实存在，而且很窄。
2. 这层意思有别的 tag 能接吗？没有。印记、资源是题材轴，自动、反应是时机轴，攻击、位移、区域是形态轴。「改的是规则本身还是规则内的收益」是一条正交的轴，现有 12 条无一承载。**归并在技术上不成立**（下面有一处修正）。
3. 删掉后语料怎么办？会丢掉全库唯一一条「哪些卡在改规则」的检索入口。这条入口的价值可量化：二天一流的下游有 4 张卡（十字受、二刀开刃、剑气回荡、燕返）的 `unlock_trigger` 写着「前置:二天一流(双刀池)」，守破离是印记池前置。挂系统的两张恰好是全库仅有的两个构筑簇开启点。改规则的卡必然引发组合爆炸，是平衡审查里风险最高的一类，恰恰最需要被单独捞出来。另外二天一流处于 **锁定** 状态，删 tag 要动锁定卡。

**必须修正的一处论证**：原提案写「没有合并目标，merge 在技术上就不成立」，这是断言不是论证。`资源` 的定义原文含「任意资源获取**或改写**」，而守破离干的正是「改写印记的获取方式」，同池的拾遗、印心都挂了资源、守破离反倒没挂——`资源` 是一个真实存在的**部分**合并候选。合并最终仍不成立，但理由要具体：资源覆盖不了二天一流（把防具槽换成副手槽是槽位结构，不是资源），两张卡不能同归一处。

**提案文本**：
- 定义：`这张卡动的是某条既定规矩本身——装备槽怎么排、印记按什么方式拿到手、结算按什么顺序走。改写了规矩本身的卡，都挂这条。`
- 边界：
  ```
  不含在既定规矩内产收益的卡：把剑气上限抬高，攒剑气的规矩没变，不挂；发一枚自选印记，
    是单次发放、没改获得规则，也不挂。
  不含只是援用已有例外的卡：规则里本来就允许的（免费移动、反应不消耗行动资源），
    或继承上游卡已经开好的口子的，都不挂。
  不含只是引擎不好实现的卡：卡面没改任何规矩、只是实现上要新记一笔账，那是工期，不是规则改动。
  与《资源》的分界：资源看这张卡对收支做了什么，本条看收支的规矩本身被没被改。
  ```
- **必须补的一刀（对抗产出）**：原稿只钉死了「常驻构筑层的规则改写」，漏掉「战斗中条件性的规则改写」。在更宽的语料窗口里，重排结算顺序、让某个动作在别人回合也合法、资源溢出转存这类卡是一整族，按定义字面全该挂、实际都没挂。**必须在边界里明确本条只管哪一层**，或者显式把战斗中的规则改写也收进来。这一刀不补，系统会重新长成一条外延失控的 tag。这项需要用户定（见 D6b）。
- 三卡测试：应挂＝二天一流（把防具槽换成副手武器槽）；像但不该挂＝残心（自选印记的措辞与守破离一模一样，但它只是单次发一枚，守破离改的是「今后每次获得印记都能自选」——这一对是全表最容易混的地方）；明显无关＝破竹（对半血以下敌人伤害 +5%）。
- **改名候选**：`系统` → `改规则`。理由：按上面第二层诊断，「系统」这个词本身就是引擎误读的磁石，只改定义句留不住这个误读——设计者在标签选择器里只看到那两个字。成本最低（2 处挂载，其中一张是锁定卡）。

#### 【战棋】—— 用自家游戏的品类名当分类标签

**原文**：`definition =「战棋层机制内容标签(含 MOV·出手序·格位)。」，boundary = ""`

**病根**：这个游戏本身就是战棋游戏。按字面读，21 张天赋 + 6 个技能没有一张不在战棋层里发生。用户说的「意义不明」不是嫌文字晦涩，是**名字承诺的范围和实际想指的范围差了一个数量级**。而全句唯一有信息量的「MOV·出手序·格位」被塞进圆括号当补充位，「含」字还明示不穷尽——读者无从知道这三样之外还有什么算，三个词用「·」并列也没交代是「任一即可」还是「须全占」。三个专名一个都没展开（MOV 是什么没说；「出手序」没说它其实由速度决定，而这正是起手式挂它的唯一理由）。

**落到实处的后果，有数据**：正因为「出手序」只在括号里露了个词、没接上「速度」，全库 3 张改速度的卡分裂成 1 挂（起手式）2 不挂（心眼·彻、心眼技能）。这条 tag 在生产库里没有被一致执行。

**提案文本**：
- 定义：`单位能走多远（移动力）、什么时候轮到它出手（速度）。一张卡只要让你走得更远或更近、更早或更晚出手，或者拿本回合走了几格当触发条件，就挂这条。`
- 边界：
  ```
  不含只是「发生在棋盘上」的卡：攻击、印记也都发生在棋盘上，不挂；必须动到移动力或出手顺序。
  不含单次位置变化：回避后挪一格只改站位、不改移动力，归《位移》。
  让你插队一次或多打一次的也挂——它改的就是出手顺序。
  ```
- **我把这一条从「改名」降到了「改定义 + 改名附条件提案」**。理由是对抗检验的一处方向性论证，我认为它成立：rename 的核心论据是「名字外延=全库，读者会以为什么都算」，这预测的失效模式是**过度挂载**；但生产库呈现的恰好是反面——零处误挂，3 张符合条件的改速度卡里有 2 张**漏挂**。数据没有为 rename 所要治的那个病提供任何证据。改名仍可辩护，但要靠另一条从未被陈述的机制（名字空洞 → 设计者干脆忽略这条 tag → 漏挂）。按已陈述的论据，改定义单独就能修掉 100% 的可观测缺陷。
- **两处必须修正的引证**（对抗检验抓到）：① 「资源按其自身边界明确排除 MOV」——13 条 boundary 全是空串，不存在可引的边界文本，该排除实际来自定义括号「（资源系统每职业独立）」+ R2.1；② 「3/21 属中位偏低」——实测挂载分布中位数是 2，战棋的 3 处**高于**中位，与反应并列第五。这处偏差的方向是低估自己 tag 的使用量，即偏向删除，而评估者仍拒绝了删除。
- **落地代价（原提案没计价）**：新定义把速度接到出手序上，采纳后**必须补挂心眼·彻与心眼两处**，挂载 3→5。不补则定义修好了、可观测缺陷仍原样留在数据里。另外新定义**把「格位」移出了外延**（旧定义明列 MOV·出手序·格位），没有卡因此被卸载，但以格计量的拔刀（周围 1 格溅射）、一闪（最远 4 格）从「可争」变成「明确不算」——这是实质范围收缩，需与「只读算不算」同等交裁。

#### 【处决】—— 名实错位的最纯样本

**原文**：`definition =「击杀/斩杀类收益与触发的机制标签。」，boundary = ""`

**这一条有独特的教学价值**：它的定义里**不含**「处决」二字，机械上**通过**了遮名测试，却依然完全不可判定。原因恰恰是名实错位——定义描述的本来就是另一个概念，名字当然不会出现在里面。「不循环」是必要条件而非充分条件，这条是最纯的样本。

**病根**：「处决」在战棋 RPG 语汇里强烈指向斩杀线（血量低于某阈值即死）。而它的实际外延是「击杀之后拿一份额外回报」。已核对 20 条 rules、6 条 terms、27 张卡，**斩杀线实例数为 0**——定义用一半篇幅（「斩杀」那一支）指向一个空集。再叠上「收益与触发」的名词化（三种互不相容的读法：击杀后获得收益／击杀作为触发条件／具备造成击杀的能力），读者拿到任何一张卡都判不出来。

**但概念本身被 100% 正确执行**：引擎层给了机械判据——6 个技能里只有居合的 `qi_gain_on_kill` 非零（=3，另有 `ki_on_kill_cd_reduction=1`），而它正是唯一挂处决的技能；天赋侧全库扫描后只有介错命中真实击杀语义，它也挂了。零误挂、零漏挂。一条**外延模糊到无法判定**的 tag 不可能在语料上呈现这种表现——模糊的是文字，不是概念。另有 R1.4 把「击杀」列为 after-damage 的一等触发时机，居合的 engine tags 直接写着 `"execute"`。

**归并的两个候选都会丢卡**：并入《攻击》丢介错（damage_type=无，完全不造成伤害，本身也没挂攻击）；并入《资源》丢居合（没挂资源，且减 CD 这类回报根本不是资源）。没有任何现存 tag 能同时覆盖这 2 张卡。

**提案文本**：
- 定义：`「把敌人打死」当触发条件、打死之后才拿到的那份额外回报。只要意思是「先杀掉、再给你一份东西」就挂，不看卡面用的是「击杀后」「击杀时」还是「击倒目标则」。`
- 边界：
  ```
  不含只是伤害高、顺带打死人的卡：把人打死本身归《攻击》；遮住「击杀返还剑气」那一句，
    剩下的部分还挂不挂？不挂，就说明挂的是那一句而不是那把刀。
  不是「血量低于某线直接斩杀」：SoT 没有这条线，别照名字的字面挂。
  击杀得是自己打出来的：「场上任意单位死亡时……」那类不挂，那是死亡触发。
  回报是剑气、印记这类资源时，《资源》一起挂。
  ```
- **必须采纳的对抗修正**：原稿的定义写「卡面写了『击杀后……』就挂」，这是一条**字符串匹配**判据，而它自己举的旗舰例居合卡面原文是「**击杀返还** 30 剑气」，根本没有「击杀后」三个字。一个严格按定义字面执行的读者会在旗舰例上判错。真正在干活的是**时序语义**，字面写法必须改掉，否则「击杀时」「击倒目标后」这些同义措辞全会漏判。这就是规范 S11 的来源。
- **改名候选**：`处决` → `击杀回报`（优于「击杀」，后者仍会被读成「能造成击杀」）。理由：名实错位是根因，改定义只是在错的名字外面加护栏，每个新读者仍会先撞上误导性的名字。成本已量化：生产库 2 处挂载，引擎层**无需改动**（居合的 engine tags 已经是 `execute` 而非中文处决），无规则引用该 tag 名。
- **改名与 D-斩杀线的绑定**：如果 SoT 将来确定要做斩杀线机制且归入本条，那么「处决」这个名字反而是对的，不该改名。**建议先答「会不会做斩杀线」，再答「改不改名」。**
- 顺带记录（非 tag 层）：居合的 effect 写「击杀返还 30 剑气并 **+1** cd」，engine_json description 写「本技能 **cd-1**」、字段名 `ki_on_kill_cd_reduction`（reduction＝减少），增减方向措辞相反，疑似卡面笔误。同卡 30 剑气 vs `qi_gain_on_kill=3` 的 10 倍差**不是** bug，是 R1.6「常规获取消耗用 10 的倍数」的既定换算，勿一并改。（2026-10-28 补注：“10 的倍数”已被用户 2026-10-24 裁决改为“剑气数值取 5 的倍数”，见天赋设计要点 §4；本条只作历史记录。）

#### 【印记】—— 用户提示「某种意义上也应属于资源」，我的处理与它的代价

**原文**：`definition =「剑意印记机制标签：0-3 离散槽位（心/道/势）。」，boundary = ""`

这条整句**没有谓语**，冒号前后都是名词短语，全条零动词。读者读完不知道印记会发生什么——怎么获得、怎么失去、攒满了干什么。而且它是 term 表的一份**会漂移的残缺副本**：term「剑意印记」原文是「0-3 离散槽位（心/道/势）；心 → 技巧、道 → 幸运 LCK、势 → 力量。」，tag 抄走了分号前半截，丢掉后半截的属性映射，术语表一改它就静默失配。

**用户的提示怎么落地**：`/api/terms` 里「剑意印记」的 `category` 字段确实就是「资源」，与「剑气」同类目；R1.6 把职业特色资源定为通用槽位。所以印记是**资源的一个实例**，不是并列的另一类。处理方式因此既不是把印记并进资源、也不是让两者互斥，而是**写成实例关系 + 并挂规则**。

**为什么保留独立 tag（这是本条最需要用户拍板的地方）**：

反方最硬的证据是 KB `content-design-general.md` §5 当天刚立的规则，完整照引不截断：「**职业特色资源不设专属 tag**：产 / 耗 / 改写任何资源的卡统一挂「资源」（定义 = 任意资源获取或改写；用户 2026-07-20 裁决，剑气按此归并）。」按字面，印记就该并。

保留的理由：
1. 剑气与印记不同型，先例不自动传递。剑气是 0-100 无结构标量，并入资源零损失。印记带类型（心/道/势）、带上限门、带**技能槽替换**（满 3 枚时招架槽位被拔刀替换，`slot_swap_trigger=marks_full`）、带天赋前置树（守破离是「开启印记池相关天赋的前置节点」，另 4 张的 `unlock_trigger` 全指向它）。
2. **有一张卡会直接掉出去**：剑三昧（印记+攻击+自动，当前没挂资源）只读持有数、不产不耗不改写，按资源的定义不符合。并掉印记后它将完全失去与印记系统的任何 tag 关联。
3. 规则层还没接上：R1.6（**锁定**）枚举职业特色资源时**只写了剑气、没写印记**。印记的「资源」身份目前仅由 term 表一个 category 字段承载。在 R1.6 补上印记之前就按「印记=资源」执行归并，是拿一个尚未进规则表的等价关系做不可逆的删除。

**必须承认的一处取证错误（本轮最严重的一处，与上一轮同型）**：原提案引「资源」tag 定义时写作「任意资源获取或改写」，但生产库原文是「任意资源获取或改写的聚合内容标签（**资源系统每职业独立**）。」——它丢掉的括号里那半句，恰恰是**反方最强的文本支撑**：「资源」这条 tag 的定义里明写了它就是为「每职业独立的资源系统」做聚合而设的，印记正是标准样例。**漏掉的是打自己论点的那半句。** 这项已由对抗检验抓到，写在这里不隐瞒。

**提案文本**：
- 定义：`剑圣独有的蓄势槽位，最多同时存三枚，分为心、道、势三种；靠技能一枚枚攒起来，攒够了一次性花掉换强力效果。`
- 边界：
  ```
  产它、耗它、改它的规矩、读它的枚数或种类、或因它得失而触发的卡，都挂这条。
  不含剑气：剑气是同线另一条储备，只是一条数值、没有槽位也没有种类；只加减剑气、
    完全不碰印记的卡不挂。
  与《资源》的关系：本条是《资源》底下的一个具体品种，不是另一类东西；产或耗印记的卡
    两条都挂，只读枚数不增减的（剑三昧）只挂本条。
  ```
  采纳的对抗修正：「分心、道、势」改为「分为心、道、势三种」（原写法「分心」会被读成另一个词，要回读一次）；判定式补上「或种类」（否则只认单一种类的卡不覆盖）；不点死消耗渠道（tag 定义不该锁死「必须用拔刀花掉」）。
- **落库后果（必须交用户，我不自行补挂）**：按并挂规则，需补挂《资源》的有——技能 斩击（`mark_gain=1`）、居合（`mark_gain=1`）、拔刀（`mark_cost=3`）三个；天赋 守破离（改的是「印记怎么获得、每枚给什么」＝改写规矩）待定。剑三昧按本口径**不补**。
- **本次核查新发现的一处实挂错误**：技能「招架」的槽位存废被印记枚数直接门控（effect 原文「满 3 印记槽时本技能槽位替换为拔刀」，`engine_json.slot_swap_trigger=marks_full`），但当前 tags 只有 `[反应]`。按新定义它应挂「印记」。**这不是定义问题，是数据漏挂；我未做任何修改，仅报告。**

#### 【自动】—— 本轮分歧最大的一条，两个方案都摆出来

这一条是唯一一处我认为**评估者与对抗检验的分歧未被任何一方说服**，必须原样交用户。

**共识事实**（双方都独立复核过，无争议）：
- 原文 `definition =「自动触发/被动生效的内容标签。」，boundary = ""`
- 挂载 15 处（天赋 14 + 技能 1），与「攻击」并列全表第一（不是唯一最高，评估者这处说法要改）
- 技能「心眼」的 tags 只有 `[自动]` 一个，删 tag 会造成零 tag 技能
- 天赋表**结构上没有 action_cost 字段**，21 张天赋的 `engine_json` 全为空串 —— 所以天赋层不存在「玩家花行动主动使用」这种形态
- 21 张天赋按「trigger 是否永久生效」×「是否挂自动」交叉分类，四格全部非空，**9 张（43%）与任何单一挂载规则冲突**

**分歧在于这 43% 说明什么：**

| | 评估者 | 对抗检验 |
|---|---|---|
| 诊断 | 那条斜杠许可了两种打架的读法（「自动触发」＝在某时点自己发动一次；「被动生效」＝一直挂着的常驻修正），43% 是这句话自己许可出来的 | 双向性是被结论预设出来的。**读法甲（自动＝不需玩家花行动激活）误挂 0 张、漏挂 7 张，是纯单向误差**；读法乙（常驻）误挂 6、漏挂 3，才是双向。单向误差＝「规则对但执行懒」，双向误差才＝「规则错」 |
| 方案 | 改名「自动」→「常驻」，重挂 9 张（摘 6 补 2 存疑 1），tag 数不变 | 保留「自动」按字面钉死并**收归技能层**（天赋一律不挂），摘掉 14 处天赋挂载；「常驻」轴另开一条**新** tag。改动约 25 处，tag 数 +1 |
| 风险 | rename 保留 id=10，所有既有引用**静默改变含义**，不报错；一个改掉 43% 外延的改名已经不是改名了 | 摘掉 14 处后「自动」只剩 1 处，几乎等于废掉；总工作量更大 |

**我的裁定**：对抗检验的**方向性论证（单向 vs 双向）我采信**，它是本轮最锋利的一处方法论；但它的方案（选项乙）代价更大。所以我给第三个方案——**取评估者的语义、取对抗检验的安全性**：

> **退役 `自动`（id=10），新建 `常驻`（新 id），重挂 9 张。**
>
> 执行上等于 delete + create 而不是原地改 key。这样新旧两个概念集合不共用 id，下游引用会立刻断掉并暴露出来，而不是静默改变含义；改动量停在 9 张，不是 25 张。

这不是折中，是把对抗检验的核心担忧（id 复用导致静默漂移）用最小成本解掉。

**两条路共有的缺口**：被摘掉的 6 张事件触发卡（十字受、拾遗、印心、起手式、疾如风、残心）的「触发式」形态就没有 tag 承接了。我建议**接受这个缺口**，因为 trigger 字段已经承载了这个信息；是否新增一条「触发」tag 属 tag 增删，交用户（D14）。

**待补挂的两张**：二天一流（失去防具槽换副手槽，常驻）、二刀开刃（副手特效以 50% 生效，常驻）。**混合卡（心眼·彻：常驻主体 + 回合末时点尾巴；守破离：常驻 + 获得印记时自选）的规则必须先裁决，规则未定之前不要开始重挂。**

## 三、取消分层的落地影响

tag 不再分 mech / content 两层。以下是改动清单。**我没有 SoT 应用仓库的读取权限（它不在 Mercury 工作树内），所以带 `[路径待核实]` 标记的条目是按材料推断的位置，落地前须实地核对。**

### 3.0 顺序（这一项最重要）

```
① 先处置 R5.9  →  ② 再改数据层  →  ③ 再改 API / 前端  →  ④ 最后改 KB
```

**R5.9 是唯一的阻塞项**。原文：「分层判定表：按**机制层/内容层**分层解析技能与天赋的触发与结算顺序。」status = **草稿**。这条规则直接依赖被取消的分层，取消后它会悬空。按规范 S8 的可删性原则——**先把规则落到它该在的地方，再从上层删除，不得直接删掉了事**。选项：(a) 该规则本就是草稿、从未生效 → 直接作废；(b) 分层解析的结算顺序确有需要 → 改写成不依赖 tag layer 的表述（比如按 `trigger` 类型或 `action_cost` 分层）。**这一项要用户先定，其余全部等它。**

### 3.1 数据层

| 对象 | 改动 | 备注 |
|---|---|---|
| Tag 模型的 `layer` 列 `[路径待核实]` | 删列，或先改为 nullable 再在下一轮删 | 建议两步走：先停止写入、前端停止展示，观察一轮再删列 |
| 数据库 migration | 需新增一条 | 若走两步，是两条 |

## 四、需要用户裁决的清单

**tag 的增删并属用户裁决域。以下全部是提案，我一项都没有执行。** 按依赖顺序排列——D10 是唯一的技术阻塞项，D-总 是执行节奏。

---

**D10（阻塞项，最先办）· 「area 攻击不触发反击」这条规则往哪搬**

「区域」的定义里焊着这条战斗规则，而它是**全库唯一副本**：R4.3「射程与攻击线」全文无反击条款；term「combat」写的是「area 攻击与反击不触发**连锁**」——是另一件事；KB 两处反过来引用 tag 定义作出处。**新定义在规则落地前不可上线**，否则改写等于删掉这条规则。

- 选项 a：扩写 R4.3 现有条文 → 改动最小，R4.3 本就定义了 area=AOE，是天然归宿
- 选项 b：新开一条 R4.4 → 更清晰，但规则表多一条

**同时必须先定一个前置事实**：tag 定义说「不触发**反击**」，term combat 说「不触发**连锁**」。这是两个逻辑上独立的判断，可能同时成立，也可能是同一条规则漂移出的两种写法。**范围攻击到底会不会引来对方反击？** 这个不定，规则搬不了。

**推荐**：先答「会不会引来反击」，再走选项 a。

---

**D1 · 印记与 KB §5 的字面冲突**

KB §5「**职业特色资源不设专属 tag**」是一条通则，剑气只是它的第一个应用实例，印记是同一通则下尚未应用的第二个实例。

- 选项 a（通则字面适用）：印记并入资源。**代价已量化**：剑三昧完全失去与印记系统的 tag 关联；「哪些卡碰了印记子系统」这个查询消失；招架的槽位门控事实无处安放
- 选项 b（通则只管无结构的标量资源）：带子系统结构的资源（印记：三槽位 + 类型 + 技能槽替换门 + 天赋前置树）可保留专属 tag

**推荐 b，并且必须同批把这个限定补进 §5**。让规则和 tag 同时立着，下一个读 §5 的执行者会再删一次——这是必须一起做掉的，不能留。

---

**D2 · 「只读取、不增减」算不算动资源**

这一条同时决定剑三昧的归属，以及「资源」会停在 8 张还是继续膨胀。生产库现状是干净的：改收支的 8 张全挂、纯只读的 3 张全不挂。

**推荐：不算。** 理由是这条线现挂载者已经在无意识地执行，写明它等于零改动地把现状固化，同时消灭最大的一处实操歧义。

---

**D3 · 技能侧「资源」5 处欠挂怎么处理**

6 个技能里 5 个明确产/耗剑气或印记（斩击、一闪、招架、居合、拔刀），全部未挂资源，与 KB §6「产 / 耗 / 改写资源挂「资源」tag」直接矛盾。

- 选项 A：按 KB 原文补挂 5 个 → 语义一致，但资源在技能侧变成 5/6，几乎失去筛选力
- 选项 B：给「资源」加一句「技能自身标价的常规产出与消耗不算，只有偏离常规收支才挂」→ 技能侧维持 0，天赋侧 8 张全部仍成立；但必须同步改 KB §6 措辞

**推荐 B**，理由是用户原话：「可以通过技能的**特殊机制**进行获取和消耗」——「特殊机制」不等于「技能自身的标价」。这四个字是用户给的口径，B 案更贴合它。

（注：原评估提案暂按 A 写，并明确拒绝了「用边界写窄来掩盖语料缺口」的捷径。我改推 B，是因为用户原话给了独立依据，不是为了消灭工作量。这个分歧如实呈现。）

**D4 · 「自动」怎么办（分歧最大）**

三个方案，详见 2.2：

- 甲：改名「自动」→「常驻」，沿用 id=10，重挂 9 张 → 改动最小，但下游引用静默改变含义
- 乙：「自动」钉死字面并收归技能层，摘 14 处天赋挂载；「常驻」另开新 tag → 语义最干净，改动约 25 处，tag 数 +1
- **丙（我的推荐）**：退役 `自动`(id=10)，新建 `常驻`(新 id)，重挂 9 张 → 取甲的语义、取乙的安全性；新旧概念不共用 id，下游引用会立刻断掉并暴露

**前置**：混合卡规则（心眼·彻、守破离这类「常驻主体 + 时点尾巴」）必须先裁，规则未定之前不要动挂载。建议口径：以效果主体判定，尾部的资源结算不改变归类。

**D5 · 「战棋」的范围与命名（三个子项）**

- **D5a 速度/出手序留不留？** 留（推荐）→ 需补挂心眼·彻、心眼两处，挂载 3→5，新名建议「移动与出手」；不留（收窄到只管移动力）→ 需从起手式摘掉本 tag，新名建议「机动」。**推荐留**，因为它不缩减 tag 已声明的范围，属保守选择
- **D5b 「格位」移出外延，接受吗？** 新定义只覆盖移动距离/出手顺序/读取移动格数，以格计量的溅射与射程明确归《区域》《位移》。无卡被卸载，但属实质范围收缩
- **D5c 改不改名？** **推荐本轮只改定义、暂不改名**，理由见 2.2（rename 的论据方向与数据相反）。若改，先答 D5a 再定名

**另一个更上位的问题（对抗检验提出，值得先答）**：名字必须写成带「与」的连接词（移动与出手），通常是「这其实是两个 tag」的信号。**是否拆成《移动力》和《出手顺序》两条？** 拆开后判定无歧义、定义更短；合并的理由是两者同属行动经济层，同时改两项的卡不少，拆开会造成大量双挂。这一项我给不出推荐（缺卡池分布数据），交用户。

---

**D6 · 「系统」（两个子项）**

- **D6a 改不改名为「改规则」？** **推荐改**。理由：按 2.2 的第二层诊断，「系统」这个词本身就是引擎误读的磁石，只改定义句留不住这个误读。成本最低（2 处挂载）。**但二天一流是锁定卡**，改名需确认锁定卡能否改动
- **D6b 只管构筑层的规则改写，还是也管战斗中的？** 现提案只钉死了常驻构筑层。战斗中条件性的规则改写（重排结算顺序、让某动作在别人回合合法、资源溢出转存）在更宽的语料窗口里是一整族，按定义字面全该挂、实际都没挂。**不补这一刀，系统会重新长成一条外延失控的 tag。** 我倾向「只管上场前那一层」并在边界里写死，但需用户确认

**D7 · 「处决」改不改名为「击杀回报」**

**推荐改**，但**先答 D7b**。

- **D7b（先答）**：SoT 将来会不会引入「斩杀线」（低血量直接处决）？若会且归入本条，则「处决」这个名字反而是对的、不该改名，且定义要把两个机制并列写清（正是原定义想做但没做成的事）；若不会或另开 tag，则改名
- 改名成本已量化：2 处挂载，引擎层无需改动（居合的 engine tags 已是 `execute`），无规则引用该 tag 名

**D8 · 「增益状态 / 负面状态」要不要与规则层的「减益 / buff-debuff」统一命名**

三条锁定规则统一用「减益」（R1.4 减益施加、R1.5 减益施加率、R2.1 减益抵抗），R3.4 用英文「buff/debuff」，tag 叫「负面状态」。三处措辞不一致。

**推荐：不改 tag 名，改 KB 与规则的表述向 tag 靠拢。** 理由：「减益」字面可涵盖一次性的属性下调，而「状态」明确了 R3.4 那层「有生命周期、会结束」的含义——正是新定义要立住的核心特征。「状态」比「减益」更准确。

---

**D9 · 「撑到被用掉一次为止」算不算增益状态**

具体卡：疾如风（本回合累计移动 3 格以上后，下一次攻击 暴击 +20、伤害 +10%），当前未挂增益状态。

**推荐：算**。新定义的核心判据是「会自己结束」，一次性充能符合。挂载 1→2。若判不算，则这类「一次性充能」形态在 tag 层没有任何归属（现只靠「自动」承接），今后数量增多时需单开一条 tag。

**D11 · 定义与边界的呈现形式** —— 我已在第一节裁定为「分字段存 + 非空校验 + 合并渲染 + boundary 分行」。列此供确认。

**D12 · 长度预算改数字** —— 从「边界 ≤50、合计 ≤110」改为「定义 ≤60、边界 ≤120、合计 ≤168」。依据是 12/13 条成稿突破了 50 字。**推荐采纳**，一条 12/13 做不到的规则不是约束。

**D13 · 挂载统计的窗口口径** —— 详见第五节。**推荐：存废判断用「在用」窗（21 天赋），边界可判定性测试用全库窗（49 天赋），两个数都记录、都标窗口。**

**D14 · 要不要新增「触发」tag** 承接被「常驻」摘掉的 6 张卡的形态？**推荐暂不新增**（trigger 字段已承载），记为观察项。

**D-总 · 执行节奏（这一项决定其余全部的落地方式）**

本提案含 **13 条改定义 + 4 条改名候选**。两类改动的风险面完全不同：

| | 改定义 | 改名 |
|---|---|---|
| 动什么 | `definition` / `boundary` 两个文本字段 | `key` 字段、可能连带 id、下游引用、KB 引用、锁定卡 |
| 可逆性 | 完全可逆 | 需要迁移，静默漂移风险 |
| 依赖 | 只依赖 D10（区域的规则迁移） | 依赖各自的范围裁决先定（D5a、D6b、D7b） |

**强烈推荐分两轮**：

> **第一轮**：13 条定义 + 边界全部重写落地，取消分层同批做（因为 10 条正文里焊着层级词，一次做完最省），加 boundary 非空校验。**零改名。**
>
> **第二轮**：4 条改名（处决、自动、战棋、系统）单独走，每条先答清各自的范围裁决题，再定名。

理由：改名的收益是长期的（防止新读者被名字误导），代价是即时的（迁移风险 + 动锁定卡）。把它和低风险的文本重写捆在一起，会让整批改动都变成高风险改动。

### 5.2 本轮真正的偏差在哪里：一个对抗 lane 的判定工具输出恒为否定

拆开看那 58%：

```
对抗 lane #1：boundary_is_decidable  false 13 / true  0   ← 13/13 一边倒
对抗 lane #2：boundary_is_decidable  false  2 / true 11
```

**lane #1 是 13/13 全判「不可判定」，与上一轮 18/18 完全同型。**

成因可诊断，不是玄学：lane #1 的方法是「自编三张卡去撞边界」。**任何有限长度的边界文本都存在边缘案例**，所以这个工具的输出恒为否定——它不携带区分信息。用它去区分「写得好的边界」和「写得烂的边界」，得到的永远是同一个答案。

**处理方式**：它的结论不能按面值采信，但它的**具体反例**要逐条看，因为其中一部分是真的、而且是本轮质量最高的产出：

| 采信 | 内容 | 为什么真 |
|---|---|---|
| ✅ | 区域：判据锚在「打中几个人」会让同一张卡在不同战局翻转 | 直接推导出规范 S11 |
| ✅ | 奥义：三个特征没说是「全中」还是「任一」，编出的卡两条判据给相反答案 | 直接推导出规范 S10 |
| ✅ | 负面状态：「属性被压低/行动被限制」二分把自己的旗舰样本（毒剑中毒＝每回合掉血）排除掉了 | 用它自己的例子证伪它自己 |
| ✅ | 处决：「卡面写了『击杀后』就挂」是字符串判据，而旗舰例居合卡面根本没这三个字 | 可直接核对 |
| ✅ | 位移：排除条款按卡的类别写而非按理由写，会误杀「走够格数才能放的突进技」 | 逻辑成立 |
| ✅ | 攻击：暴击既在定义里（改攻击结果）又在边界排除里（只加属性不算） | 卡面形态相同，读者必然踩 |
| ❌ | 各种「无论怎么写都会有灰区」型批评 | 这是分类学的普遍性质，不是本批定义的缺陷 |

同理，lane #1 的 4 次 `overcorrection_flag` 里有 3 次（奥义、攻击、增益状态）；lane #2 的 1 次（自动）。lane #1 那 3 次经我复核后，2 次（奥义、增益状态）的批评成立并已按它改，1 次（攻击）我认为补上两句后消解——**这三条我都在第二节如实标注了分歧，没有藏。**

### 5.3 第二个必须报告的发现：基线的采样窗口是窄的

这一条比上面那条更严重，因为它影响本提案里**所有**的挂载数字。

基线报告写「21 张天赋全部 shelf_state=在用，无已删除」，并声称用 `?include_trashed=1` 和 `?shelf_state=all` 两种参数复拉验证过。但：

1. 「区域」lane 实测：该端点会**忽略任意 shelf_state 取值**——传 `?shelf_state=NONSENSE_XYZ` 返回与基线**逐字节相同**的 14673 字节。所以那两次复拉不构成反证核查：参数被忽略，和「回收站真的是空的」会产生完全一样的证据。
2. 「负面状态」lane 实测：正确的参数名是 `include_shelved=true`，加上之后返回 **49 条**（在用 21 / 已归档 19 / 待删除 9）。

**结论：本提案里所有「21 天赋」的挂载统计都是窄窗数字。**

好消息有三个：
- 扩窗后**没有任何一条裁定改变**。负面状态在 49+6 全窗口仍为 0 挂载，且仍是唯一的零挂载条目
- 但三条的计数变了：**增益状态 1→2、奥义 1→4**
- 它顺带解释了一个此前看起来像「数据源不一致」的现象：lane #1 引用的一批卡（破釜沉舟、见切、先之先、影缝、无想剑、明镜止水、留气…）在 21 张窄窗里查不到，而 lane #2 用 curl 复核生产库时也查不到——它们很可能就在那 28 张归档/待删除的卡里。**lane #1 不是读错了数据源，是读了更宽的窗口。** 这反过来提高了它部分卡例的可信度，尤其是「系统」那条指出的「战斗中条件性的规则改写是一整族」。

**必做动作（不属裁决，属修正）**：所有挂载统计重跑一次，明确标注窗口；D13 定口径。

### 5.4 第三：上一轮的「截断限定词」错误小规模复发了一次

上一轮的四类取证错误里，第三、四类是「多个视角同时截断同一处原文 / 同时漏读一个限定词，而丢掉的恰好是打自己论点的那一支」。本轮复发了一次，规模小但性质相同：

> **「印记」lane 引「资源」tag 定义时写作「任意资源获取或改写」，而生产库原文是「任意资源获取或改写的聚合内容标签（资源系统每职业独立）。」**
>
> 它丢掉的括号那半句，恰恰是**反方最强的文本支撑**——「资源」这条 tag 自我声明了它就是为「每职业独立的资源系统」做聚合而设，印记正是标准样例。**漏掉的是打自己论点的那半句。**

已由对抗检验抓到，本提案 2.2 已如实写入并按它调整了论证结构（不再靠「先例不同型」这条已被削弱的推理，改靠可点名的语料损失 + R1.6 未收录 + 引擎字段簇）。

同批被抓到的其他小失实（方向、性质都记在这里）：

### 5.5 结论

**本轮没有重演「系统性偏向推翻现状」的偏差。** 存废层面 0 删 0 并，方向与上一轮相反，且每条保留都有独立取证（锁定规则背书、引擎侧镜像标记、下游前置树、可点名的语料损失）。用户点名的三条中，没有一条被顺手做成删除；用户给了一句听起来像删除授权的话（「印记某种意义上也应该属于资源」）+ 一条 KB 规则字面支持，评估者仍把它读成「属于」（子集语义）而非「等于」（合并语义），把裁决原样交回。这是抗住了诱导。

**但本轮出现了两个新的、可诊断的偏差，两个都必须写进下一轮的方法学：**

1. **判定工具的输出恒为否定**：一个对抗 lane 用「自编卡撞边界」的方法，13/13 全判不可判定。凡是「找边缘案例」类的检验，天然永真，不能按面值采信——必须换成「拿生产库真卡逐张判、统计判不出来的比例」这种有分母的检验。
2. **采样窗口过窄且自查失败**：基线用错了参数名去做反证核查，而该端点会静默忽略错误参数、返回与基线完全相同的响应，于是「查过了、没问题」和「根本没查」产生了一模一样的证据。**下次做窗口核查，必须用一个已知应当改变结果的参数做阳性对照**（比如先确认某个参数确实能改变返回条数，再用它去查）。

**另外还有一件事要说清楚**：本提案的 4 条改名候选（占 13 条的 31%）是一个需要警惕的比例。我的判断是它们共享同一种病理（名字的字面外延与实际所指不符），不是零散求变；但为了不让这个判断影响落地风险，我把改名整体推荐为**第二轮单独执行**，本轮不改任何一个名字。如果用户认为 31% 仍然偏高，最先该砍的是「战棋」（它的 rename 论据方向已被数据反驳，我已把它从 rename 降到附条件提案）。
