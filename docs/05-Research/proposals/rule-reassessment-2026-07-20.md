## 一、逐条裁定

### 1. `anti-homogeneity-six-dist`(通则 §12 L100)— **重写(轻度,原地改三处)**

**一句话理由**:六个自检维度与「3 次重复」阈值都站得住(原文措辞是「须**自检**」「局部最优**信号**」,不是闸门 [已核 L100];通则 §10 L85 另有「审阅是提醒器不是闸门」兜底 [已核]),真正过硬的只有句尾「必须换轴」四个字。

**三视角分歧**:三个视角一致判 partially-valid,但处方分歧极大 ——
- first-principles + superordinate:删维度1、删维度4、删「3 次」阈值,四维降格为线索
- counter-example:删「payload 类型」桶,改成「逐卡辩护」

**三个反驳者全部推翻,且推翻理由互相独立收敛**:
- 「3 次」阈值的证伪取证用了**全库累计语料**去量一条写死「单批产出」的 per-batch 规则 [已核 L100 计量单位确为「单批」/「一批内」],单位错配。
- 「维度4 与禁防御性条款堆叠冲突」是作用域误读:天赋册 §5 L84 [已核] 把「禁防御性条款堆叠」显式挂在 `rules` **字段**下,是文本纪律;维度4 管的是机制层护栏品类且要求是「混用勿单押一种」,从未要求每卡必挂。
- 「逐卡辩护」替代方案被反驳者一击命中要害:mode collapse 是**无意识**失败,自评辩护对 LLM 是免费的且不可检测;直方图的全部价值恰在**不可编造**。

**我采信反驳方**,理由是三个视角的取证错误方向完全一致(全部指向「规则会误伤真卡」),而反驳方的核心论据是可从原文直接核对的措辞(「自检」「信号」「单批」),不是语料统计。

**可执行动作(三处原地改)**:
1. 句尾改为:`同一解决方案在一批内重复 3 次以上 = 局部最优信号,须复核该组的构筑位 / 条件窗口 / 强度带是否真的分开;确认无法区分再换轴。`
2. 补一句消歧:`「同一解决方案」= 同条件轴 + 同 payload 形态;不同触发轴上解决不同问题的同类 payload 不算重复。`
3. 「命名长度」这一项与天赋册 §6 L91 [已核,近乎逐字重复] 去重 —— 通则侧改为交叉引用天赋册 §6,**但动手前须先核 `skill/equipment/relic` 三份分册是否已有反同质化条目**;若无,通则 §12 是唯一覆盖非天赋实体的载体,不得删。[UNVERIFIED — 我未读三份分册]

## 二、上位原则收编

18 份评估共提出 17 条上位原则候选。去重后剩 4 条可采纳、5 条须剔除。

### 采纳(4 条)

**原则 1 —— 按结算实态定价,不按文本形状定价**
> 强度必须按效果**实际兑现**什么来估:条件的真实 uptime(不是它写没写条件)、payload 落在哪个乘区且是否被 clamp 吃掉(不是它写了多大的数)、可重复触发的期望次数(不是单次数值)。文本形态的差异(暴击加算通道 vs 最终乘区通道、条件件 vs 无条件件、固定值 vs 百分比)是合法设计空间,**保留差异、在定标环节区别对待**。

- 合并自:always-true 三个视角各自的 D/E/F 候选(措辞不同、内核同一)
- **落点 = 通则 §3(数值构成模式)的一句导语,不是 §12**。§12 标题是「机制约定与反例」[已核 L95],是案例袋;把定价原则塞进案例袋会架出一个只能统摄 6 条里 2 条的假层级。
- **吃掉**:§12 永真条件检查(降为它在「条件」粒度的实例)、§12 避开已饱和维度(降为「payload」粒度的实例)、并**直接给出暴击双通道那次裁决的答案**(两通道都保留,最终乘区因难以积累定价高于暴击乘区,分别给数值)
- **不吃**:§12 机制绑定池纪律(那是归属判定不是定价)、§12 禁防御性条款堆叠(那是可读性约束)

**原则 2 —— 决策区分度(作为反同质化六分布之上的判据)**
> 每张卡必须能回答「玩家在什么局面下会选它,而不选同池的另一张」。判据轴 = 构筑位 / 条件窗口 / 强度带。形态相同不是缺陷,**决策等价**才是;形态各异但玩家「随便选哪张都差不多」的一批,即使六个分布全绿也是失败批次。

- 合并自:anti-homog lens1 的「决策区分度」+ lens3 的部分内核 + common-tier lens3 的「决策位纪律」
- **与六分布并列,不替代**。分布检查负责**发现嫌疑**(可机械复算、不可编造),决策区分度负责**裁决去留**(不可机械化)。这是本次最重要的结构结论:两者并存不是二选一。
- 可交叉引用天赋册 §9 L114「稀有度拉开的是适用面与构筑绑定深度」[已核] 与 §2 池边界。

**原则 3 —— 读者面决定措辞,内部词跨到用户可见面须过登记门**
> 三个面各有措辞规范:**玩家面**(effect / 卡名 / UI)、**用户可见的设计面**(notes / rules —— 用户在设计库面板审阅)、**机器面**(trigger / `engine_json` / R1.8 归层措辞)。未在 `/api/terms` 注册的词不得成为前两个面的理解前提;`03-AI-Context/` 内部分析文档不受此限,首次出现给一次定义即可。

- 合并自:duan-dai 三个视角的 O/P/Q 候选
- **关键修正**:三个视角都把 `notes` 划为「设计者面因而自由」,但 L68 [已核] 明文把 `notes` 写进禁用范围,且在 SoT 里设计者就是**用户本人**。所以是三面不是两面,`notes` 属用户可见面。
- **吃掉**:通则 §5 L47(升格并写实)、天赋册 §4 L68 的判据部分(L68 降为「该原则下一条具体词的注册状态记录」,保留其钦定展开串)、天赋册 §10 L138 trigger/effect 分工的**理由**
- 收益:堵掉「改叫气段 / 高气区就合规」的同义词规避路径 —— 按状态(未注册)封杀,不按字符串封杀。

**原则 4 —— 真源变更未结清下游引用 = 变更未完成**
> 责任人是**改基座的那次作业**,不是下一个设计新卡的人。

### 同质:**成立,但「同源」不等于「错误」**

六条被评估规则中有 5 条可追溯到 2026-07-19~20 三天内的用户批评;两份文档共 9 处带日期的用户归因,集中在同一个窗口。这是 reactive accretion(反射式增生)的真实指纹。

**但本次最重要的发现恰恰是反证**:18 份评估全部以「这条来源于一次批评」作为主要证伪线索,而 18 份评估全部被反驳者推翻。**「规则的出身」不能作为独立的证伪依据** —— 用户纠正 → agent 记录,是这个项目**期望**的反馈回路;通则 §12 永真条件检查与天赋册 §6 文化质量门槛出身完全相同,但三个视角对前者判「过拟合」、对后者的内核照单全收,批判被选择性使用了。

### 检查项 vs 设计原则比例:**失衡,但没有 9:1 那么夸张**

按「能否被机械核对通过 / 需不需要判断」严格分类,我数出真正把判断压成布尔的条目**只有 5 条**:

| 条目 | 位置 | 性质 |
|---|---|---|
| 同轴数值步进 ×1.3~1.5 不超 ×1.5 | 天赋册 §9 L126 | 可核对的倍率带 |
| 同一解决方案重复 3 次以上必须换轴 | 通则 §12 L100 | 计数阈值 + 固定补救动作 |
| TTK = 1-2 击,单卡不得独立跨断点 | 天赋册 §9 L129 | 快照常数 + 绝对禁令 |
| 命名长度二 / 三 / 四字混合 | 天赋册 §6 L91 | 直方图 |

对照真正承载判断的原则约 8-10 条(五层层定位、数值形态由定位决定、稀有度主轴 = 机制复杂度、池边界反事实判据、真源优先级、裁决权边界、避开饱和维度、永真条件)。**比例约 1:2 偏向原则,而非材料方声称的 9:1 偏向检查项。**

**关键限定**:在这套体系里,可机械核对**不是缺陷** —— 全仓无任何 linter 执行这些条目(执行者是同一个有判断力的 agent),且通则 §10 L85「审阅是提醒器不是闸门」+ §11 裁决权归用户,整套体系里没有任何机械闸门。所以「把判断力降级成机械合规检查」这个病灶在 SoT 当前形态下是**假想危害而非观测到的危害**。校准锚点的真实教训应当落在「不要用禁令消灭有意义的差异」上(原则 1 已吸收),而不是落在「检查项太多」上。

## 六、方法论反省

**结论:本次重估的前 18 份评估存在系统性的框架诱导偏差,证据是统计级的,不是印象。**

### 证据一:verdict 分布本身就是偏置指纹

18 份视角评估的 verdict:**partially-valid 17 份 + local-patch 1 份 = 18/18 判「有问题」,零份判 valid / universal-discipline**。六条规则、三个独立视角、无一例外。一个健康的评估流程不会在 18 次独立判断里一次都不给出「这条没问题」。

对应地,18 份对抗验证的 `refuted` 字段:**18/18 为 true**。全部被推翻。

### 证据二:多个反驳者独立、具名地点出了这一点

- anti-homog / first-principles 的反驳者:「评估写道『我的处置是**净减少条目**』,并把『净减少』本身当成正确性的证据。这是对『防过拟合』任务框架的过拟合:先选定了处置**形状**,再去找证据,而找来的最强一条经实测是反的。」
- anti-homog / superordinate 的反驳者:「三处**都朝同一个方向偏**。这是『防过拟合』框架推着往『这是 local patch,应当溶解』的方向走。」
- always-true / first-principles 的反驳者:「评估没有倒向 local-patch,它倒向了另一边:为了产出一条『上位原则』,把一条本来已经写对的定价条款重新描述成一个需要被重写的合规检查。这同样是过拟合到任务框架 —— 只不过过拟合的方向是『必须找到可提升的抽象层』。」
- common-tier / first-principles 的反驳者:「结论对同一份文档里三条**同构**的层分配条款只字未评,单独挑出带『不做』字样的这一条判为过拟合修补。触发它的是**措辞形状**(听起来像禁令),不是规则类型。」

### 证据三:取证错误全部朝同一方向(这是最硬的一条)

如果偏差是随机噪声,错误方向应当双向分布。实际上我核到的四类独立取证错误**方向完全一致**,全部指向「规则会误伤 / 规则已失效」:

1. **计量单位错配**:用全库 21 张累计语料去量一条写死「单批产出」的 per-batch 规则(anti-homog,三视角中有两个犯)
2. **采样窗口滤掉反证**:只扫「在用」卡得「段带 0 次」就断言「问题从未发生」,而违规恰恰在已剔除的两张卡的 `notes` 里 —— 把 remediation 之后的语料当 baseline 读(duan-dai)[UNVERIFIED 语料,但逻辑成立]
3. **截断引用**:三个独立视角**同时**丢掉 §6① 的「或成体系的武学·禅武·兵法语汇」并列支 [已核 L92],而这一支恰好是它们全部反驳的靶心。三个独立视角同向截断同一处,概率上不能用粗心解释
4. **漏读限定词**:三个视角同时把「**纯**裸属性平加」读成「裸属性平加」,从而虚构出与 §1 的冲突 —— 而规则自己那格里的通过范例(起手式「速度 +4,持续 2 回合」)用的就是固定值 payload [已核 L118]

**零处错误朝相反方向**(即「规则其实比我以为的更该保留 / 更该收紧」)。这个不对称就是偏置本身。

### 我自己这一轮的偏差风险(诚实标注)

我给六条的裁定是 **5 保留 + 1 轻度重写,零删除**。这本身可能是对「反驳者全胜」的过拟合 —— 逆反矫正与原偏差是同一种病,只是方向相反。

我采取的三条控制措施:

1. **只用可核对的原文文本作裁定依据**。我逐行读了两份文件,亲自确认了 §6① 的完整措辞、§9 普通档的「纯」字、通则 §2 L26 的架构层出处、§12 的「自检 / 信号」措辞、§11 L89 的「建议区间」在 agent 职权内、§9 L126 的「仅在数值可比时适用」。**我不是因为反驳站在后一轮才采信它**,而是因为反驳的核心论据是引文、被反驳方的核心论据是我无法核实的语料统计。这个证据类型的不对称是我采信反驳的主要原因,应当明说。

2. **凡不可核实的一律标 UNVERIFIED 且不作裁定依据**。生产库语料统计、`seed.json` 已删卡内容、三份分册有无反同质化条目 —— 这些我都没有独立验证,报告里全部标出,并在第四部分第 14 项明确把「动手前须先核三份分册」列为前置条件。

3. **对反驳方也做了反向检验,并推翻了它一处**。base-change lens3 的反驳者主张「五合一有损」,我采信;但 duan-dai lens3 的反驳者主张「`notes` 属设计者面因而自由」在其他地方被反证 —— L68 [已核] 明文把 `notes` 写进禁用范围,而在 SoT 里设计者就是用户本人。我在原则 3 里显式修正了这一点,没有照单全收。

### 本次最值得沉淀的方法论教训

**「规则的出身」不是证伪依据。** 18 份评估里,「这条是当轮被批评后加的」被反复当作主要论据。但同一份文档里,通则 §12 永真条件检查、天赋册 §6 文化质量门槛出身完全相同(都是「2026-07-20 用户抓出 / 纠正」),而多份评估对前者判「过拟合」、对后者的内核照单全收。批判被选择性使用了。

用户纠正 → agent 记录,是这个项目**期望**的反馈回路。真正需要警惕的不是「每次批评加一条」,而是**从不做合并与退役审视**。这也正好解释了为什么第二部分我只采纳 4 条上位原则、剔除 5 条:上位原则的价值在于**统辖**已有条文并消除漂移路径,不在于**替换**它们 —— 替换会丢掉每条各自携带的查表指令(先查 `stat_tiers`、先读 tag definition、先扫同池条目),而那些指令才是这套规则集真正的可执行内核。
