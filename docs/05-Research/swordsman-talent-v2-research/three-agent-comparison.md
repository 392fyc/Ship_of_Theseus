## 2. 共享区（Lv 1-10）对比

### 共同点
- 三版本共享区结构高度一致：sw_start → 三分路(L2/M2/R2) → 收束(hub5) → 三分(L6/M6/R6) → 收束(hub8) → 分流(pre_saint9/pre_magic9) → 转职
- 节点内容基本相同：锐刃、敏锐、洞察、连环、剑舞、虚实 → 剑心通明 → 斩铁、剑道精义、魔力感知 → 临界之刃、元素抵抗 → 剑之极

### 差异点

| 差异 | Codex | AntiGravity | opencode |
|------|-------|-------------|---------|
| 起始节点后 | 直接三分路 | 加 sw_hub1(学徒试炼,全属性+1) | 加 sw_hub9(分道明心) |
| 剑舞 action_cost | move | move | swift |
| 魔力感知 | 含"揭示攻击者抗性" | 含"揭示攻击者抗性" | 简化为仅 M.DEF+3 |
| 转职节点命名 | sw_adv_sword_immortal | sw_adv_sword_immortal | sw_adv_cultivator |
| 坐标系 | y=3080→200(降序) | y=0→2060(升序) | y=0→2060(升序) |

### 评价
- **Codex** 最精简，无额外hub节点
- **AntiGravity** 加 sw_hub1 使 Lv1→Lv2 多了一步，共享区 Dijkstra 最短路径可能偏移
- **opencode** 加 sw_hub9 在 hub8 之后，使转职锚点从 Lv10 推迟到 Lv11（需验证）
- **opencode 的剑舞定为 swift** 更合理——攻击后追加移动1格应是迅捷动作而非移动动作

## 3. 剑圣路径（Lv 11-20）对比

### 共同点
- A线: 二刀流 → 迅捷步伐 → 流转不息 → 神速追击 → 幻影连斩 → ... → 极意·幻影剑舞
- B线: 致命打击 → 居合蓄势 → 剑气极意 → 剑气释放 → 居合之心 → ... → 极意·修罗一闪
- M线(共通): 闪刃反击(reaction) → 饮血剑

### 差异点

| 差异 | Codex | AntiGravity | opencode |
|------|-------|-------------|---------|
| ss_B12 | 居合蓄势(不移动+20剑气) | 居合蓄势(相同) | 剑意共鸣(暴击+10剑气) |
| ss_M12 | 闪刃反击(招架减伤30%+10剑气) | 闪刃反击(相同) | 见切返(格挡+80%反击+20剑气) |
| A线整体 | 双刀追击流 | 双刀追击流 | 双刀追击流 |
| B线整体 | 居合修罗流 | 居合修罗流 | 居合修罗流(改版) |

### 评价
- **opencode 的 ss_B12(剑意共鸣)** 解决了原始 prompt 中 Issue 2（暴击率上限溢出问题），改为"暴击命中+10剑气"，设计更优
- **opencode 的 ss_M12(见切返)** 更具特色——格挡+反击+高剑气收益，比 Codex/AG 的"减伤30%+10剑气"更有深度
- 三版本的 A 线高度一致，缺乏差异化

## 4. 剑仙路径（Lv 11-20）对比

### 结构差异

| 差异 | Codex | AntiGravity | opencode |
|------|-------|-------------|---------|
| sc_A11 | 飞剑缠绕(减速目标伤害+15%) | 飞剑缠绕(相同) | 本命飞剑·觉醒(解锁飞剑Hybrid普攻) |
| sc_B11 | 御剑术基石(射程+1) | 御剑术基石(相同) | 剑阵·初式(解锁剑阵部署) |
| sc_A12 | 无极化剑(魔攻后追加物斩) | 无极化剑(相同) | 御剑术(飞剑命中恢复3%剑元) |
| sc_B12 | 剑阵·陷(标准行动) | 剑阵·陷(相同) | 陷·深渊(被动:进入阵移动-2) |
| sc_A15_qual | 天外飞仙(移动力+1+无视高低差) | 天外飞仙(相同) | 万法归一(飞剑取较低防计算) |
| sc_B15_qual | 剑阵·戮(引爆剑阵真伤) | 剑阵·戮(相同) | 绝·不侵(阵内免控+15%减伤) |
| sc_A20 | 秘仪·虚空斩(全屏单体狙杀) | 秘仪·虚空斩(相同) | 极意·虚空剑阵(Hybrid无视地形+射程+1) |
| sc_B20 | 秘仪·诛仙四剑(跟随剑阵) | 秘仪·诛仙四剑(相同) | 极意·人阵合一(剑阵随移动+减伤50%) |

### 评价

**Codex/AntiGravity 剑仙路径高度相同**，内容几乎一字不差。

**opencode 剑仙路径差异化最大**，核心优势：
1. **sc_A11 解锁飞剑普攻** — 更符合 deep-dive-rules 的剑仙lore（转职后获得本命飞剑）
2. **sc_B11 解锁剑阵** — 将剑阵部署独立为trait而非active_skill，更合理
3. **sc_B12 被动减速** — 将"陷"效果改为被动触发而非主动技能，减少行动经济压力
4. **sc_B15_qual 绝·不侵** — 直接映射 deep-dive-rules 的"绝"意象（免控）
5. **sc_A20/B20 改为 trait** — 终端节点改为永久被动增强而非主动技能，与 Codex/AG 的 active_skill 不同

**潜在问题**：
- opencode 的 sc_A20 和 sc_B20 是 trait 而非 active_skill，可能导致终端缺乏"高光时刻"
- Codex/AG 的终端是全屏狙杀和跟随剑阵，更有史诗感

## 5. 银蔷薇桥接对比

| 节点 | Codex | AntiGravity | opencode |
|------|-------|-------------|---------|
| cm_M11 | 蔷薇起手式(移动力+1,无视ZOC) | 蔷薇起手式(相同) | 蔷薇入门(闪避→优雅标记→命中+15%) |
| cm_M13 | 弱点洞悉(命中+15%,暴击+10%) | 弱点洞悉(相同) | 弱点洞悉(命中标记弱点→暴击+5%×2回合) |
| cm_M16 | 荆棘华尔兹(闪避→100%反击) | 荆棘华尔兹(相同) | 荆棘华尔兹(无视ZOC) |
| cm_M20 | 蔷薇终幕(击杀→刷新CD) | 蔷薇终幕(相同) | 蔷薇终章(25%完全回避) |

### 评价
- **Codex/AG**: cm_M11 给移动力+1+无视ZOC，非常强力，可能过于泛用（Bridge Tax 不够）

- **opencode 的 cm_M20**: 从 cm_M16 直接连接，形成独立的银蔷薇深入链路，设计更清晰
- **Codex/AG 的 cm_M20**: 依赖 ss_B19|sc_A19，意味着必须深入一侧路径才能解锁

## 6. 深潜区（Lv 21-25）对比

三版本深潜区 **完全相同**：
- ss_A21(气盛无匹) / ss_B21(不屈战魄)
- sc_A21(虚空行者) / sc_B21(剑元护体)
- 3个 detour 节点（血气唤醒、聚元法阵、破极之躯）
- 斜向跨系边: ss_B21→sc_A23, sc_A21→ss_B23
- 4个 Lv 24 强化节点 + 4个 Lv 25 终极节点

### 评价
- 深潜区设计稳定，三版本无分歧
- 符合 deep-dive-rules 的拓扑规则（斜向单向边、detour无出边、内外侧布局）

## 7. 普攻权重评估

| 维度 | Codex | AntiGravity | opencode |
|------|-------|-------------|---------|
| 普攻相关节点数 | ~5 | ~5 | ~7 |
| 追击增强节点 | ss_A14, ss_A15_qual | 相同 | 相同 |
| On-Hit 被动 | sw_L2(锐刃), sw_R3(虚实) | 相同 | 相同+cm_M11(优雅标记) |
| 量谱充能(普攻) | 无直接普攻→剑气节点 | 相同 | ss_B12(暴击→剑气) |
| 反击增强 | ss_M12(reaction减伤) | 相同 | ss_M12(格挡+反击) |
| 剑仙飞剑普攻 | 隐含在转职效果中 | 相同 | sc_A11 明确解锁 |

### 评价
**三版本普攻权重均不足**——这是 v2 的核心改进方向：
1. 缺乏"普攻→量谱充能"的显式节点链
2. 缺乏 on-hit 被动叠加机制
3. 追击相关节点集中在 A 线，B 线普攻价值低
4. 剑仙路径几乎无普攻增强节点

### 基线选择：Codex CLI (sw_codex.json)

虽然 opencode 综合分更高，选择 Codex 作为基线的理由：
1. **结构最规范**: 无多余hub节点，共享区最精简
2. **坐标系清晰**: 五线谱 x 坐标分布合理
3. **Codex/AG 高度一致**: 说明设计共识已形成，可作为稳定基础
4. **opencode 的创新点将被吸收**: ss_B12 重设计、剑仙 A11/B11 身份、银蔷薇差异化等优秀想法将在 v2 中采纳

v2 设计将以 Codex 结构为骨架，融合 opencode 的创新节点设计。
