# 技能设计要点(Skill Design Principles)

> **读者 = 设计 SoT 技能的 agent**。跨实体通用纪律见 [[content-design-general|内容设计通则]];本文只写技能实体专属要点。放 `03-AI-Context/`,不进设计书面板、不同步 NAS。
>
> 相关人类文档(权威真源):[[01-Game-Design/skills-and-range|技能与射程]] · [[01-Game-Design/Core-Systems/turn-system|回合系统]] · [[01-Game-Design/rules-catalog|规则总目录]]

## 1. 字段面(设计层)

- 设计库 Skill：`id` / `class_id` / `name` / `damage_type`（设计层枚举）/ `resource_type` / `skill_type` / `is_projectile` / `cd` / `target_mode` / 射程三列（`range_min` / `range_max` / `range_shape`）/ 作用范围两列（`area_shape` / `area_size`）/ `displacement` / `upgrade_of` / `effect` / `rules` / `notes` / `tags`。
- **技能没有 trigger 字段。** 时机由 `resource_type` 与引擎侧的 `timing_constraint` 表达（见 §3），不走天赋那套五段。
- `cd` 与射程属于设计库的独立结构化字段。效果中不重复写冷却或射程，卡面由对应字段展示。
- 技能的伤害参数（威力、系数、命中方式与命中加成、暴击方式与倍率、基数属性、段数等）记在伤害条目 `damage_entries` 里，条目是这些参数的唯一权威；`effect` 写效果本身，不再重复这些数字（2026-10-24 起，见设计库 `docs/entity-contract-skill-talent-memory.md` §3。其中威力、系数、命中是用户裁决，其余字段是主代理判断）。同一技能的多条伤害条目是互斥备选，由 `applies_when` 区分；多段用 `segments` 表达。
- 设计库不存引擎数值副本。伤害条目之外的效果（状态、资源、位移等）如何落实为 Godot 运行数据，等该技能进入 Ship 实装时逐项分析，不从效果文案批量反推。
- **`rules` 字段技能也有**（2026-07-29 补齐）：effect 写效果本身，rules 写结算细节与规则引用，notes 写设计意图。
- 技能**没有** `rarity` / `status` / `shelf_state` 字段（与天赋不同）：无稀有度分层，也不走草稿、上架状态与软删那套生命周期。
- **`is_projectile`** = 是不是弹道类（2026-07-21 用户定义）：是 = 发射一个实体，飞行途中可能被技能、特效或地形阻挡；否 = 点对点直接作用，不被阻挡。与 `damage_type` / `skill_type` / `resource_type` 三个分类维度正交。默认为否；要可拦必须显式声明。
- **`target_mode`** = 目标选择方式（单位 / 格子 / 方向 / 自身，2026-08-06 用户裁决去掉“选”前缀），取值以设计库 `TargetMode` 枚举为准。它不能由作用范围形状可靠反推，因此必须独立记录。天赋没有这个字段。
- **技能与天赋的字段面差异**：天赋有 trigger 五段与旧自由文本 `trigger`，技能一个都没有；技能另有 `target_mode`、冷却、射程三列、作用范围两列、`displacement` 与 `upgrade_of`，天赋都没有。设计天赋时不要照技能的字段面推，反之亦然。

## 2. 双维度分类(每技能必填,正交)

- **`skill_type`** = 技能*做什么*:攻击 / 位移 / 增益 / 辅助(含治疗)/ 控制。
- **`resource_type`** = 技能*耗哪种每回合行动资源*:标准 / 迅捷 / 移动 / 反应 / 无(「无」留给完全被动、无主动触发成本的技能,如心眼)。
- 两者与引擎 `action_cost` 是双轨独立字段(通则 §9),应描述同一现实资源但独立维护。
- 自身指向的姿态类归「增益」+ 射程 self,不为「目标恒为自身」单设分类。

## 3. 行动资源与时机(R3.2 / R3.3)

- 游戏没有普通攻击，技能是战斗出手的核心。无冷却的基础攻击技能承担持续出手的职责，但它仍然是完整技能，不能按“普通攻击”降格处理。
- 每个单位通常在自身回合开始时获得一次移动机会，并把标准行动点与迅捷行动点恢复到各自容量；两类行动点默认容量均为1，允许范围均为1至3（R3.2）。标准动作每次消耗1点标准行动点并使剩余移动失效；迅捷动作每次消耗1点迅捷行动点，不消耗移动或标准行动点；反应被动触发，不消耗主动行动点。
- 默认容量下，一个单位回合通常至多使用1个移动动作、1个标准动作和1个迅捷动作；容量被明确提高后，可以继续支付同类行动点。技能设计仍须说明它占用哪个资源，以及同槽技能在默认容量与扩容后的取舍，不能把“默认1点”写成不可突破的每回合次数上限。
- `action_cost` ∈ free / move / standard / swift / reaction；施放时机 `timing` ∈ any / before_move / after_move / before_attack / after_attack（R3.3）。

## 4. 射程与范围

- 攻击方式由技能声明:melee = 射程 1 / ranged = 射程 >1 / area = AOE(R4.3);攻击线不受地形阻挡。
- **射程与作用范围是两件事,各自有结构化字段,别混**:
  - **射程**回答「哪些格可以被选为目标」,以**施法者**为原点,三列 `range_min` / `range_max` / `range_shape`(`RangeShape` = 菱形 / 直线 / 方形 / 十字;射程 0 的自身技能留空)。
  - **作用范围**回答「选定之后作用到哪些格」,以**目标格**为原点,两列 `area_shape` / `area_size`(`AreaShape` = 单体 / 菱形 / 直线 / 方形 / 十字;单体 ⟺ 大小 0)。
  - 例:拔刀是「选 1 个单位、作用 5 格」;一闪是「沿一个方向选目标、最远 4 格,受伤格按位移沿途算」(位移技能的读法见下条)。
- **枚举取值以设计库 `RangeShape` / `AreaShape` 为准**(设计层字段的权威在设计库,人类文档讲的是形态的设计意图)。实测在库 23 条只用到:射程 菱形 12 / 直线 3 / 留空 8,范围 单体 21 / 菱形 2 —— **方形与十字枚举里有、数据里 0 实例,选用前与用户确认**。
- **位移类技能的作用范围两列恒为「单体 + 0」**:这是统一的「不适用」标记,意思是这两列不按 `AreaCalculator` 的口径读(引擎 `tactical_manager.gd` 的 `_compute_skill_area_cells` 见到 `displacement` 就改走位移路径)。位移技能的范围信息在**射程**里:受伤格 = 从施法者所在格走到落点的沿途格(**不含起点、含落点**,引擎 `_get_displacement_path_cells`),最长由 `range_max` 封顶——一闪 `range_max` 4,最远打 4 格。设计库的作用范围预览图也是照这个口径画的:以施法者为原点,画到射程上限。
- **位移与「选方向」是两件事**:瞬身同样勾了 `displacement`,但它 `target_mode` = 单位、射程 菱形 1–5;一闪与连闪才是 `target_mode` = 方向。位移技能怎么选目标,由 `target_mode` 单独决定。
- **射程归技能 / 天赋 / 遗物管,武器不管理射程**(R1.7)。

## 5. 数值落层

- 设计侧在 `effect` 中用完整、自然的中文写出效果、概率与复杂伤害关系；伤害参数在伤害条目里（见 §1），不在 `effect` 里重复。
- Godot 运行字段如何从伤害条目落实，属于 Ship 实装阶段的决定。
- `cd` 与射程已经是设计库结构化字段，效果中不再重复这两项；伤害参数同理由伤害条目承载。
- 附加效果时机分为命中时与造成伤害后（R1.4）：前者只要求攻击命中，后者要求本次伤害已经造成。
- 减益施加率 = skill.chance × max(0.1, 1 − target.LCK/100)（R1.5）。
- 具体数值由用户定稿；Agent 可以提出骨架、区间与风险，但不得替用户作最终数值裁决。

## 6. 职业资源联动

- 技能是职业特色资源获取 / 消耗的定义载体(R1.6):资源的获取、消耗与换算由技能 / 天赋 / 遗物条目定义。剑气的获得、消耗与阈值一律取 5 的倍数(用户 2026-10-24,见 [[talent-design-principles|天赋设计要点]] §4;取代早先“常规值用 10 的倍数”的写法)。
- **「奥义」tag = 身份判据,不是强度判据**:一条职业线的终极技能——整条线就这一记,不看消耗多大 / 伤害多高 / 顺不顺带斩杀或产印记(那些各归各的 tag);只标在技能上,天赋不挂。剑士与剑圣的终极技能是**居合**(用户 2026-07-20 裁决,取代此前「高消耗、强效果」判据——该判据在拔刀这类反例上失效:消耗整个印记池 + 20 剑气、暴击倍率 ×1.2(独立乘区,与基础 ×1.5 相乘 = ×1.8)、带溅射,字面全占却不该挂奥义)。被攻击 / 被触发的反应类挂「反应」tag。
- 「资源」tag 挂载判据见通则 §5(产出 / 改规矩 / 依托数量判定三种关系,技能自身的常规消耗不算)。技能侧示例:居合消耗的剑气是这一招的成本,不挂;斩击能让玩家拿到剑气,才挂。

**剑士线资源节奏的用户裁决**(2026-10-09 至 10-21;记录见设计库提案 `docs/proposals/2026-09-talent-system/claude/` 下 `25-myrmidon-kit-skeleton.md`、`26-kensei-marks-layer.md`、`27-memory-structural-review.md`、`29-damage-model-additive.md` 与 `auto/user-model.md`,2026-10-28 迁入本文。多为转述记录,不是逐字原话;“归纳”是 Claude 推出的做法)

- 基础配置下剑气花费大于收入(2026-10-12)。“花费大于收入”约束的是基础配置;投入后在有利场景里主导、基础技能用得少,是投入的回报(用户 2026-10-13)。
- 挨打扣剑气的惩罚过大(用户 2026-10-09)。由此的设计(Claude,25 号):近战受击时剑气不变,〔招架〕的防御随持有剑气提高。
- 标准动作技能以剑气与印记为使用条件,迅捷、移动技能以冷却为使用条件(2026-10-13)。冷却一般给功能性技能,〔太阴剑〕冷却 0 算特例(用户 2026-10-14)。由此的做法(归纳):节点奖励节奏时,作用在迅捷或移动技能的冷却上,或提供再移动。
- 技能威力与系数的分工(2026-10-18):威力高于〔斩击〕时,相对〔斩击〕的伤害倍数随等级下降,对重甲更强;系数调节技能巅峰期的强度,在减去防御之后相乘。
- 额外标准行动做成每关卡限定次数(用户 2026-10-13)。例外:〔阴阳剑〕阴阳圆满的额外回合保留现行写法,不加每关卡上限(用户 2026-10-14)。“每关卡限定次数”这类计数的定义尚未写入规则表(27 号的待办)。
- 多行动资源下的整体强化各职业都有,评估时看多资源下各方案的相对差异,不追究理论强度上升(用户 2026-10-21)。
- 技能交互顺着回合规则:回合默认先移动再攻击,移动机会只有一次(2026-10-18)。

具体技能的数值(例如〔居合〕〔拔刀〕的倍率与消耗)以设计库记录为准,不在本文复写。

## 7. 转职前后的纯净度(剑士 / 剑圣分层)

- **下位职业(剑士 myrmidon)的技能 = 转职前的纯净效果,不得写入任何印记内容**;印记是上位职业(剑圣 kensei)专属机制,依据 R2.4「下位职业的技能与天赋默认同时属于其上位职业;上位职业专属的仅属该上位」——印记属剑圣专属,不下沉进剑士技能。
- 转职后追加的印记特效,做成剑圣技能组下的**独立条目**,不改写同名的剑士版本。
- **同名不同 `class_id` 是允许的**:剑士与剑圣可以各自拥有一张同名技能(如斩击 / 一闪 / 招架 / 居合 / 心眼),剑士版是纯净基础效果;二者靠 `class_id` 区分,不视为撞名(用户 2026-07-20 裁决,依据 R2.4)。
- **转职时同名技能可以增加效果,也可以替换原有效果,两者都是常规做法**(用户 2026-10-28:「不算例外，这应该会很常见」)。例:剑圣〔斩击〕〔居合〕〔心眼〕保留剑士版原效果并增加印记效果;剑圣〔招架〕把剑士版的防御、魔防加成替换为按技巧加闪避(用户 2026-10-12 裁决,方向甲,记录见设计库 `docs/proposals/2026-09-talent-system/claude/26-kensei-marks-layer.md`「转职迁移规则」);剑圣〔一闪〕与剑士版相同。替换原有效果不违反本节的纯净度,纯净度只约束剑士版不得含印记内容。
- **技能以“职业 + 技能”组合定位**(用户 2026-10-28:「技能要和职业做一个组合来确定准确坐标」):同名技能在不同职业下可以是不同的结算,所以设计、天赋点名、手算和实装说到某个技能时,都要能确定是哪个职业的版本;设计库以 `class_id` 和技能 id 区分(如 `myrmidon_zhanji` 与 `kensei_zhanji`)。剑圣有自己的同名条目时,剑圣使用剑圣版,不与按 R2.4 继承来的剑士版并存;剑圣天赋点名〔斩击〕指剑圣〔斩击〕(两条均为推断)。
- 未定:剑士天赋按 R2.4 随转职归属剑圣后,其点名的剑士技能是否作用于剑圣同名版本。2026-10-28 设计库的剑士天赋(含各状态)都没有在效果或规则中点名基础技能,暂无实例;出现实例时须先定。

## 8. 冷却、升级与同槽形态

- 冷却按使用者的自身回合计数。`cd=0` 表示技能本身不限制再次使用；`cd=N` 表示在第 N 个后续自身回合重新可用。冷却结束只恢复技能可用性，不额外提供行动点或资源（R3.5）。
- 回忆升级永久替换基础技能。升级技能必须独立给出完整字段；明确作用于基础技能的效果默认也作用于升级版本，除非效果明确排除某个升级。兼容效果只能修改升级形态实际存在的内容，不能为没有攻击、伤害、范围或位移的形态凭空补出这些内容（R2.5）。
- 临时替换和按条件占用同一槽位，不等于永久升级。条件形态只有在条件成立且自身已经结束冷却时才替换原技能；仍在冷却时保留原技能，恢复可用后若条件仍成立再立即替换。多个形态分别记录并持续计算各自冷却（R3.6）。
- 动态显示名可以属于同一个技能身份，多形态则可以拥有不同的动作、目标、射程和冷却。当前数据模型不能完整表达一张回忆天赋对应多个条件形态时，应在版本化设计检查点中保存真实关系，不得把不同形态压成一套虚假的统一字段。
