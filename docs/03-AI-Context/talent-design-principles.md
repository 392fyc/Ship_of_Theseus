## 1. 数值构成模式由天赋定位决定

判据本体(三选由定位决定、概率类须设递减或上限)见 [[content-design-general|通则]] §3;本节写三种模式在天赋侧的特性、可缩放触点与案例。别默认某一种更高级——固定值不是「低级」、属性挂钩不是「高级」,是各自的适用区间。

**① 纯固定数值(加算固定值,如「暴击 +10」)**
- 特性:前期效果好(相对当时属性占比高),**后期数值不够看**(被成长稀释)。
- 定位:前期 / 过渡件、低稀有度节奏件(层归属判据见 [[content-design-general|通则]] §2)。

**② 百分比数值(乘区 / 提升类,如「伤害 提升 N%」)**
- 特性:效果取决于**所在乘区**(R1.8 各量为独立乘区);一般追求**分散乘区投资**达到最大收益——多个独立乘区各投一点,因相乘而优于单乘区堆叠。
- 定位:中后期、乘区互补构筑。

**③ 属性挂钩 / 成长型(如「暴击 + DEX/2」「DEX% 概率」)**
- 特性:前期**明显偏弱**(属性低),随属性成长走强;**强度估算的重心在后期**——前期弱是设计代价,定标时须在后期给足补偿并确认不失控。
- 定位:成长型件、绑职业签名属性(如剑圣 DEX)、构筑深度(堆签名属性 = 强化该卡)、跨等级自平衡。
- 平衡注意:绑签名属性的概率类是通则 §3「须设递减或上限」最容易踩的形态——剑圣 DEX 走高后,可反复触发的效果期望次数会被推到失控区间。

**天赋侧的选择次序**:先定这张卡的定位(前期过渡 / 中后期乘区构筑 / 成长型 / 职业身份绑定),再选模式。

**伤害增益先选层**(2026-10-28 用户裁决:「天赋应该区分+威力，+系数，伤害提升，伤害总增等。」)

规则表 R1.1 把一次伤害拆成几层,同一个数字放进不同的层,结果完全不同。写一张增伤卡,先说清它落在哪一层,再定数值:

| 层 | R1.1 中的位置 | 写法示例 | 特性 |
|---|---|---|---|
| 技能威力 | 括号内,与力量或魔力相加,再减防御 | 〔居合〕威力 +5 | 低攻高防时最显著;受防御影响 |
| 技能系数 | 括号外的乘数 | 〔斩击〕系数 +0.2 | 随属性成长放大,防御高时收益被压低 |
| 普通天赋提升 | 各项提升相加,乘 (1 + 提升之和) | 〔斩击〕造成的伤害提升 10% | 同层互相稀释,是最拥挤的一层 |
| 总增与总降 | 每一项单独相乘 | 伤害总增 10% | 与其他来源相乘,不被同层稀释;定价按最强的一层对待(推断,待用户定标) |

“特性”一列由 R1.1 的公式推出,数值示例只说明写法,不是定稿值。“总增”即 [[content-design-general|通则]] §4 里写作“更多”的独立连乘层,两个说法指同一层。R1.1 目前在设计库中是“待审阅”状态(R1.8 已锁定),R1.1 改动时本表要同步。附伤是另一条结算线(R1.13、R1.14),不吃伤害提升。乘区拥挤度与定价见 [[content-design-general|通则]] §3。

**属性联动优先于小百分比**(2026-10-24 用户裁决:「重点在于，如何和属性联动，而不是单纯百分比加伤害。且，比如5%的伤害提升，你觉得在现有数值算法下能提升多少？」)
- 优先设计随属性或属性差变化的效果。小百分比增伤在 R1.8 向下取整后几乎看不见,例如 15 级〔斩击〕13 点伤害,提升 5% 仍是 13 点。
- 火纹 if 剑圣的〔流星〕、Engage 戒指的再移动是用户点名的属性联动参照;再移动类偏骑士,剑圣的移动类机制绑定速度或〔一闪〕。

**可缩放的属性触点(R2.1 战斗触点):**
| 属性 | 战斗触点 | 适合缩放的效果 |
|---|---|---|
| STR / MAG | 伤害加法层(R1.1) | 伤害 / 减益幅度 |
| DEX | 命中基数、暴击基数(R1.2/R1.3);剑圣签名 | 暴击、触发概率、连击 |
| SPD | 闪避、出手序(R1.2/R3.1) | 机动、先攻、回避 |
| LCK(固定) | 暴击回避、减益抵抗(R1.3/R1.5) | 尾部风险、抗性 |
| DEF / RES | 减伤 | 生存 |
| HP | 生命 | 血量阈值类 |

**案例(成长型 + 收敛)**:燕返「副手追加命中后以 DEX% 概率再次触发,每成功一次概率 ×0.8(如 50%→40%→32%)」——绑剑圣签名 DEX、前期弱后期强,递减自带几何收敛,是「成长型 + 职业身份 + 构筑深度 + 自平衡」的合成。

### 输出效果还要区分结算形态

固定值、百分比和属性挂钩回答的是“数值怎样成长”，不能代替“效果在哪个结算单位上生效”。设计输出类天赋时还要区分三种形态：

| 形态 | 作用单位 | 更容易放大的结构 | 默认边界 |
|---|---|---|---|
| 伤害提升 | 修改技能或攻击自身的原始伤害 | 高基础倍率、较少伤害段 | 不自动提高附伤或追加攻击 |
| 附伤 | 每个符合条件的直接伤害段各携带一次 | 多段、高频、低单段倍率 | 沿用来源命中，默认不能暴击，不新增命中、暴击或造成伤害事件 |
| 追加攻击 | 产生新的独立攻击 | 能稳定满足追加条件的攻击动作或多目标动作 | 独立命中与暴击；是否继续携带附伤或触发其他追加必须明确声明 |

评估组合时，至少分别计算：攻击动作次数、直接伤害段数、目标数、每段可携带的附伤数、每个目标可产生的追加攻击数。不能只比较最终百分比，也不能用提高多段技能自身倍率来掩盖附伤没有按段获益的问题。

附伤默认使用100%效果系数。只有测试证明某个具体技能或伤害段必须折算时，才在玩家可见内容中声明该对象的系数，不预先建立覆盖所有技能的隐藏系数表。

当前天赋数量还不足以做完整组合定标。待组合样本充分后，以〔二天一流〕代表的双刀体系和〔连斩〕代表的多段体系作为两条基线，校准其他路线的天赋与回忆天赋；在此之前只锁定结算关系，不提前压低数值。

## 2. 天赋归属:池的边界由核心机制决定

**双刀池的卡必须以「副手 / 双击 / 双目标 / 两把不同武器」为核心机制**——单刀剑圣做不出来的,才算双刀卡。

- 通用剑气经济、以及按剑气高低给收益的被动,都是**剑士线共享轴**(心眼 / 剑气属整条线,剑圣 + 剑仙都有),不属于双刀池;它们该放剑士 / 剑圣**通用层**。
- **反例(会跑偏)**:击杀产气、按剑气高低给闪避、按剑气高低给先攻——任何单刀剑圣照样成立,不是双刀卡。
- **职业继承(R2.4)**:下位职业的技能 / 天赋默认同时属上位;上位专属只属上位。设计一张卡前,先定它归哪一层。

**印记池的卡围绕印记的「获取方式 / 当前构成 / 倾泻结算」做文章**——印记(心 / 道 / 势三种,总量上限 3、战斗清零)是剑圣专属机制(R2.4,不下沉剑士);具体来源决定能否取得重复种类,消耗则由拔刀及其部分升级形态承担。印记资源本身不通用地提供属性,只有技能或天赋明确读取时才产生对应收益。在库簇:离形(改变构成规则)、万象一刀(拔刀时按消耗构成逐枚强化)、残心(拔刀后补印)、印心(获印记时产气并处理同种收益)。

- **印记池不设硬前置(用户裁决,与双刀池相反)**:双刀池以二天一流为硬前置;印记池不是。离形是改变构成并抬高上限的可选放大器,不是其他印记卡的准入条件。每张卡都必须先在没有离形时成立并完成定标。
- **持有收益由读取者定义**:现行剑圣〔心眼〕按种类读取持有印记并给出百分比属性收益;替代型心眼升级是否保留该段,以升级技能完整效果为准。设计印记池卡时先确认当前技能是否仍读取印记,不能把印记自身当成永远存在的属性来源。
- **纳刀印(离形赋予)**:持有印记中最后获得的一枚,只在效果明确读取纳刀印时按两枚计算,并随最新获得转移。纳刀印是资源特性,与状态〔纳刀〕不是同一对象。

## 3. payload 维度:避开对本职业已饱和的维度

设计前先看该职业的属性档位(class `stat_tiers`),签名属性所在的判定链往往已经很强,别在已饱和处加值。

- **剑圣命中已饱和**:DEX=S,`base_hit = weapon_hit + DEX×2` 在 DEX≈35+ 对常规敌人 clamp 100(R1.2)——「+命中」类 payload 对剑圣接近死卡。
- payload 应落**未饱和维度**:暴击、伤害、资源(剑气)、站位 / 空间、属性缩放。
- 暴击维度对剑圣存活(60 气时约 47-64%,未饱和),是可加值的主维度。

## 4. 剑气高低:一条可互动的状态轴

剑气上限固定为100点,以50点划出两个区间:高于50点与不高于50点。**卡面文本(effect / notes)与面向用户的汇报直接写清固定点数条件,不得换写成上限百分比,也不得自造简称指代两个区间。**

现行〔心眼〕不再以 50 点分界:剑士〔心眼〕(`myrmidon_xinyan`)与剑圣〔心眼〕(`kensei_xinyan`)都是每拥有 20 点剑气暴击 +1,剑气每比 100 点少 40 点速度 +1;剑圣版另按种类读取印记。具体文字以设计库记录为准。

- **50 点高低轴是独立锚点**(2026-10-28 用户裁决:保留,作为独立锚点写进剑气资源):它写在设计库剑气资源的定义里,不再依附于〔心眼〕。
- **这条高低轴是设计资源**:卡可以按剑气处在高区还是低区给不同收益,形成「攒气 vs 花气」的状态选择。
- **同锚纪律**:按这条高低轴设计的卡,默认共用固定 50 点阈值;若玩法确需其他阈值,必须把差异作为明确设计内容定标,不能由剑气上限变化间接产生。
- 心眼是剑士线基座(R2.4 继承到剑圣 / 剑仙),不是双刀专属——与剑气高低互动的卡若与双刀无关,归通用层(见 §2)。
- **剑气数值取 5 的倍数**(2026-10-24 用户裁决:「剑气获取存在大量的零散数字，这种数字在做加法时很容易造成难以计算或者溢出的问题。」卡片评论:「请取5的倍数」):剑气的获得、消耗与阈值一律取 5 的倍数。
- **剑气获取要少**(2026-10-24 用户裁决:「剑气获取变动是直接影响循环的。比如初始情况下，三次斩击后可以释放一次居合。但如果剑气获取提升到30，两个回合就可以做到。……所以剑气获取的增加可以存在，但不能烂大街」):剑气获取类卡全池只留少数几张;每张写明它把基础循环(〔斩击〕攒剑气 →〔居合〕)改成几回合,以及对〔心眼〕及其升级版本的影响。

## 5. 文风:一眼可感 + 只挂必要口径

通用文风纪律(effect / notes 写法、速查纪律、禁自造黑话)已上收 [[content-design-general|通则]] §6;本节只留天赋专属口径。

参照标的:**二天一流 / 二刀开刃 / 交刃 / 剑气回荡**。

- **rules**(结算细节与规则引用;天赋 / 技能 / 装备三个实体都有此字段、职责相同,技能那份于 2026-07-29 补齐):只挂现存规则引用(R1.x)+ 必要口径(双持门 / 每回合口径 / 独立结算);**禁**防御性条款堆叠、**禁**逐字复述规则原文。
- **直接写技能名,不造“某某位技能”**(2026-10-24 用户裁决:「自创词汇：爆发位技能，印记位技能等。实际我们声明过，你可以直接声明，是居合，拔刀XXX。而声明居合时默认包含居合的升级版本，除非特殊声明不包含XXX。」):卡面直接写〔斩击〕〔一闪〕〔招架〕〔拔刀〕〔居合〕等;默认包含该技能的升级版本(R2.5),不包含时写明“不包含〔某某〕”。“普攻位、位移位、防御位、爆发位、被动位、印记位”一类说法一律不用。
- **天赋自身造成伤害时写全参数**(2026-10-24 用户裁决:「天赋如果需要造成伤害，且该天赋并非对技能的加强天赋时，这个天赋也需要有威力和系数？虽然这对天赋来说不是通用schema，但效果说明时需要注意」):效果写全伤害类型、计算属性、威力、系数,必要时写命中与暴击规则;不为天赋另建通用伤害字段。

## 6. 命名:配合机制意象(通用命名原则见 [[content-design-general|通则]] §7)

- **剑士线借鉴池**:剑豪题材的相关游戏 / 小说 / 漫画 / 动漫等作品(典故经由作品取材,不做历史考据)。
- **批量命名反同质化**:判据本体见 [[content-design-general|通则]] §12 六分布第一项(覆盖一切实体)。天赋侧的执行口径 = 名字字数与形态要有分布(二 / 三 / 四字混合,参照剑士线已上架语料),单批全部同长必须重排(2026-07-19 用户纠正驱动:一批 15 张全二字)。
- **文化质量门槛**(2026-07-20 用户纠正:命名文化水平要提高):①名字须有**可指认的文化出处**——具体作品的招式 / 流派 / 人物 / 术语,或成体系的武学·禅武·兵法语汇,泛用词拼装不算;②**禁用游戏通用机制词做卡名**(连击 / 强化这类任何游戏都在用的词)——无文化印记,且多职业后极易与他线同类效果撞名;③效果越通用,名字越要穿本线的文化外衣;④拿不准时一卡给 2-3 个命名候选交用户选。
- **出处优先级(2026-07-21 用户裁决)**:①式的两支不是并列关系——**优先取动漫 / 小说等作品中的名称**,武学·禅武·兵法语汇是次选。**不想完全重复原作时,在原名上加一点自己的修饰**(取其核心概念另起、或改一字),而不是退回通用武学术语。用户原话:「相对于这些术语,我更偏向于使用动漫、小说中的名称,如果不想完全重复可以加一点点自己的修饰。」
  - 落地案例:**死线**(暴击时 DEX/2% 更多伤害)——意象取「看见对方的死线(弱点)并据此攻击」,灵感源自直死之魔眼一类的作品设定;不直接用原名,而取其核心概念「死之线」收成两字。它替换的旧名「会心一击」正是②禁的通用机制词。
  - 反例参照:同一张卡曾拟用「切先」(日本刀术语,刀尖 / 剑道「切先三寸」)——出处成立但属武学语汇路线,按本条优先级应让位于作品取材。
- **名字配合机制意象**:产气卡的名字要扛得住产气意象;双刀卡往「成双 / 左右 / 呼应 / 分合」意象走。
- **案例**:剑气回荡(主副呼应 + 副手命中回气,「剑气回响」)、燕返(佐佐木小次郎秘剑,副手连击 = 燕返之疾;与锚点二天一流的武藏是宿敌,呼应到位)。二天一流与燕返的典故主要取自小说 / 动漫作品。

## 8. 流程:用户构想与后续完善分工

- 默认分工见 [[content-design-general|通则]] §11：新天赋的核心构想与候选方向由用户提出；agent 在既定构想后负责事实核对、规则闭合、数值推演、结构和文字优化、反方审查、落库准备与方法论沉淀。用户也可以把一个对象与边界已经固定的批次明确交给 agent 从零提出方案；这项授权只对该批次生效，agent 必须在冻结范围内收束为推荐方案，最终去留与数值仍由用户裁决。
- 天赋侧落地：落库草稿 `status = 待审阅`；升级型分级草稿写 `levels_json`。设计库不存引擎数值副本；数值定稿只落 effect / rules 等设计字段。Ship 当前仍从自身的 Godot 数据文件读取可执行字段，任何实装都必须另行完成设计字段到运行时数据或代码的明确转换。
- 数值定稿后再对最终效果跑经济验证（逐回合产 / 耗气、到段回合数、心眼联动、组合外溢）。

### 职业强化类天赋协作蓝本

「职业强化类」是本节用于区分工作流的称呼，不新增设计库稀有度或类型枚举。它指回忆天赋以外、以职业本身为归属和强化对象的天赋。

1. **输入**：只读取目标职业当前有效的职业规则、资源规则、已上架且不是草稿的相关天赋、职业数值档位、本次用户裁决，以及用户提出的核心构想或对固定批次的明确设计授权。先写清职业核心机制、已饱和维度和禁止扩大的范围。
2. **独立分工**：事实核查者整理有效材料；方案整理者在获授权的范围内补全玩法、规则与字段；结构核查者检查字段、触发事件和注册表引用；反方审查者专门寻找永真条件、滥用组合、同质化与低收益属性；整合者只依据证据和用户裁决收敛，不把自己的草案当成先例。
3. **候选卡格式**：每张卡分别给出 `class_id`、稀有度建议、名称候选、主触发五段、必要时的独立附加触发、effect 全文、必要的 rules、notes、tags、出现条件和 `levels_json` 方案。职业强化类天赋不填写 `upgrade_skill_id`，也不另建替换技能。
4. **验证**：说明它强化了哪条职业机制、为何不属于通用层、数值占位的上下界、失败与滥用场景、与当前有效天赋的重叠程度，以及设计库和 Ship 是否已有消费路径。
5. **裁决边界**：未获授权时，核心构想与候选方向仍由用户提出；用户明确授权固定批次后，agent 可以从零提出并优化该批方案，但不能据此扩大对象、另立长期规则或把提案写成已裁决事实。新机制、新枚举、结构扩展、最终数值和会改变职业身份的效果始终由用户最终裁决。
6. **收敛与回执**：只有候选字段完整、独立反方意见已处理、结构适配性明确且开放项已交用户时才可收敛。回执记录查询范围、来源版本、排除材料、授权边界、验证结果和仍需用户裁决的事项。

## 9. 稀有度与强度标尺

**主轴 = 机制复杂度 / 构筑权重,不是裸数值。** 同功能位的卡裸强度保持同一量级;稀有度拉开的是适用面与构筑绑定深度(隐性契约:若违背,玩家会把「高稀有度不更强」当成平衡事故)。

| 档位 | 语义 |
|---|---|
| 普通 | 微机制件:极简条件或微交互 + 小数值(例:起手式 / 破竹)。纯裸属性加算不做天赋,判据见 [[content-design-general\|通则]] §2 |
| 稀有 | 单轴直给的资源 / 乘区件,或单一简单条件;强化现有轴、不改打法(例:剑意澎湃) |
| 史诗 | 机制交互件:条件触发 / 替代 / 解锁 / 连锁 / 反应,两个机制轴联动,开始构筑绑定(例:交刃 / 燕返) |
| 传奇 | 形态改变 / 池开启器:改变职业玩法结构,build-defining,常为池的强制前置提供方(例:二天一流) |
| 独特 | 全局唯一机制;天赋侧语义待用户裁决(暂无卡例;装备侧已用作唯一性档) |
| 回忆 | **技能升级专用档**,不参与上面这条强度阶梯 —— 它装的不是「一个天赋效果」,而是「把某个已有技能永久换成升级版」,字段构成与其余各档完全不同。详见 §12 |

> 独特与回忆是两个**特殊档**:不进普通稀有度池、不影响其他档的出现概率。独特只在特殊事件下产出;回忆按回忆点模型获得,见 §12。它们不是「比传奇更高一档」,而是另一个维度。

**幅度双层**:
- 层 1 = 形态跨度(判据见 [[content-design-general|通则]] §3),承担主要「稀有度感」。
- 层 2 = 同轴数值步进:同一效果轴相邻档位间 ×1.3~1.5 参考带,不超 ×1.5(防「形态 + 数值」双重膨胀);仅在数值可比时适用。

**定标规程**(设计时执行):
1. 同池同档横向比较(主要标尺);
2. 手算经济验证兜量级(逐回合产 / 耗气、到段回合数、心眼联动、组合外溢,见 §8);
3. 数值定稿归用户(见通则 §11,§8 分工不变)。

量级判断只有横向比较与手算这两条路:设计库的模拟与评分端点已于 2026-07-27 随引擎数值副本一并退役(设计库不再存引擎数值,端点没有数据可读),不必再去找工具粗测。

**用户的稀有度量化**(2026-10-24 用户裁决:「你可以参照双持系天赋，传奇天赋更接近于回忆天赋，会在一定程度上影响玩法。而史诗则一般是比较强大的数值或是一些新奇的小机制，或者机制联动。稀有和普通则基本以数值为主，偶尔存在一些改善生活的极小机制。」)

| 档位 | 用户给的量化 | 参照卡 |
|---|---|---|
| 传奇 | 接近回忆,一定程度上改变玩法 | 〔二天一流〕 |
| 史诗 | 较强的数值,或新奇的小机制,或机制联动 | 〔交刃〕〔二刀开刃〕〔燕返〕 |
| 稀有、普通 | 以数值为主,偶尔有改善操作的极小机制 | 〔剑气回荡〕(稀有) |

- 史诗不应只是单一增伤(2026-10-24 用户评〔万象归一〕:「提升25%拔刀伤害和史诗天赋似乎有点不配」)。
- **减冷却是强度设计**(2026-10-28 用户裁决:「减冷却是明显的强度设计」):冷却缩减改变技能的可用频率,以及每回合有哪些技能可选,属于行动经济的强度设计,不能当作普通档的小数值。冷却结束只恢复技能可用性,不额外提供行动点(见 [[skill-design-principles|技能设计要点]] §8、R3.5)。幅度取 −1,或改为加长现有位移技能的冷却(2026-10-24 用户评〔疾驰〕:「cd减少数值有点高，目前没有给剑圣的位移技能赋予过高的cd，如果要有此类效果我建议-1cd或加长现有位移技能cd。」)。稀有度按它改变的行动经济定档,不因数字小而降档(推断,待用户定标)。

## 10. trigger 结构与措辞规范

trigger 回答「这张卡什么时候生效」,不写效果内容、不写数值;effect 自含完整句,开头可重复时机。

**结构 = 事件 / 对象 / 来源 / 条件 / 频次五段**(设计库字段 `trigger_event` / `trigger_object` / `trigger_source` / `trigger_condition` / `trigger_frequency` + `trigger_frequency_n`),天赋与装备两个实体共用同一套词汇表与校验:

| 段 | 形态 | 要点 |
|---|---|---|
| 事件 | 封闭枚举,24 条分 9 族(持续 / 回合结构 / 行动 / 攻击链 / 受击链 / 判定 / 资源 / 状态 / 移动) | 新卡必填的主干段;取值以设计库 `TriggerEvent` 为准 |
| 对象 | 注册表 id | 只有 8 条参数化事件带对象槽位,分指技能 / 资源 / 状态 / 判定四张注册表(`/api/skills` `/api/resources` `/api/states` `/api/judgments`) |
| 来源 | 该事件的合法来源集 | 只有 7 条事件带来源维度:攻击链的命中 / 暴击 / 命中后 / 造成伤害 / 击杀取「主手 / 副手」,获得状态与失去状态各有自己的来源集 |
| 条件 | 自由文本 | 事件之外的附加前提,写法见下 |
| 频次 | 限流周期(每次 / 每单位回合 / 每轮次 / 每场)+ 次数整数 | 「每次」= 不限流,该档次数恒为 1 |

**枚举取值与校验口径以设计库为准**(`app/models.py` 的 `TriggerEvent` / `TriggerFrequency`,校验见 `app/validation/trigger.py`),本文只写怎么用、不抄词表——抄一份就多一处会漂移的副本。校验三要点:**空 = 不限定**,不是错误(不填对象即「不限对象」,不填来源即「不限主副手」);填了就必须合法(对象须真实存在于对应注册表,来源须在该事件的合法来源集内);**不带对象 / 来源槽位的事件填了任何值即报错**——出现这种错通常意味着事件挑错了,回去重挑。

- **常驻型**:事件取「永久生效」。替代或修改既有机制的说明写进 effect / rules;封闭枚举下事件段不能再拼「·替代X」这类后缀。不用「被动·…」「被动(…)」写法——被动信息由「常驻」tag 承载。
- **旧自由文本 `trigger` 字段仍在**,回填期与五段并存、不删。新卡直接填五段;存量卡里 `trigger_event` 为空、只有自由文本的属正常状态,不是错误数据。存量回填须先出逐条措辞映射清单交用户过目,agent 不自行改在库卡的 trigger。
- **只有装备与本节共用五段结构;技能一个 trigger 字段都没有**——技能的时机由 `resource_type` 与引擎侧 `timing_constraint` 表达,字段面另有 `target_mode`、射程三列、作用范围两列等(见 [[skill-design-principles|技能册]] §1、§4)。装备有五段但没有旧自由文本 `trigger`、也没有 `target_mode`(见 [[equipment-design-principles|装备册]] §3)。
- **附加触发行**(2026-08-05 裁决):一张卡默认单触发;只有**独立的离散触发点**才开附加行(暂限 1 行,撞顶再议)。授予窗口态的后续效果、对既有机制的持续性改写都不算——前者落在被授予状态与 effect 里,后者归「永久生效」主行。附加行存于设计库子表,五段规则与主行相同,且附加行不得取「永久生效」。当前用例:剑气回荡、二天一流。

**怎么给一张卡挑事件**

- 先定这张卡挂在哪条链上(攻击链 / 受击链 / 回合结构 / 资源 / 状态 / 判定 / 行动 / 移动 / 持续),再在族内选最贴的一条。族是设计时的第一个问题,也是录入表单的第一级。
- **就窄不就宽**:能挂「暴击时」就不要挂「命中时」。事件宽窄决定触发面,触发面决定这张卡值多少——挑事件本身是定价决策的一部分(同通则 §3 乘区选择的道理)。
- **不要用条件段绕过事件选择**:条件段是自由文本、不可校验,把本该由事件表达的时机塞进条件,等于把刚结构化的东西退回散文。现有枚举覆盖不了的时机,提请用户扩枚举(枚举增删属通则 §11 的用户裁决权),不自己在条件段造词。
- 带对象槽位的事件尽量把对象填上(例:事件「使用技能时」,对象填拔刀)。留空 = 任意技能,那是一张触发面大得多的卡,定标时别按填了对象的版本算。
- 双刀池的卡多半要用到来源段的「副手」,这是 §2 双刀核心机制在 trigger 上的落点。

**攻击链五事件的 R1.4 时机归属**(2026-08-05 裁决,与规则表 R1.4、[[battle-calculation|战斗计算]] §效果时机双型配套):

| 事件 | R1.4 时机 | 计次 |
|---|---|---|
| 命中时 | on-hit(命中判定成立即触发,不论是否造成伤害、不读取伤害结果;攻击序列第 5 步) | 每次命中一次 |
| 暴击时 | on-hit(暴击判定成立即触发) | 每次暴击一次 |
| 命中后 | after-damage(该次命中的伤害结算完整收束后;**实际伤害为 0 也触发**;攻击序列第 6 步) | 每次命中一次,多段伤害不重复计 |
| 造成伤害时 | after-damage(每段伤害结算后;0 伤不触发) | 每段一次(R1.10) |
| 击杀时 | after-damage(击杀结算) | 每次击杀一次 |

挑法:依赖实际伤害数值的效果挂「造成伤害时」;不读数值、但必须等伤害收束后才发生的(资源获取、标记结算、追加判定)挂「命中后」;施加减益、打标记这类与伤害彻底无关的挂「命中时」。

**条件段该写什么**

- 条件段回答「在什么前提下」,与事件的「什么时候」分工。常见形态:资源阈值(剑气 ≥ N / 剑气 = 100)、剑气高低轴(§4,使用固定点数)、状态在场(状态名以 `/api/states` 注册表为准)、自身或目标的属性 / 生命比较。
- **状态引用措辞**:条件段引用已注册状态统一写「处于〔状态名〕状态」,方括号便于全库检索;State 条目改名或删除前先全库检索引用。状态注册表会持续增加,不得在本文硬编码一份“现有状态”清单;每次设计都重新读取 `/api/states`。纳刀印属于资源特性,不能因为名称相近而与状态〔纳刀〕混用。
- **战斗结算中不插入玩家选择**:需要玩家选择目标、形态、代价或开关时,必须在动作开始前完成。攻击动作或其他结算一旦开始,后续分支自动处理,不得在命中、伤害或资源结算之间弹出选择。条件段只写自动判定前提,不承载交互。
- 不重复事件已经表达的信息,不写效果内容与数值(那是 effect 的活)。
- **口径默认**:阈值型条件即时判定、不做快照;需要快照才在 rules 成文注明。
- 五段里只有条件段不可校验,写得越随意后面越难检索——能用事件 + 对象表达的,就不要落到条件段。

**频次怎么定**

- 频次是**防滥用护栏**的主力手段之一(护栏手段须分布使用,见通则 §12 六分布第四项)。先看触发面:事件宽、又能反复触发的效果不配限流就是失控入口;触发面本身已经很窄的才留「每次」。
- 周期按效果服务谁来选:只在自己行动时才成立的用**每单位回合**,与敌方行动交织 / 跨全场统计的用**每轮次**,一场一次的大件用**每场**。频次档里没有「本回合首次」——它与「每单位回合」语义重复,且「回合」不合 R3.1 的精确用词(轮次 = 全体各行动一次的完整循环,单位回合 = 其中某一个单位的行动)。
- 次数与周期一起定价:「每轮次 2 次」与「每轮次一次」是两张不同强度的卡,不是同一档的两种写法。
- 可反复触发的概率类效果,限流与递减(通则 §3 的 `1 / (1 − p)` 判据)是两种手段,可以只用一种,但至少要有一种。

---

**同一效果的默认触发口径**：effect 中没有另行声明时，全部效果都跟随主 `trigger_event` 在同一主事件中结算。只有某段效果确实发生在另一个独立事件时，才登记附加触发；不要因为一句 effect 含有多个结果就拆出附加触发。

## 11. 出现条件(unlock_trigger)与天赋间关系

`unlock_trigger` = **本卡的出现 / 解锁条件**,空 = 正常开放节点。方向纪律:只写「本卡需要什么才出现」,不写「本卡是谁的前置」——前置提供方的说明放 rules / notes。规范式 = `前置:X(池名)`(半角标点;天赋树落地后可演进为坐标等结构化格式,字段已预留)。当前 L1-L3 审阅不消费该字段(纯预留)。

天赋间关系三分法(载体分工):

| 关系类型 | 载体 | 例 |
|---|---|---|
| 解锁型硬前置 | 消费方 unlock_trigger「前置:X(池)」+ notes 设计簇说明 | 交刃 / 燕返等双刀卡 |
| 升级型(lv1→lvN) | levels_json(每级一个完整草稿对象;lv1 取顶层字段) | 剑意澎湃 lv2 |
| 隐性构筑依赖 | 不标(玩家构筑抉择) | 攒气件 ↔ 耗气件协同 |

不建结构化关联、不进规则表;天赋数量成型后一次性关系梳理。

## 12. 回忆类天赋(技能升级)

**定位**：回忆是与「独特」并列的特殊档，不进普通稀有度池，也不影响其他档的概率。获得方式按用户 2026-10-12 的回忆点模型：玩家把回忆点自由分配到回忆本体与专属节点（见下文“回忆点、专属节点与回忆的定位”；早先“只在特殊事件下随机产出”的写法已被取代）。它的作用只有一件事：把某个已有的上位职业基础技能永久升级成同职业的新技能。

**为什么单列**：回忆天赋与职业强化类天赋不是同一种设计对象。职业强化类天赋以职业为强化对象，内容落在天赋自身的触发与效果字段；回忆天赋以一个既有技能为升级目标，天赋只建立升级关系，完整玩法内容落在升级后的技能上。因此两类天赋不得共用同一张字段蓝本。

### 硬约束

| 约束 | 说明 |
|---|---|
| **一个技能只能被回忆升级一次** | **局内规则**：某个技能一旦被某张回忆天赋升级，该技能在这一局内不再获得第二次回忆升级。设计库允许同一技能存在多个备选升级，但一局只会兑现其中一个 |
| **升级前后属于同一职业** | 回忆天赋、基础技能和升级技能的 `class_id` 必须完全相同。升级技能不是跨职业移植 |
| **仅上位职业基础技能** | 回忆天赋只能属于上位职业，也不能把下位职业技能或已经升级过的技能作为目标 |
| **禁止链式升级** | 升级技能的 `upgrade_of` 指向基础技能；不能以另一条升级技能为基础继续升级 |
| **完全替换** | 升级技能永久取代基础技能。新技能必须独立给出完整字段，不能依赖“保留原技能未改部分”才能成立 |
| **默认兼容并核对内容** | R2.5 规定，明确作用于基础技能的效果默认也作用于升级版本，除非效果明确排除某个升级。兼容效果只能修改升级形态实际存在的内容；兼容矩阵用于核对内容是否存在、计次是否放大以及是否需要例外或补充表达 |
| **没有天赋等级维度** | 回忆天赋只有一个版本，不做 lv1→lvN；发生变化的是技能，不是天赋自身 |
| **天赋与技能分开命名** | 天赋名是玩家在事件中看到的卡名；技能名是战斗中显示的名字，两者不必相同 |

### 案例提炼

以下卡片只作为方法证据，不借此重开既有玩法裁决，也不把案例中的数值当作其他技能的定标值。卡片是否锁定以设计库 `status` 为准，本节不另行认定（用户 2026-10-28：「设计库优先」）。

- 〔化剑为气〕与〔疾风骤雨〕表明：回忆天赋本身只需清楚说明永久升级关系，完整玩法必须落在可独立理解的升级技能实体上。
- 〔裂空〕把单体动作改为多目标形态，〔连斩〕把一次命中改为由连续命中决定长度的攻击序列。两者都改变了目标或结算结构，并分别补清了逐目标资源、整次使用、逐刀结算与外部触发次数。这类变化才构成回忆升级；只在原技能末尾加收益不构成形态升级。
- 〔残心〕与〔印心〕表明，资源获得的时点、对象和重复条件必须形成完整命题；〔介错〕表明并行资源效果是否叠加要明确；〔破竹〕表明阈值判定时点与同层加法应放在 rules。案例共同指向同一要求：玩家字段说明当前玩法，rules 说明必要结算边界，notes 只保存开发意图。

### 固定工作集与材料边界

1. **记录来源**：先读取 live API 与 `origin/master` 快照，记录 `schema_version`、来源提交、完整 talents 与 skills 集合的规范化 SHA256，并确认目标对象在两处语义一致。来源发生无法解释的漂移时停止。
2. **筛选材料**：先筛 `shelf_state=已上架`，再按任务允许的状态取材。草稿、待删除、已归档不作为设计依据；用户明确点名的草稿对象只作为本次待改写载体。锁定对象只作参考，除非发现具体矛盾，不重开其裁决。
3. **枚举兼容对象**：同时检查结构化指向、玩家文案与通用结算语义。结构化指向包括技能对象、升级关系与相关状态链接；文案检索包括明确点名基础技能的当前有效天赋或规则；通用结算语义包括会因动作、命中、暴击、伤害段、击杀、资源变化、状态或目标数而作用于基础技能的效果。只查名字会漏掉通用效果，只查结构字段会漏掉仍在文本中表达的关系。文本命中只用于发现候选，不能单独证明结构关系；最终结论必须引用专用字段、现行规则或明确裁决。
4. **冻结工作表**：每个基础技能、两个回忆天赋载体、两个升级技能载体、直接相关职业与前置、触发元数据、当前有效兼容对象各占一行。记录原文和来源，不在盘点阶段改写或评价。

### 双层设计

#### 第一层：技能形态升级

先把基础技能逐句拆开，对每一句标为「保留」「删除」「改写」或「改换结算结构」。逐项覆盖：

- 动作类别、目标选择、射程、作用范围与位移；
- 命中、暴击、伤害段、逐目标或逐事件的结算单位；
- 标准动作、额外动作、攻击机会及专属资源的取得和消耗；
- 职业机制节奏、前置成本、失败分支与多人环境可靠性；
- 与现有锁定卡、状态条件和通用规则的组合放大。

升级必须同时给出玩家得到的优势和承担的限制或风险。删除新增机制后，如果基础技能仍能原样运行而只是少一段额外收益，这个方案更接近职业强化效果，不是合格的回忆升级。

#### 第二层：原技能兼容性

对固定工作集里的每个现有效果分别问：

1. 它依赖的是基础技能的身份，还是某个可能已被改掉的具体形态？
2. 它按一次使用、一次动作、一个目标、一次命中、一段伤害还是一次资源变化计数？
3. 升级后的多目标、多段、自动续击、位移或资源变化会不会把触发次数意外放大？
4. 升级是否删除了该效果必需的命中、伤害、消耗、状态或目标条件？
5. 继承后会不会产生零代价循环、自触发、互相触发或已经结束的结算被再次打开？
6. 玩家文案是否能独立说明结果，现有结构和运行时是否能稳定表达？

同一基础技能的两个升级方案可以得出不同结论，不能为了整齐强行统一。

### 兼容性结论

| 结论 | 判据 |
|---|---|
| **默认继承** | 按 R2.5 继续生效，且效果依赖的内容在升级后仍存在；矩阵须写明按一次使用、逐目标或逐段中的哪一种口径生效，并确认没有未声明的次数放大 |
| **明确不继承** | 升级删除了必要形态，或继承会破坏该升级的取舍、造成异常循环或不可接受的次数放大；必须说明玩法理由以及玩家从何处得知 |
| **需要统一措辞但不新增结构** | 玩法上应继续生效，现有结构也能承载，但当前文案只点名基础技能或依赖旧形态；修改玩家文案或 rules 即可表达，不借机新建关系模型 |
| **未来建模需求** | 玩法意图明确，但现有设计库结构或运行时无法无歧义表达；记录所缺的能力和受影响对象，不把它写成已经能够继承，也不在当前内容任务中扩建系统 |

每个基础技能提交一张矩阵，同时比较两个升级方案：

| 现有天赋或规则 | 在原技能上的生效单位 | 升级方案甲 | 甲的结论与玩法理由 | 升级方案乙 | 乙的结论与玩法理由 | 需要的文案或结构动作 | 设计库与 Ship 表达能力 |
|---|---|---|---|---|---|---|---|

矩阵必须覆盖固定工作集中的全部当前有效对象。没有相关对象时也要写明检索范围和“无”，不能省略矩阵。设计兼容性与运行时可实现性分别下结论：本轮不修改 Ship，不等于可以跳过运行时缺口，也不等于运行时缺口可以反向否定已经成立的玩法设计。

### 回忆技能升级协作蓝本

1. **事实盘点**：事实核查者冻结对象、来源版本、审计边界和兼容对象；方案整理者不得使用被排除的草稿或归档内容补证。
2. **方案设计**：在用户给出的核心构想或对固定批次的明确授权内，结算分析者完成逐句形态对照与典型回合推演，方案整理者补全两套有明显玩法差异的升级。
3. **独立审查**：结构核查者检查字段和载体；反方审查者专查多人环境失效、触发次数膨胀、资源或行动循环、前置成本失真、状态条件含混、递归边界与兼容性漏项；整合者只处理范围内问题。
4. **候选输出分成两个实体**：
   - 回忆天赋：`id`、`name`、`class_id`、`rarity=回忆`、`upgrade_skill_id`、完整 effect，以及必要的 rules、notes 与 tags；不套用职业强化类天赋的触发五段和等级蓝本。
   - 升级技能：`id`、`name`、`class_id`、`upgrade_of`、动作资源、目标模式、射程、作用范围、位移、effect、rules、notes 与 tags。所有未改字段也要明确给出，保证该技能能独立导入并完整替换基础技能。
5. **每个候选必须附带的证明**：单卡作用、优势与代价、多人环境可靠性、触发次数、行动与专属资源、前置成本、组合放大、状态条件、逐句形态对照、删除性检验、典型回合、命中失败与资源不足时的行为、递归边界、兼容性矩阵、可调数值和不得破坏的定标约束。
6. **字段职责**：effect 写玩家可独立理解的完整当前命题；rules 只写必要的结算顺序、计次、叠加与例外；notes 写开发意图、结构缺口或权威指针，不保存旧方案、改版经过和自我辩解。已有独立结构字段的信息不在文案中无意义重复。
7. **结构适配性**：逐项标明「已结构化支持」「只能由自由文本表达」「设计库缺口」「Ship 运行时缺口」。设计库能存而 Ship 不消费时，不能写成已经可实装；需要新枚举或共享形状合同时，先作为用户审核项，不在内容任务中自行扩建。
8. **收敛与回执**：两套方案都字段完整、兼容矩阵无漏项、独立反方意见已经处理，并且只保留一套推荐成果包供用户审核后，任务才可收敛。未经审核，不把提案写入生产事实。

### Agent 自检清单

#### 来源与范围

- [ ] 已记录 live API 的版本、来源提交、完整集合摘要，并与 `origin/master` 对照。
- [ ] 已按 shelf_state 后 status 的顺序筛选材料；被点名草稿只作待改写载体。
- [ ] 已冻结基础技能、两个回忆天赋、两个升级技能、职业与前置、触发元数据和全部兼容对象。

#### 单卡与技能

- [ ] 回忆天赋和升级技能是两个完整实体，升级技能无需读基础技能正文也能独立理解。
- [ ] 升级改变了目标、空间、结算结构、资源节奏或行动风险中的至少一项，不是单纯数值上浮。
- [ ] 已覆盖单卡作用、多人环境、触发次数、行动与资源、前置成本、组合放大、状态条件和字段归属。
- [ ] 已明确逐次、逐目标、逐命中、逐伤害段与整次使用的边界，以及失败和递归行为。

#### 兼容性

- [ ] 已同时检索明确点名、结构化指向和通用触发语义。
- [ ] 每个兼容对象已按 R2.5 对两个升级方案分别检查，确认升级形态是否仍有被修改的内容，并记录例外、次数放大和表达缺口。
- [ ] 多目标、多段和自动续击没有把外部效果的次数静默放大。
- [ ] 需要改文案或未来建模的项目已写清动作与权威，不把缺口伪装成现状。

#### 收敛

- [ ] 两个升级方向有真实玩法差异，且各自的优势、代价和使用场景清楚。
- [ ] 独立分析与独立反方审查已完成；范围外建议未被升级为当前阻断。
- [ ] 最终只提交一套推荐成果包，保留真实风险与备选理由，等待用户一次性审核。
- [ ] 未经审核未写生产 API、受控快照、Ship 运行代码或 KB 当前裁决。

### 停止条件

来源提交或生产数据发生不可解释漂移、冻结对象缺失或关系损坏、所需权威事实无法取得、写入范围将超出任务授权，或独立审查发现一轮集中修正仍无法避免错误设计时停止。普通玩法取舍由 agent 按现行方法收束，不中途请求用户裁决。

### 升级不是槽位切换

升级是永久替换：基础技能被完整取代，一切以升级技能的完整记录为准。明确作用于基础技能的现有效果按 R2.5 默认继续作用于升级版本；兼容矩阵负责确认升级形态是否仍有对应内容、计次是否变化以及是否需要明确例外。这与战斗中按条件来回切换的临时形态不同，后者的两个技能仍同时存在。

### 回忆点、专属节点与回忆的定位

以下是用户 2026-10-12 至 10-22 对回忆与回忆节点的裁决。它们原先只记在设计库提案目录（`docs/proposals/2026-09-talent-system/claude/` 下 `28-memory-and-talent-principles.md`、`29-damage-model-additive.md` 与 `auto/user-model.md`），2026-10-28 迁入本文。出处里的文字多是当时的转述记录，不是逐字原话，所以本节不加引号；“归纳”表示 Claude 从多次回复中归纳的取向，用户可以随时纠正。

**回忆的定位**（用户 2026-10-18，记录见 28 号 §12）

- 回忆是 SoT 区别于传统战棋的部分，偏肉鸽、暗黑类构筑：每个技能有自己的新形态，新形态再有几个特化方向；类似 WoW 英雄天赋树，用不同加点应对不同场面。
- 不能洗点，玩家需要预设玩法方向。
- 普通天赋更接近火纹的角色特性与职业特性，与回忆一起构筑玩法（见 §13）。

**回忆点经济**（用户 2026-10-12，记录见 28 号 §10）

| 项目 | 裁决 |
|---|---|
| 获得 | 击败传奇敌人（一般是 Boss 或小 Boss，最终 Boss 除外）时获得；三个 Act 共 5 点，正常流程最少 5 点，过程中可能额外获得；将来加入 Act 4 时再适配 |
| 使用 | 回忆有专属入口，可以随时加点；回忆天赋树在转职后开放。“转职前获得的点数保留到转职后使用”是 Claude 的理解，用户未单独确认 |
| 分配 | 玩家自由分配到回忆本体与专属节点：可以 5 个技能各升一次，也可以专精 1–2 个技能 |
| 专属节点上限 | 每个回忆最多 3 个专属节点，避免过度设计 |
| 三选一 | 三选一固定给普通天赋；保留位方案否决 |

- 同一技能的回忆互斥：依据本节硬约束“一个技能只能被回忆升级一次”。2026-10-12 时这是 Claude 的默认做法，用户没有单独确认。
- 分配后本局固定：由用户 2026-10-18 的“不能洗点”推出。
- 用户 2026-10-15 提出把回忆做成类似 Last Epoch 技能树或 Inkbound 升级模板的扩充方案，2026-10-17 定为“未来再说，当前不动”。回忆簇的数量与结构仍待用户决定，当前按上表执行。

**本体与节点的强度分配**

- 回忆本体持平或略亏，专属节点给更高的额外收益（用户 2026-10-12）。“5 个技能各升一次”收益低是玩家自己的选择，玩家有自主权。
- 回忆本体必须保持自身特色，不能把特色移到节点；特色可以带缺陷，由节点补足（用户 2026-10-21，记录见 29 号）。
- 额外回合、额外行动类回忆：单资源时明显低于对位，多资源时相对更高（用户 2026-10-21）。评估时玩家的标准与迅捷动作暂按常态最多各 2 次计算，敌人每回合仍是单次行动（用户 2026-10-21，记录见 29 号）。
- 同一技能的互斥回忆，在同一组场景、同一基线下比较；判断过强以同等投入为基准（归纳，2026-10-13）。

**节点的方向**（用户 2026-10-18 对〔裂空〕〔连斩〕节点的说明，Claude 整理，记录见 28 号 §12）

| 方向 | 含义 | 例子 |
|---|---|---|
| 功能 | 改变攻击形状、选目标或站位，不直接改数值，大部分场景适用 | 〔贯虹〕 |
| 数值补足 | 补技能的短板数值或资源 | 〔凝气〕 |
| 移动 | 出手前后的位移，打完就走 | 〔游刃〕 |
| 单体／破甲 | 强化对单个、高防御目标的打击 | 〔连绵〕 |
| 属性堆叠奖励 | 奖励堆某项属性的玩家 | 〔破限〕 |
| 技能交互 | 与其他技能或印记联动 | 〔圆满〕 |

- 一个回忆的几个节点覆盖不同方向，不落在同一方向。
- 节点方向给普通天赋留“挂钩”：移动节点配移动后增益类普通天赋，属性堆叠节点配命中、技巧类普通天赋，技能交互节点配〔招架〕、闪避类普通天赋。
- 技能交互较难设计，不强行加；交互必须顺着现有回合规则（先移动再攻击、移动机会只有一次）（用户 2026-10-18，否决〔游刃〕与〔一闪〕的交互）。

**节点的质量**

- 节点要有存在感：用户指出〔不动〕（额外闪避改为等于技巧）与其他节点相比太普通，需要重做（2026-10-19，记录见 29 号）。
- 避开窄条件配普通加成、节点之间互相抵消、堆数值与自动化、过度复杂的状态机（归纳）。
- 改动从原版出发，能保留的机制尽量保留（归纳。来源是用户 2026-10-20 讨论〔空想〕时说的“最好保留原版的一些设计”，记录见 29 号）。
- 升级技能不继承原技能自身的效果文本：需要的效果必须在升级技能里明写，未写视为没有；回忆可以自由修改基础被动的性能（用户 2026-10-20，记录见 29 号）。作用于基础技能的外部效果（例如天赋）仍按 R2.5 默认作用于升级版本，两者不冲突。
- 用户定过的回忆与节点不替换、不删除；偏弱时列为观察项（归纳，2026-10-22）。Claude 自己设计的节点在评估中失效时，重做而不是硬调数值（归纳）。
- 节点不提供跨战斗的永久增益；本场战斗内持续的增益可以（归纳，依据用户 2026-10-28 评〔两仪〕：「单回合生效也行，不提供永久增益更方便平衡」，随后确认「〔两仪〕本场战斗生效」）。
- 状态默认每个关卡重置，跨关卡保留必须特别写明（用户 2026-10-28 评〔剑痕〕：「〔剑痕〕不保留。基本没有特殊声明时都是每个关卡重置」）。推广到资源，以及在设计库里写成“每场战斗开始时为 0”（把一个关卡当作一场战斗），是归纳。回忆本体给的〔剑痕〕也按此改为每场战斗开始时为 0 层。
- 状态与技能可以同名（2026-10-28 用户裁决：「没问题，属于的族不同」），例如〔见切〕技能给出〔见切〕状态。

**剑圣的防御定位**（记录见 `auto/user-model.md` 第二节）

- 剑圣兼顾物理输出与闪避坦克，闪避须整局有效（2026-10-12）。
- 用户 2026-10-13 指出：基础加闪避、天赋加百分比减伤不自洽；护盾与闪避互补。由此的做法（归纳）：防御身份是闪避，不新增百分比减伤；护盾可以有，但量要受控。
- 剑圣不以生存能力著称，防御要控制，不给后续高生存职业开坏头（用户 2026-10-22）。由此的做法（归纳）：新增或重做的节点不提高防御减伤，防御类节点优先改成进攻、资源或交互。
- 异常闪避与异常回复需内部调整（用户 2026-10-21）。
- 敌人攻击模型可以大胆，不按属性推算（用户 2026-10-22）。
- 招架组：牺牲一定的主动性，换来较为持续的减伤或反击（用户 2026-10-21）。
- 招架组两个回忆的分工（2026-10-28 用户裁决：「〔浮生若梦〕的特点应该是，对攻击的抵抗更强，但仅限少量攻击，主要用于抵抗可预见的高伤害，具有一定cd使单位必须掌握释放时机。而〔见切〕则是提供一个输出端补强，可以更频繁的释放来持续获得收益，所以防御收益相对低且没有〔浮生若梦〕稳定」）：
  - 〔浮生若梦〕：确定抵抗少量攻击，冷却让释放时机成为决策。节点不得把它扩展成长期覆盖多次攻击的防御（推断）。
  - 〔见切〕：输出端补强，冷却比〔浮生若梦〕短；防御收益低于〔浮生若梦〕，并且是概率性的、不稳定的（推断）。

**已作废的写法**：28 号 §3、§5 曾建议普通天赋“写成接口事件或技能位置（普攻位、位移位、防御位、爆发位）”，不写具体技能名。用户 2026-10-24 否定了这类自造词，改为直接写技能名（见 §5）。共享量与事件作为两层之间接口的思路仍可参考。

### 规模预期

v1 每个基础技能预计制作 **2 个**回忆升级供玩家选择。这是内容投入预期，不是设计库容量上限，也不能从当前数据条数反推。

## 13. 普通天赋池的组织

普通天赋是叠加在“职业 → 技能 → 回忆天赋 → 回忆节点”之上的系统，前面几项成立后再设计（2026-10-28 用户裁决：「至少先得把职业+技能+回忆天赋+回忆节点的逻辑确立打通，普通天赋可以作为基于前项成立后的系统叠加。」）。

- **战棋而不是肉鸽**（2026-10-24 用户裁决：「你的很多普通天赋设计有点更偏向肉鸽游戏，而不是战棋游戏。」）：设计一张卡先问它在棋盘上改变了什么决策，例如站位、行动顺序、目标选择、技能取舍，而不是只加一个数。
- **参考来源**（2026-10-24 用户裁决：「火纹的一些角色特性，职业特性我就觉得很有意思。你可以多参考参考。不过我们的战棋没有通用的追击系统，也没有反击系统（所以不存在火纹里的先手，后手，追击）。」2026-10-28 补充 XCOM、The Last Spell、永铃回响）：先查 [[05-Research/references|参考作品索引]] 里的已有调研；依赖追击、反击、先手后手的机制不用。
- **流派是两个维度**（2026-10-24 用户裁决，原话较长，要点：剑圣有追加特效流、剑气循环流、反击流、一闪流、斩击流等；「斩击流（放弃居合）严格来说是靠上位的裂空或者连斩。并且斩击流和追加特效流也可以是共存的。追加特效流准确来说是一种输出方向，和技能威力流相反」）：
  - 输出方向：追加特效 ↔ 技能威力，两者相反。
  - 技能重心：斩击流（靠〔裂空〕或〔连斩〕）、一闪流、反击流（反击只来自回忆或技能给出的反击）、居合循环。
  - 两维可以组合，例如斩击流加追加特效 =〔连斩〕多段逐段触发。每个流派在各稀有度都要有可选的卡，每张卡标注所属流派。
- **资源加速必须配兑现**（2026-10-24 用户裁决：「加速居合或者拔刀都不意味着我们的攻击频率变高（每回合的行动资源是一样的），所以要么是居合或者拔刀的威力被天赋极大加强来，要么是我们不在意在释放什么技能，而是这些技能触发的特效本身被利用且可以频繁造成伤害（附伤）」）：剑气、印记的加速本身不算收益；资源加速卡写明服务哪个兑现方向，评审检查“只加速、无兑现”的卡。
- **锁定的双刀卡也可以改**（2026-10-24 用户：「双刀流的几个天赋虽然写着锁定，但不意味着你不可以修改。如果觉得数值或效果有问题，同样你有权限修改」）：〔二天一流〕〔交刃〕〔二刀开刃〕〔剑气回荡〕〔燕返〕发现数值或效果问题时直接修改，不只提建议。
