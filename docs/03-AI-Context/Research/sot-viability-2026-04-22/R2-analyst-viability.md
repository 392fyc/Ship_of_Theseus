## Executive Summary

基于 5 份 researcher 输出，载体 A（小型战棋）在锚点承载、Godot 4 可行性、co-op 成本三轴均优于 C/D，是唯一不需要核心机制改造的路径。天赋树当前 75 节点规模存在显著平衡与新手引导风险，建议以 Tier 2（30-40 节点）为开发起点而非裁判结论。最大不确定性来源：战棋 + 4p co-op 在 Steam 上成功案例仅 Sunderfolk 一例（上线 3.5 周），且"复杂天赋树 + roguelite"在行业内属已知设计盲点。信度 3/5，中等。

## 任务 A：四轴打分

### 载体 A：小型战棋 + Roguelite（Into the Breach 骨架）

**Market — 4/5**

Steam 战棋 roguelite 正向信号明确：Into the Breach 94% 好评 (21,759 评，B2.2)、Sunderfolk 2.0 co-op 94% 好评 (1,663 评，B2.2)。中文玩家对战棋亲和度高于全球均值（Banner of the Maid 中文评价强于英文区，B2.2）。减分项：Banner of the Maid (823→82 CCU) 与 Hadean Tactics (2045→10 CCU) 的衰减曲线说明战棋 roguelite 的长尾留存是已知弱点；Sunderfolk co-op 数据仅 3.5 周，长期留存未知。

**Tech — 4/5**

co-op 网络同步成本最低：格子位置 + 职业技能 + HP 状态，Godot 4 MultiplayerSynchronizer 原生承载（B2.2）。美术量最低——网格单位复用，无 ARPG 怪物库需求。战棋逻辑（回合制、格子判定）在 Godot 4 教程生态中覆盖度最高（GDQuest）。减分项：生产级战棋 + 4p co-op 的 Godot 4 样本缺失（B1.3），Phoenix Point 以"同步成本过高"为由放弃 co-op，说明即使回合制网络同步也有隐性工程成本。

**Content Scale — 3/5**

多职业（8×2=16 路径）+ 战棋地图 + Relic 三层内容理论上可扩展。但 B1.2 明确指出"复杂 talent tree + roguelite + 战棋"是行业盲点，无成熟参考。75 节点/职业 × 16 路径 = 1200 节点总量，平衡测试成本非线性膨胀。战棋地图随机性上限受网格尺寸约束（≤10×10）。Into the Breach 靠"确定性谜题"而非内容量驱动留存——SoT 天赋深度能否接替谜题复杂度，尚无证据。

**Retention — 3/5**

4p co-op 社交粘性是正项（Sunderfolk "多年来最好的多人体验之一"，B1.3）。roguelite run 结构（3 Acts × 10 Stages）提供短中期复玩动力。减分项：战棋 roguelite 的衰减陡峭（两个案例均 90%+ 衰减，B2.2）；Gloomhaven 的"匹配困难"（玩家倾向固定小组，B1.3）说明 4p co-op 的 sticky 特性是双刃剑——留存依赖固定组，单人或随机匹配场景留存差；Into the Breach 社区明确表示 co-op "会变成一人独断，其他人按指令点击"（B1.3），说明战棋 co-op 的协作设计需主动破解。

**总分：14/20，可行性区间：中等偏高**

### 载体 C：ARPG + Roguelite（Diablo-like 4p co-op）

**Market — 3/5**

No Rest for the Wicked (Jan 2026 co-op 加入后峰值 62K CCU，B2.2) 是正向数据点，但背靠 Moon Studios（Ori 开发商）信誉。中国玩家 ARPG 基数存在（PoE 硬核社区）但被大厂垄断。Wolcen 2020 扑街（<100 CCU 衰减）是高度相关的中小团队反面样本。

**Tech — 2/5**

实时战斗同步要求百毫秒级延迟，Godot 4 文档对生产级实时 co-op 覆盖薄弱（B2.2）。美术需求最重：怪物库 30+ 种、5+ 主题环境、实时特效，solo dev 无法独立交付（B2.2）。co-op 成本倍增 2.2×，三载体最高（B2.2）。

**Content Scale — 3/5**

ARPG 内容扩展性强（季节制、掉落池），但 SoT 锚点中"枪火式天赋"与 ARPG 的习得累积式天赋树架构冲突，需重构（B2.2）。多职业克制关系在 ARPG 语境下导致 co-op 平衡非线性爆炸。

**Retention — 4/5**

ARPG 的装备驱动 loop 是已被验证的长尾留存机制（PoE 季节制、D4 赛季更新）。但这一留存机制与 SoT "roguelite run 内完整循环"的核心锚点有结构冲突——roguelite 每次重置等于清空装备积累。

**总分：12/20，可行性区间：低-中等**

### 载体 D：Deckbuilder Tactics + 网格

**Market — 3/5**

卡牌 roguelite 在 Steam 总体红海（STS、Balatro、Monster Train 2 占高地），但"卡牌 + 4p co-op"仍是蓝海（STS 2 仅 Mar 2026 开局，B2.2）。中文玩家对单纯卡牌热情低于西方（B2.2），STS 2 EA 无中文本地化。STS 2 从 97% 首日好评→50% 30 天好评的反差（B2.2）是平衡成本的直接信号。

**Tech — 3/5**

网络同步需求低于 ARPG、高于战棋（需处理 turn order 协议、手牌同步、combo 触发）。美术量低-中等，卡牌插图可外包。co-op 成本倍增 1.9×（B2.2）。GDQuest 有 roguelike deckbuilder 教程覆盖，但战棋 + 卡牌的融合层在 Godot 生态无样本。

**Content Scale — 4/5**

卡牌框架天然承载修饰器逻辑（"手牌 = 技能修饰器"直观映射），内容扩展靠卡池增量。STS 2 的 200+ Relic + 350+ Card（B2.1）说明卡牌内容规模可以极大。减分项：多职业专属牌组设计成本高，每职业需独立卡池——8 职业 × 2 进阶 = 16 套牌组的平衡工作量接近天赋树的平衡量。

**Retention — 3/5**

单人卡牌 roguelite 留存已被验证（STS 95%+ 好评长期稳定），但 co-op 卡牌的留存数据尚无 60 天样本（STS 2 才上 EA 1 个月）。STS 2 的"权力幻想被 4 人稀释"批评（B2.2）是留存风险点——每人"牌权"缩小 75%，需要强协作 bonus 补偿。

**总分：13/20，可行性区间：中等**

## 任务 B：天赋规模三档 trade-off

**前提说明**：用户已明确当前 75 节点为非确定版本，三档评估均以"可能加强也可能简化"为前提，不视为 ground truth。以下所有开发成本以载体 A 为参照基底。

### Tier 1：保持 75 节点/职业（当前版本）

- **开发成本**：1.0x（基准）。8 职业 × 75 节点 = 600 节点总量（16 进阶路径后扩展至 ~1200 节点等效平衡面）。每节点需要 balance pass，加上 Bridge Tax 经济学与 Deep Dive 拓扑约束，预计平衡迭代周期 6-12 个月，远超 solo dev 安全范围。
- **平衡成本**：极高。B1.2 明确："成熟商业设计迄今未见"复杂 talent tree + roguelite 组合。行业内 Othercide、Hades 2、Monster Train 都主动回避超大天赋树。
- **新玩家 onboarding 难度**：高。SoT 锚点是"复杂天赋树"，但 B1.2 指出 80+ 节点天赋树在 roguelite 中易导致"meta 已锁定，run 内选择变虚"的决策稀释。Five-Staff 布局 + Bridge Tax 对新玩家认知负荷高。
- **核心锚点承载度**：5/5。完整呈现"复杂天赋树"锚点，build 深度最大，跨轴 synergy 空间最丰富。
- **4p co-op synergy 影响**：每玩家独立 75 节点树，4 人组合产生 4^n 级协作可能，理论 synergy 最深；但协商成本和"A 火伤 B 无用武之地"的跨玩家浪费风险（B2.1）最高。
- **结论**：内容最丰富，但 solo dev 可行性最低。仅适合有明确扩展计划（至少 2-3 人团队）或先做单职业原型验证后再扩的路径。

### Tier 2：简化到 30-40 节点/职业

- **开发成本**：0.55x。节点总量压缩至 ~240-320（16 路径），保留 Five-Staff 布局骨架和 Bridge Tax 经济学，砍掉 Deep Dive 区细节旁支和 stat_minor 填充节点，保留 gauge_core / gauge_extend / active_skill / advancement 核心类型。
- **平衡成本**：中等。接近 Monster Train Champion spec（单 run 5 个选择点）× roguelite 层的复杂度，有 Hades 2 Arcana（25 张 + Grasp 容量限制，B1.2）作为可参照的中等规模成功案例。
- **新玩家 onboarding 难度**：中。Five-Staff 视觉布局仍存在，但每轴节点数压缩后信息密度下降，玩家可在 1-2 次 Run 内理解主路径。
- **核心锚点承载度**：3/5。双转职路径保留，gauge 系统保留，Bridge Tax 经济学保留，但 build 深度感弱于 Tier 1。"复杂天赋树"的感知取决于呈现——若 UI 清晰展示 Five-Staff 结构，玩家感知深度可高于实际节点数。
- **4p co-op synergy 影响**：协商成本降低；跨玩家 synergy 设计空间仍足够（4 职业 × 30-40 节点 = 每人约 10-12 个有意义决策点/run），可对标 Hades 1 Mirror of Night（~16 个大类互斥选择，被评为"对的升级感"，B1.2）。
- **结论**：solo dev 可行性最高的起点。可以先以 Tier 2 做 MVP 原型，通过玩家反馈决定是否向 Tier 1 扩展。

### Tier 3：简化到 20-25 节点/职业

- **开发成本**：0.30x。节点总量 ~160-200（16 路径）。接近 Gunfire Reborn 修饰器规模（每职业 3 技能 × ~20 升级点，B2.1），或 Dead Cells 突变系统规模（B1.2）。
- **平衡成本**：低。有大量参照案例（Gunfire Reborn、Hades 1 Mirror、Dead Cells）。
- **新玩家 onboarding 难度**：低。单次 Run 内 25 点预算可在第一局完整体验一条主路径。
- **核心锚点承载度**：2/5。"复杂天赋树"锚点严重压缩。Five-Staff 布局若保留会显得稀疏；Bridge Tax 经济学在节点稀少时无实际约束力；"多职业"的差异化主要由职业技能而非树状路径体现，退化为"技能修饰器"模式而非真正的天赋树。
- **4p co-op synergy 影响**：协商成本最低；synergy 设计空间有限，易在 5-10 次 Run 后枯竭；玩家"build 身份感"弱，co-op 中职业差异化依赖职业基础技能而非天赋选择。
- **结论**：作为"最小可验证原型"的早期测试版本可接受，但若 SoT 将"复杂天赋树"作为核心差异化卖点，Tier 3 实质上放弃了这个差异化。

## 任务 C：载体决策

### 主路径：载体 A（小型战棋），天赋规模从 Tier 2 起步

**决定性 rationale（3 条）：**
1. **锚点零改造**：多职业 / 天赋树 / roguelite run / 4p co-op 均与战棋框架天然兼容，无需重构核心系统（B2.2 锚点承载 ★★★★★）。
2. **co-op 工程成本最低**：格子战棋网络同步复杂度最低（1.7× vs ARPG 2.2×，B2.2），Godot 4 MultiplayerSynchronizer 原生适配，solo dev 可在不引入额外工程师的情况下实现 4p。
3. **市场蓝海仍存**：格子战棋 + 4p co-op 在 Steam 上成功案例极少（A 级样本仅 5-7 个，B1.3），Sunderfolk 2.0 94% 好评验证需求存在但供给稀缺，多职业 + 深度天赋的差异化角度尚未被占领。

### 备选路径：A + D 混合（战棋主体 + 卡牌子系统）

**条件**：MVP 验证后，若天赋树在 roguelite 层的"每 Run 节点选择"体验不够直观，可将 Run 内激活机制映射为"天赋卡牌"呈现，兼容 STS2 类玩家的熟悉感。卡牌层作为天赋树的 UI 变体，不引入独立的牌组构筑系统，避免 D 路径的 co-op 适配成本。

### 明确弃用：载体 C（ARPG）

**理由**：co-op 成本 2.2×（三载体最高）+ 美术量双杀 + 核心锚点需重构 + 中小团队历史失败率高（Wolcen）。技术风险与市场红海双重不利，与 solo dev 规模不匹配（B2.2 Godot 4 可行性 ★★☆☆☆）。

## 任务 D：Critic Guard List

**Guard 1：战棋 co-op 的"一人独断"问题**

- 描述：Into the Breach 社区明确指出格子战棋 co-op 会退化为"最强玩家发令，其他人执行"（B1.3）。战棋的优化解空间在完全信息下有限，4 人协作决策成为瓶颈而非乐趣。
- 失败后果：co-op 玩家体验分裂（强玩家主导 / 弱玩家空转），流失弱势玩家群体，4p 设计变成 1+3 人模式的变体。
- Fallback：为每名玩家设计"职责专属决策"（如 Sunderfolk 的角色专属行动权），确保 4 人中每人有独立的、不可替代的决策贡献，破解"最强玩家包揽"的动力学。

**Guard 2：天赋树 roguelite 解耦未验证**

- 描述：B1.2 明确："复杂 talent tree + roguelite + 战棋"的成熟商业设计迄今未见，是行业盲点。B1.2 失败模式 2 指出大天赋树导致"meta 已锁定，run 内选择变虚"——玩家在 meta 层确定方向后，run 内节点激活退化为微调确认，决策空间消失。
- 失败后果：天赋树变成数值强化工具而非策略层，roguelite 的每 Run 新鲜感丧失，差异化卖点空洞化。
- Fallback：采用 B1.2 模式 C（Monster Train Champion Spec）的 run 内递进解锁——每次战斗后从当前路径中随机呈现 3 个节点供选，而非全树开放选择。将大树的"可能性"转化为 run 内的"发现感"。

**Guard 3：4p co-op 平衡成本非线性**

- 描述：Ravenswatch 的 3→4 人难度跳跃（B1.3），以及 B2.1 中"STS2 4p Shared Relic 协商成本爆炸"的信号。战棋的 4 人数值 scaling（敌人 HP / 地图尺寸 / 技能 AoE）在 roguelite run 内每一关都需要独立验证。
- 失败后果：4p 模式平衡周期拉长，发布时仅 2p 体验良好，4p 有明显平衡漏洞，导致"co-op 测试不足"类评价（Jagged Alliance 3 的"偶有 desync"模式，B1.3）。
- Fallback：从设计起点确定 2p 为首要 co-op 模式，4p 作为扩展版本，允许分阶段发布（v1.0 = 2p co-op，v1.1 = 4p co-op）。

**Guard 4：Sunderfolk 数据窗口期风险**

- 描述：B2.2 明确 Sunderfolk 2.0 co-op 数据仅 3.5 周，"长期留存未知"。当前 94% 好评可能是发布蜜月期，60/90 天数据尚不存在。SoT 的整个战棋 + co-op 可行性论证高度依赖这一单点数据。
- 失败后果：若 Sunderfolk 出现与 Hadean Tactics（2045→10 CCU）相似的快速衰减，战棋 + co-op 的市场信号将被修正，SoT 主路径的市场可行性需重新评估。
- Fallback：在 R3 评估后 30-60 天内追踪 Sunderfolk CCU 数据；同时避免将 Sunderfolk 作为唯一正向数据点，关注 Frosthaven 1.0 发布后（2026 目标）的数据。

**Guard 5：天赋树"非确定版本"的设计漂移风险**

- 描述：用户明确备注 75 节点为个人探索结果，"可能加强玩法也可能需简化"。在设计未收敛的情况下，所有基于天赋规模的技术估算（平衡成本、开发时间、build 深度感）都会随设计漂移而失效。
- 失败后果：R2 评估结论基于错误的规模假设，导致资源预算错误（高估或低估平衡成本），后期重构代价高。
- Fallback：在开始全规模实现前，完成至少 1 个职业的完整 Tier 2 原型（30-40 节点），通过 5-10 次 roguelite run 内测验证天赋树与 run 循环的实际体验，再决定是向 Tier 1 扩展还是维持 Tier 2。

**Guard 6：Small grid × 复杂天赋的决策密度冲突**

- 描述：Into the Breach 的设计深度来自"完全信息 + 小网格 + 固定伤害"形成的谜题感（B2.1 Pattern F）。SoT 在同样的小网格基础上叠加 75 节点天赋树，可能导致战场决策（定位 / 攻击顺序）被天赋系统的心智负荷淹没。B1.1 的 Wargroove"单一正解"反弹案例说明，确定性本身不等于玩家满足——多解设计是必要条件。
- 失败后果：玩家感知"天赋系统太复杂 + 战棋太简单"或"战棋太复杂 + 天赋系统太多"，两个系统相互削弱体验，均无法充分发挥。
- Fallback：设计"天赋 - 战棋联动节点"——某些天赋效果直接改变战场信息结构（如 Immortal-Slaying Sword Formation 的领域控制），使天赋选择成为战棋决策的前置条件而非独立层级。

## 任务 E：开放问题 → 用户

**Q1：4p co-op 是核心锚点还是可选特性？**

B1.3 数据显示战棋 + 4p co-op 在 Steam 上极罕见（A 级样本 5-7 个），实现成本明显高于单人版本（1.7×）。如果 4p co-op 是"必须有"的核心定义特征，则需从第一天起驱动所有系统设计；如果是"如果可行就加"的可选特性，则可先做单人完整体验，co-op 作为后期扩展。这个决定会直接影响 MVP 范围定义。

**Q2：天赋树的"复杂"是目标感受还是目标规模？**

B1.2 指出"玩家感知深度可高于实际节点数"——Hades 2 的 25 张 Arcana 被玩家广泛评价为"足够深"。当前 75 节点的目标是：（a）产生足够多的有意义决策点让玩家感到"自主构筑了独特角色"，还是（b）实现超大节点数本身作为差异化卖点的展示？如果是 (a)，Tier 2（30-40 节点）可能已满足；如果是 (b)，则 Tier 1 是必要的，但需要接受对应的平衡成本。

**Q3：Town Building × 天赋树的 Gold 竞争是 roguelite 核心机制还是演化中的设计？**

talent-tree-design.md §7.2 描述了"天赋解锁 vs 建筑投资"的 Gold 竞争，并标注为"SoT 核心差异化机制"。但这一机制与天赋规模强耦合：Tier 1（75 节点）时 Gold 竞争有真实张力；Tier 3（20-25 节点）时 Gold 竞争会快速饱和，失去意义。请确认 Town Building 系统当前的设计状态（是否已有原型），以及它是否是 MVP 必须包含的范围。

### 假设需挑战

1. Sunderfolk 94% 好评（3.5 周数据）被用作"战棋 + 4p co-op 市场可行性"的主要正向证据，样本窗口过短，critic 应要求更长时间窗口数据或替代证据。

### 优化偏差热点

1. **载体 A 可能被偏好因为它是"最直觉的战棋"**，而非因为 4p co-op 在战棋语境中被充分验证——分析师倾向于"锚点匹配度高"这个更容易量化的维度，而轻视"4p 协作动力学是否真正在战棋框架内有趣"这个更难量化但更重要的问题。
2. **Tier 2 推荐可能是"中庸陷阱"**——30-40 节点的天赋树既不够小（无法有 Gunfire Reborn 的流畅感），也不够大（无法实现 SoT 核心差异化），可能是"两边都不满足"的次优解而非真正的甜点。
3. **ARPG（载体 C）被明确弃用的判断可能过早**——分析师基于 Wolcen 案例给出了强烈的反面信号，但未充分考虑 ARPG 作为"天赋修饰器载体"而非"完整 ARPG"的轻量变体路径（例如：仅保留 ARPG 的视角和流畅性，而非完整的装备 / 掉落系统）。
