# 遗物设计要点(Relic Design Principles)

> **读者 = 设计 SoT 遗物的 agent**。跨实体通用纪律见 [[content-design-general|内容设计通则]];本文只写遗物实体专属要点。放 `03-AI-Context/`,不进设计书面板、不同步 NAS。
>
> 库内当前 0 条遗物内容(实体功能先于内容交付)——本文先立结构原则;**首批内容设计前,先与用户对 archetype 配比与强度标尺**。架构权威 = [[architecture-consensus-v2|五层架构共识 v2]](L5);人类侧专属文档 relics-system.md 仍待落地(共识 Δ-2)。

---

## 1. 层定位(L5:核心 build-defining)

- 遗物 **6 格**,run 内获取(奖励 / 商店 / 事件)、run-reset;与 L2 转职选择强耦合——转职时玩家看已持遗物池决定方向。设计一件遗物,先想「它如何影响转职 / 加点决策」。
- 正典名 = **遗物 Relic**(ADR-010;Rune 为废案,新内容不得使用)。

## 2. 两类 archetype

- **经济类**:EXP / 属性 / 天赋点加速——作用于 L3 成长,幅度 stay-within-class-model(加速职业既有曲线,不越轨改形态)。
- **流派类**:改变职业形态 / L2 天赋节点行为(扩散燃烧、即时结算式)——build-defining 主力,与 L2 重要节点等价。
- 与 L4 装备的协同只做风味放大;把「流派改变」做进装备是层错配(通则 §2)。

## 3. 字段与结构

- 遗物是**全局实体**:无 `class_id`、无 tag 关联表;羁绊分组是**引擎侧概念**(`synergy_categories`,数组,≠ 天赋 tag 体系,两者不互通),设计库不存它。
- `rarity` 五档(普通 / 稀有 / 史诗 / 传奇 / 独特)与天赋 / 装备共用;`shelf_state` / `trashed_at` 软删。
- **设计库不存引擎数值副本**:引擎层字段在 Godot 仓维护,两侧之间没有回填管线——`engine_json` / `eng_*` 只读镜像已随 2026-07-27 用户裁决退役(通则 §9)。设计侧只写设计层字段。
- 字段的确切名称以设计库 app 当前实现为准(`/api/relics`;库内 0 条,暂无样本可对照)。

## 4. 设计约束

- **供给 = 人工管理**(通则 §10):审阅只提醒不阻塞,腾位裁量归用户。
- 6 格是稀缺槽位:单件强度定标须计入「占用 1/6 构筑空间」的机会成本;具体强度标尺待首批内容与用户共同确立。
- 流派类遗物改变 L2 节点 / 机制行为时,effect 须写明作用的机制锚点(所改的节点、术语或机制名),不泛写「强化所有 X」。
- 经济类幅度守住 stay-within-class-model:加速成长曲线,不改变职业成长模型本身。
- **资源系统每职业完全独立**(2026-05-25 用户裁决):剑气、法力、怒气等职业资源各自独立设计,不引入统一的资源抽象层。**禁止设计跨职业通用的「资源获取率 +X%」「资源消耗 −X%」类遗物**;确需影响资源的遗物,逐职业单独设计,并尽量避免。跨职业生效的遗物可以触碰属性、状态效果、行动经济,不触碰资源的累积与消耗率。
- **不做唯一 / 可叠加去重规则**(2026-07-05 用户裁决):遗物不设「唯一」或「可叠加」的去重机制。注意与稀有度第五档「独特」是两个概念。
- **品质非对称**(2026-07-05 用户裁决):遗物只用 `rarity` 分档;装备是 `rarity` 加品阶(`tier`,只给额外数值,尚未落地;见 [[equipment-design-principles|装备册]] §4)。
- **掉落先按稀有度分桶**(2026-07-05 用户裁决):掉落先按 `rarity` 分桶抽取。若实测单轮航程难以凑成羁绊,再评估「同羁绊掉落轻微优先」,当前不做。
