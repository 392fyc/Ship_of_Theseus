# 装备设计要点(Equipment Design Principles)

> **读者 = 设计 SoT 装备的 agent**。跨实体通用纪律见 [[content-design-general|内容设计通则]];本文只写装备实体专属要点。放 `03-AI-Context/`,不进设计书面板、不同步 NAS。
>
> 相关:[[01-Game-Design/Characters/class-system|职业系统]](槽位 / 武器类型 / 双持)· [[01-Game-Design/rules-catalog|规则总目录]];首批内容取材记录 = SoT-fyc-space `docs/fe-sword-weapon-import-2026-07.md`(临时工作文档)。

---

## 1. 层定位(L4:不承担 build-defining)

- 装备 = 随机捡取、run-reset、词缀 / 暗金模式;影响小→中;玩家无法围绕装备规划 build。**不得设计流派改变型装备效果**——那是 L5 遗物的领地([[architecture-consensus-v2|架构共识]] Δ-3 硬约束)。
- 装备 × 遗物协同只做风味放大(火属性武器 × 燃烧遗物),不承载核心 build。

## 2. 武器参数框架(R1.7,硬前提)

- `weapon_might` / `weapon_hit` / `weapon_crit` 三参数的唯一来源 = 所装备武器;职业不自带基础武器档案。
- 每单位恒持一件武器(不可卸、只可替换);**开局发给一件,不由职业预先绑定**(2026-07-21 用户裁决——原 `/api/classes` 的 `initial_weapon_id` 字段随之删除,职业数据不再指定具体是哪一件);敌方单位同口径发配。
- 武器不区分伤害类型(由技能 / 天赋 / 遗物声明)、不管理射程(射程归技能 / 天赋 / 遗物)。
- 属性键(STR / DEX 等)不属基础参数。**不另立词缀实体**(2026-07-29 用户裁决:武器特效挂 equipment 本身)——R1.7 正文里「归入词缀层」的说法指的是「不算基础参数」这层意思,不代表要建一张词缀表。
- 「装备加属性」目前**仍无结构化字段**(补的是特效字段,不是属性加成字段),此类效果继续占位;待其成为真实设计需求时再单独立项,别顺手塞进 `effect`。

## 3. 字段面与槽位

- Equipment 是**全局实体**(无 `class_id`):`name` / `description` / `rarity` / `slot` / `notes` / 三武器参数 + `shelf_state` / `trashed_at` 软删。
- **武器特效字段(2026-07-29 用户裁决「武器特效该挂在 equipment 上」)**:`trigger_event` / `trigger_object` / `trigger_source` / `trigger_condition` / `trigger_frequency` 五段 + `effect` + `rules` + `tags`。词汇表与**天赋**共用(`TriggerEvent` 23 条封闭枚举分 9 族),故特效的生效时机可校验、可检索,不再只是散文。
  - 与天赋的差异:装备**无**旧自由文本 `trigger`(从来没有过,无存量措辞要迁)。
  - **技能不在这套里**:技能一个 trigger 字段都没有,时机由 `resource_type` 与引擎侧 `timing_constraint` 表达。`target_mode`(目标选择方式)是技能专属,装备与天赋都没有——装备特效依附于携带者的攻击动作,不由玩家选目标。
  - `effect` 写特效本身、`rules` 写结算细节与规则引用、`notes` 写设计意图(玩家不可见)——职责同天赋,见文案规范 §六。
- 槽位体系(设计叙述,见 [[01-Game-Design/Characters/class-system|职业系统]]):通用两槽 = 主手(双手武器:剑 / 弓 / 魔导书,每职业限装对应类型)/ 护甲;另有副手,仅剑圣双持天赋解锁,属职业专属特例、不进通用槽位枚举。饰品槽已于 2026-08-09 作废。双持的核心收益来自天赋节点而非装备叠加(副手仅 50% 威力)。
- 口径注意:库内 `slot` 当前实际取值只有「武器」(22 件全部),护甲等其余槽位尚无实体;id 前缀由 slot 驱动(`eq_wpn_` / `eq_arm_`)。设计前以 `/api/equipment` 实际取值为准。

## 4. 稀有度分级(普通 / 稀有 / 史诗 / 传奇 / 独特)

- **主轴 = 有无特效**:普通制式武器(铁剑 / 钢剑级)不需要特效。
- **第二轴 = 数值强度**:同样无特效,数值显著高于同档制式武器的按数值强度拔高档位(例:银剑 might 13 定稀有,王者之剑 might 20 定史诗)。
- 不照搬外部作品自身的军阶 / 等级体系分档(军阶会把「有特效但军阶低」的武器错归普通档)。
- 原作特性已被数值字段表达的(高暴击 = `weapon_crit` 高值),notes 不重复写占位说明。
- **品质非对称**(2026-07-05 用户裁决):装备是 `rarity` 加品阶(`tier`),品阶只给额外数值;与上文按稀有度分的「档」不是一回事。`tier` 字段在设计库中尚未落地;遗物只用 `rarity`(见 [[relic-design-principles|遗物册]] §4)。

## 5. 特效的承载与占位纪律

- **特效写进结构化字段**(2026-07-29 起):特效本身写 `effect`,生效时机写 trigger 五段,结算细节与规则引用写 `rules`。**不再往 `notes` 里塞特效**——`notes` 只放设计意图。
  - 此前(2026-07-05 建表 ~ 2026-07-29)的纪律是「特效一律走 `notes` 占位」,当时装备只有 `description` + `notes` 两个散文字段。**库内 23 件装备的特效目前仍全部停在 `notes` 里、`effect` 为空**,回填是待办,不是已完成状态——读到 notes 里的特效说明属正常,不要当成错误数据。
- 仍未接入结算机制的效果(如射程类)照旧须**明确标注不生效**;标注写在 `rules`(玩家可见·查询向),不写 `notes`。
- 「对某类单位额外伤害」等需要新判定机制的效果 = 独立的规则新增,不倒推装备批次先行实装。
- **禁止跨职业通用的资源率特效**(2026-05-25 用户裁决,资源系统每职业完全独立):装备特效不得写「资源获取率 +X%」「资源消耗 −X%」这类对所有职业生效的条目;确需影响资源时,逐职业单独设计,并尽量避免。

## 6. 移植 / 取材纪律

- 外部作品数值必须联网核实,逐件记录来源 URL(不凭记忆填数)。
- 同一武器多作品数值不同时,取单一版本为唯一数值,不建重复条目。
- 促销码专属 / 与既有条目完全重复的项跳过;敌方专属改编为玩家可得时,须在 notes 注明改编。
- 来源作品的重量 / 耐久 / 射程等 SoT 无对应机制的维度不移植;若后续纳入,回取材记录逐条重新抓取。
