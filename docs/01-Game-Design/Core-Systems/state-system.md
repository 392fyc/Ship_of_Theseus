# 状态体系

## 定位

状态只回答一件事：一个单位当前是否处于某种状态。技能、天赋或规则负责说明状态从何而来、持续多久以及在什么条件下出现；状态本身不反向列出谁会使用它。

同名且含义相同的状态使用同一个身份。来源改变了触发门槛、持续时间、层数或强度时，不另建一个同名状态；这些差异保存在本次施加形成的状态记录中。其他内容只需判断单位是否持有该状态，不需要追查它由什么条件获得。

## 状态的内容

每种状态负责说明：

- 它是增益、负面、条件或其他哪些类别；类别可以复选，候选项可随设计扩充。
- 它能否被驱散，以及施加时是否需要计算抵抗。
- 它是否永久存在。非永久状态的具体持续时间由给予它的来源说明。
- 它包含哪些效果，每项效果在何时生效。
- 相同来源再次施加时如何处理：增加层数、延长时间、刷新时间、忽略新施加，或保留为独立记录。
- 层数改变时，各项效果如何随层数变化。

增益和负面状态都可以设为可驱散或不可驱散。驱散只按该字段判断，不以状态是正面还是负面作推断。

## 来源与状态记录

一次施加由来源单位、来源条目、目标单位和状态身份共同确定边界。

- 同一单位通过同一条目对同一目标重复施加同一种状态时，依照该状态的重复施加规则处理。
- 来源单位不同，或同一单位通过不同条目施加时，分别保留独立记录。
- 不同记录分别结算，不互相覆盖；结算顺序按它们加入目标的先后顺序。
- 来源单位死亡、离场或改变阵营，不会自动删除已经形成的限时状态；另有说明时除外。
- 状态栏可以把同一种状态的记录合并展示，但不同来源单位的记录不得合并。合并展示不改变各条记录的独立结算。

运行中的状态记录保存实际来源、目标、持续时间、层数、参数与加入顺序。设计库记录这些信息应当从哪里取得；游戏运行时保存每次施加后的实际结果。

## 生效时机与持续时间

状态的每项效果分别说明何时生效。可用的时机包括：

- 在状态持续期间一直生效；
- 获得状态时；
- 持有者回合开始时；
- 持有者回合结束时；
- 轮次开始时；
- 轮次结束时；
- 失去状态时。

同一状态可以包含多个效果，各自使用不同的时机。

非永久状态持续多久，由给予该状态的来源说明。回合或轮次中途获得的状态，在完整经历相应时段前不会减少持续时间。由条件维持的状态随条件即时出现或消失，不计算剩余回合。

## 免疫与抵抗

施加状态时先检查免疫，再检查抵抗。

- 状态或给予它的来源可以明确写明无视免疫；此时即使目标通常免疫该类状态，也可以正常获得状态。
- 对友方或自身施加增益时，通常不计算抵抗，但仍可能被免疫阻止。
- 是否计算抵抗由状态说明；是否无视免疫可以由状态或来源说明。
- 没有明确写明无视免疫时，不得绕过免疫。

## 单向连携

规则、技能和天赋可以：

- 给予一种状态；
- 以目标是否持有某种状态作为条件；
- 改变自己给予的状态记录中的数值、层数或持续方式；
- 改变获得某种状态的条件。

State 表不保存反向引用。删除或改名状态时，由设计库检查所有指向它的规则、技能和天赋；正文不能作为可执行关系的唯一依据。

## 文案边界

规则正文，以及技能或天赋中对规则的说明，都是未来面向玩家的语料。它们必须使用自然、完整、无需查阅内部资料即可理解的中文，不得出现内部字段名、实现步骤、机械化措辞，也不得用某个具体技能或天赋充当规则例子。

可执行关系与玩家文案分开保存。游戏不得从自然语言正文猜测状态身份、时机、持续时间或参数；缺少结构化记录时应停止导入并报告缺项。

## 权威边界

状态、类别、生效时机、效果类型、条件模型以及规则、技能、天赋到状态的连携，以设计库现行接口为结构化权威。本页记录用户裁决、设计理由和阅读口径，不复制设计库表结构作为第二份权威。游戏仓只记录已经落地的运行行为。
