## 1. 一次航程映射机制

基石第 6 节的一次航程七步，是玩家实际跑一轮 run 的叙事皮。逐步对齐机制环节如下 `[已定，对齐 run-loop 机制]`：

| 航程步骤 | 机制环节 | 叙事皮说明 |
|---|---|---|
| ① 认缆 | 角色选择 + 本轮 run 目标 | 在系缆柱前认下这一程要送的归乡（骨灰归乡 / 老兵回家 / 信鸽 / 家书），并点齐 1–4 名摇桨的乘员。委托＝run 目标的叙事皮。 |
| ② 落墨 | world-map 生成（本轮三幕） | 出航当日清晨图房落墨，画出横在港与目的海岸之间的三片水域＝本轮三幕。潮换答案就换（见第 3 节机理）。 |
| ③ 过水八站 | 一幕 8 关 + 门 + 商店 | 每片水域泊八站＝一幕八关；前七站过后瞭望手报出前方两三处去向＝每关后 2–3 扇门、奖励类型前置可见；跟潮的货郎船每片水遇两回＝商店每幕固定插入两次。 |
| ④ 泊夜 | 准备阶段 Preparation Phase | 把船拖上滩：烤船底养伤＝恢复；换船板 / 清点船舱（船舱＝运输队 Convoy 大背包）＝装备遗物替换；听传闻＝查看情报。恢复量只随开局难度档、run 内恒定、可按角色拒绝（背水流）。机制侧 Prep 在每站门后都有一次，泊夜是它的统一叙事皮（见循环嵌套）。 |
| ⑤ 过主 | 每幕第 8 关守门 Boss（Act Boss） | 每片水域深处坐着它的主人＝这片水的执念本身；**过主＝这片水的第八站，八站已含守关，其后没有第九站**。第三片水的主人正当执念涨潮，是本轮真正的终局关卡＝最终 Boss。守关＝疏浚而非斩杀（见 6.1）。 |
| ⑥ 送达 | run 通关结算 | 过完三片水、抵达目的海岸，把人送上他自己的家门。「到了家的人，亲手把船推回海里」＝一程报酬里最重的一份（对应终局的大额结算与 Boss 固定携带的特殊遗物）。 |
| ⑦ 轻归 | 战后返程 / 新一轮之间的呼吸 | 空船不招执，回程风平浪静一觉睡回港口＝送达之后无战斗的返程，是本轮回收与下一轮认缆之间的换气段。 |

**循环嵌套**：② 落墨与 ① 认缆每轮一次；③ 过水 → ④ 泊夜 → ⑤ 过主 三步随三片水域各跑一遍（幕 1 → 幕 2 → 幕 3）。**站间与幕间两级整备**：机制侧准备阶段 Preparation 在每站门后都有一次，泊夜是它的统一叙事皮；两片水域相接的拖滩处是其中最完整的一次大整备（幕间）。团灭＝船在海上碎了，走 Settlement 回元层重铸、图房重新落墨（基石第 5 节；非惩罚，死是天气）。`[已定]`

**门与商店的叙事皮细节** `[提案]`：瞭望手只报「看得见的」两三处去向（沉船 / 岸上火光 / 可疑平静水面），对应门上前置可见的奖励类型；具体货色要靠上去才知道，保住期待感（前七站过后各有一次报去向，第八站坐着守关）。事件门绝不连续两站＝海不会让你连着两回撞上无主的怪事。货郎船（跟潮的流动商贩）`[提案]` 是水域里**固定的非战斗商贸靠泊**——它与偶发的事件门那类无主怪事不同，是可预期、可上前交易的一处，并非水域里唯一的非战斗遭遇；每片水两回、嵌进泊夜，不占去向、不占一站，正如商店固定插入、不占门不占关。货郎卖的是这一汛能凑上的船板 / 器物 / 遗物（对应商店售**装备与遗物**，真源 `run-loop.md` 行 185）。

## 2. 越近岸水越凶 幕序难度递增的世界内解释

机制侧三幕难度自 Act 1 向 Act 3 递增（敌人 HP / 攻击倍率抬升、词条数量从区间下限走向上限、敌人阶梯组合上探；见 `run-loop.md` 难度缩放表与 `enemy-and-ai.md` 五层阶梯）。归潮之海给这条递增一个**世界内的解释，而非纯机制配平** `[提案]`：

- 执越重，漂得越近岸（基石推论 2）。图房把本轮通往目的海岸的水域按离岸远近排开，**离岸越近＝执越重＝越难**。所以幕序不是人为拔高的难度墙，是执重排序的自然结果。`[提案]`
- 第一片水离港最远、执最轻，是顺路的外海；第三片水抵在目的海岸的岸口，是当季执念涨到最满的那片——它的主人就是本轮最后要过的终局关卡。`[已定，承基石推论 2]`
- 执有潮汐（推论 3）：同一片浅滩这轮涨潮抵在岸口凶得像最后一关，下轮退回外海只是第一站。所以「难度递增」是**本轮此刻的执重排序**，不是给每片水钉死的固定难度——这为跨轮同一守关出现在不同幕位提供了世界内根据（见 6.1）。`[提案]`

> 机制对齐注：幕内难度还有第二根轴——开局难度档（类 Hades 热度，系统后置）。世界内它读作「这一汛整片海的凶险底噪」，与「离岸远近」正交：一个管本轮三片水的相对高低，一个管整轮航程的绝对深浅。`[提案]`

## 3. 抽幕机理 折处必淤与账簿式落墨

> **本节是本文的核心增强**，回应主审对基石「永远恰好三片」被判为凑设定的点名：给「为什么这一轮恰好是这三片、且难度递增、且第三片必是执念最重」一个世界内的机理，而不止是「港方落墨」的断言。措辞（折处必淤 / 淤口 / 账簿）可回退，机理骨架（读缝—称执—落墨）作为本文采纳的设计方案。`[提案]`

### 3.1 图房不发明航路，图房读缝

图房落墨不是凭空发明这一轮该走哪三片水，而是**读缝**。执如暗流，朝人想回去的海岸流动；在两片水域相接的**缝**处，水流转折。凡水流折处必淤——执在折处淤积，攒成一个**淤口**。一个淤口＝一片可泊的水域＝一幕的存在根据。图房手里那本账，记的就是通往各处海岸的缝上、此刻哪些淤口淤得最重。`[提案]`

### 3.2 账簿式选择器 三步落墨

图房落墨＝一次账簿式清点，可拆三步写实 `[提案]`：

1. **认海岸**：先看你认下的委托要送去哪片海岸（认缆已定，见 §1）。目的海岸定了，通往它的那条主缝也就定了。
2. **称执**：沿这条主缝清点缝上所有淤口，逐一称量本汛各自淤了多重的执。执重会随潮涨落，所以每轮称出来的数都不一样——这是「海图每天重画」的账簿版。
3. **落墨**：把称得最重的几个淤口按离岸远近排开，落成本轮的三片水域——离岸最近的那个淤口执最重，必定排在末位，成为第三片水、本轮最后的关。轻的淤口本汛不成幕，留待下汛。

由此，「随机抽幕」在世界内读作：**这一轮恰好淤在你这条主缝上、且淤得够重的，是这三片**。随机性不是第四面墙外的骰子，是站在图房桌前就能看懂的海况账。`[提案]`

### 3.3 为何恰好数片 且难度递增

- **为何是有限的几片、不是十片八片**：一条能行船的缝，在被执彻底淤死、整条不可航之前，只容得下有限几个可泊的淤口。再多淤一处，缝外的水就整片堵死、那片海岸本汛无路可达（＝本轮根本无法开局）。港方口头说的「永远恰好三片」，是对「一条可航缝的淤口上限」的顺口简称，不是世界强行规定的神圣数字。`[提案]` `[机制事实：幕数以 run-loop.md 的 3 幕×8 关为准，此处只给叙事解释，不锁数量]`
- **为何难度自港向岸递增**：账簿按执重（＝离岸远近）排序落墨，排序本身就把最重的执放在最靠岸的末位（见 §2）。递增是排序的自然产物，不是人为拔高。`[提案]`
- **第三片必是执念最重**：这不是剧本硬设的高潮，是账簿排序的末位必然——最靠岸＝执最重＝当季涨潮的那片。`[提案]`

> 这套机理只解释「图房怎么读出这一轮的水」，不改机制侧「3 幕×8 关、每幕第 8 关守关、第三幕末最终 Boss」的任何数字。`[提案]`

## 4. 幕池扩写 每次大的失乡多一片新水域

归潮之海的「幕池」＝**水域集**：这条海上所有可成幕的水域的登记册（事件场景池的归潮之海形态）。它天然可扩，靠两条世界内的口子 `[提案]`：

- **上新的口子（长账送达）**：疏浚一汛一汛磨掉执的分量，若终有一次把某位水域主人真正送回了家（彻底了结其执），这片水永久消散、主人退出名录，水域集腾出一个位置（基石第 7 节长账，`[已定]`）。**注：长账是纯叙事层的跨轮进展——它只推进「名录轮换 / 腾位」，绝不改动任何守关的战斗数值；机制侧 Act Boss 每轮以满状态重置，被疏浚打散的执随涨潮重新成形、却比上一汛更近归途一分（桥接见 §6.1）。** `[已定，机制事实：长账不改 Boss 战力]` 名录轮换＝下游 `legendary-and-enemies.md` 的登记职责，本文只承接「腾位」这一结构事实。
- **进新的口子（新的失乡）**：海上水域远不止眼下这几片，每年都有船队没能回来——**每一次大的失乡，海上就多淤出一片新水域**（新的执、新的缝、新的淤口）。幕池由这片海自己扩写，不需要设计者在世界外硬加一章。`[提案]`

**支持扩到十几片以上幕的机制含义**：水域集是一个「可长的登记册」，不是钉死的三章。每轮只从册中被本汛主缝淤出、且够重的淤口里落墨三片（§3），所以册子里纵有数十片水域 `[占位，具体规模以机制轮 map_pool 为准]`，每轮仍只呈现三片——**登记册规模与单轮幕数解耦**。这与机制侧「map_pool / battle_pools 可扩、单 run 仍是 3 幕×8 关」严丝合缝：往册子里加水域＝往池里加候选幕，不改动抽幕方式与单轮尺寸。`[提案]` `[机制事实：单 run 3 幕以 run-loop.md 为准]`

## 5. 水域集登记体例

每片水域＝一幕。登记册里每片水域的**最小字段**如下 `[提案]`（专名一律 `[提案]`，属用户裁决域；能描述就不硬造）：

| 字段 | 含义 |
|---|---|
| 水域名 | 描述性称谓优先（独眼牧岸 / 沉舰风暴眼），专名 `[提案]`。 |
| 主人（守关） | 这片水的执念本身，半神以下、英雄可击的量级（大名怪物 / 妖异），**绝不填主神与创世级**；对应机制侧守门 Boss。详细机制登记归 `legendary-and-enemies.md`。 |
| 认执（他放不下的那件事） | 一句话点明主人生前是谁、放不下什么——**主人的执就是他的打法**：这一句同时决定守关的签名机制方向，也决定杂兵（随潮的溺众）穿什么形状、一眼可读。 |
| 签名机制方向（只给色彩，不锁数值） | 由「认执」直接派生的一句叙事皮，指向机制侧的 Boss 独有机制方向；具体机制归机制轮。 |

**示例池**（承基石水域集，专名 `[提案]`，机制方向只示意色彩；每条守关均补一句「认执」以落到「主人的执就是打法」公式）：

- **塞壬浅滩**：认执＝她放不下「让每个人都听见自己的家」，要把旅人永远留在离家最近的那一刻。歌声唱每个听者自己的家乡，乡愁叠层，叠满的人丢下阵位朝歌走；堵耳可免、代价是听不见同伴。守关：塞壬长姊 `[提案]`。签名方向＝叠层诱导 / 站位控制。
- **独眼牧岸**：认执＝他放不下自家牧群与洞穴，认不得归船，把每一条靠岸的船都当成来夺走他仅剩之物的贼。守关波吕斐摩斯（瞎）`[提案]`，循声扑最响一格，投石引声、羊群掩护。签名方向＝声响索敌 / 掩体。
- **沉舰风暴眼**：认执＝他放不下那桩没能辩白的冤——归航途中被自己人处死，每夜把沉船那一晚重走一遍，想改写却永远改不动。守关沉舰统帅 `[提案，原型：归航途中被联军处死的将官]`，每回合重演沉船那夜一步，你在他的剧本里抢位活命。签名方向＝定时脚本 / 抢位生存。
- **在册候选（专名与细节 `[提案]`）**：食莲林湾、变形之岛（喀耳刻）、峡流双怪（斯库拉与卡律布狄斯）、风袋群屿（埃俄罗斯）、石像礁（美杜莎）、迷宫外海、蚀阳牧场、冥河河口……守门 Boss 名单允许与 Plan-1 重合（Medusa 等大名可用）`[已定，2026-07-24 用户裁决]`。

> **候选的认执与量级护栏** `[提案]`：候选池入册前，每条须补齐「认执」一句、落到「主人的执就是打法」公式，否则不成守关。其中带**神格锚点**的候选（蚀阳牧场＝日神的牛群、冥河河口＝冥界门槛、变形之岛＝喀耳刻）**一律钳在半神以下、英雄可制得住的量级**：守关**不得填同名主神本尊**（基石第 11 节「远方的神不下场」，`[已定]`），须落到该地的**执团 / 替身 / 幸存者**或**英雄可降伏的小神**一档——例如蚀阳牧场的守关是「替日神看守金牛群的太阳的牧女（Phaethusa 与 Lampetie）的执——守着一群永不能碰的牛、自己也被这份看守钉在岸上回不了家」，而非日神本尊（守关身份以 legendary-and-enemies 登记为准）；冥河河口是「困在门槛上、渡不过也回不去的摆渡执念」，而非冥王本尊；变形之岛的喀耳刻属**小神量级**，须以「英雄凭外援制服（如 moly 之助）而非斩杀」处理，恰好贴合疏浚非斩杀。纯自然之力型的候选也须给出人格化的「执」读法——例如**卡律布狄斯**不作无主的大漩涡，而读作「一位被罚永世吞海、再也上不了岸的女儿，她的执是把每一条路过的船都拖下去陪她」，如此才贴归乡母题；给不出人格化认执的候选，宁可移出体例演示池。

> 登记体例只立「每片水域填哪几栏」；具体每片填什么、名录如何随长账轮换，归下游 `legendary-and-enemies.md`。本文的示例池是**体例演示**，不是定稿名录。`[提案]`

## 6. 三条通用约束的幕结构落点

### 6.1 Boss 复战条款 疏浚非斩杀

同一守关为何能跨关、跨轮反复遭遇？世界内根据是基石第 7 节的**疏浚**：你在水域深处「打赢」主人，不是杀死他，是把他这一程淤起来的执**打散**、清掉暗流让水暂时通航。执有潮汐（推论 3），被打散的念想随下次涨潮回聚、主人重新成形。「这片海上没有斩杀，只有疏浚。」`[已定，承基石]` 落到幕结构：你每一轮面对的守关不是复活的尸体，是**又一次涨满的同一片执**——所以它可以这轮排作第三片水（当季涨到岸口、成为本幕守关），下轮退成第一片水（顺路的外海，仍是那片水的守关），也可以在不同 run 里反复出现，全无违和。`[提案]`

**长账桥接（承 §4，防下游误读）** `[已定，机制事实]`：疏浚打散的执随涨潮重新成形，但每一汛都被送近归途一分——这就是长账。**长账是纯叙事层的跨轮进展，只标记「离家更近」、只推进名录轮换，绝不改动守关的战斗数值**；机制侧 Act Boss 每轮以满状态重置，「重新成形却更近归途」两句并存不悖：战力每轮满值，归途每汛缩短。下游据此**不得**把长账读成「Boss 跨轮变弱」。

### 6.2 委托人失败规则 没送到的漂回港口等你

一轮失败 / 委托未送达（团灭）时，系缆柱上等的人**不会死、不会被清算**。依推论 5，海留不住「算了」：没送到的委托随潮漂回防波堤内，人与缆一起等下一条船（基石第 8 节，`[提案]`）。落到幕结构：团灭 → Settlement → 新一轮认缆时，委托人仍在系缆柱前，招呼如常，或许执略有偏移（细节微变、可重入委托池 `[提案]`），但绝无责难。这条专为防止连败被读成「愧疚清算」，与 Hades 式「重开非惩罚」调性对齐——潮还没对上而已，不是你欠了谁。对应港口伦理「海上不欠，岸上不留」。`[提案]`

### 6.3 高频杂兵 随潮的溺众

每片水域最常出现的普通敌人不是无名怪物，是**这片水的执下没回成家的人**（沉没船队的乘员、被本片浅滩的执留住的活人），穿着这片水的执的形状成群出现，是主人之执的延伸、一眼可读。

**世界内根据（承基石，镜像 6.1 分层）**：底层「执是这片海一切现象的通货、杂兵为何成群由执解释」为基石第 2 节 `[已定]`；「随潮的溺众＝由本片水的执赋形的没回成家的人」这一具体框架为基石第 9 节 `[提案]`。

**本文新增的幕结构落点** `[提案]`：杂兵的神话身份由**所在水域的「认执」字段**直接派生（见 §5 登记体例）——塞壬浅滩里是被歌声留住的听众，独眼牧岸里是迷途的牧群与船员。玩家进任何一站，看杂兵的形状就知道自己踩进了谁的执里。这解决了「只有 Boss 可读、杂兵是泛型填充」的空白：**杂兵与守关共享同一片水的母题**，可读性不靠额外背书。

## 7. 远景终点与再航 船长自身的归乡

为什么送完一个还要再航？近景：系缆柱上永远还拴着缆，送完一个潮水送来下一个，替别人回家是每轮的直接理由（基石第 10 节，`[已定]`）。远景：潮总有一天会把「这一船人自己的那片海岸」漂进图房的墨线里——送足够多人回家之后，船自己的归路才浮现（远景元目标，`[已定，2026-07-24 用户裁决]`）。

**船长定位（厘清）** `[已定]`：这条船没有一个恒定不变的「船长」角色。**船长＝每一程从当轮 1–4 名乘员里出任的那个玩家视角**，随认缆的队伍而变、随团灭重铸而换（乘员皆归途上的人，见基石第 5 节）。因此「船自己的归乡」不绑在单一个人身上——它是**这一船「有事要做的人」共同归途的落点**：一船人各有各的海岸，船的归途是这些归途在图房账里合成的那一道墨线。这与远景归乡相容：远景不是「某位固定船长终于回家」，而是「替人归乡替到足够多，这一船人自己的海岸才轮到被落墨」。

落到幕结构：远景归乡**不是第 4 幕、不是一块通关结算屏**，而是一道地平线——图房那本账里，始终有一个属于「这一船人自己的海岸」的淤口，只是它离岸最远、执最轻（因为你一直在替别人放下执、鲜少称量自己的），本汛从不排进落墨的三片里。直到长账磨到某个临界，它才第一次够重、够近，被图房落进墨线。这给循环一个人尺度的、极远的终点意象，而非大结局。`[已定，远景终点意象本身]`

**触发与呈现（可回退方案）** `[提案]`：给一个不重新引入宇宙级、始终守在人间层的落法——当累计送达达到某个阈值 `[占位，阈值以机制轮为准]`，某一轮落墨时，图房在照常排出的三片水之外，多描出一段**没有名字的海岸线**；那不是第四片可打的水，而是船自己的归途第一次浮现在墨线上，作为一道可望的地平线呈现。它不设守关、不加战斗内容、不召唤任何主神或创世级存在（量级钳制照旧，基石第 11 节 `[已定]`）。具体阈值、这段海岸线如何逐轮变清晰、是否可最终「靠岸」，均属用户裁决域 `[待定]`。

> **乘员命名制度注（不在本文裁决域）** `[待定]`：本文只说明乘员在世界观里是什么（归途上的手艺人、每程 1–4 人、可出任船长视角）；乘员**如何命名**（匿名代号制 vs 具名英杰）属下游 `crew-and-units` 的裁决项，且用户 2026-07-24 明确推迟再议、本轮不得自主定名。留档：前两波提案池集体倾向**匿名代号制**，与 Plan-1 英杰名裁决（梅林 / 罗兰 / 阿塔兰忒 / 贞德）存在方向冲突，待基座定型后另议。

## 8. 与 KB 已定机制骨架的关系

本文是**叙事口径**文档，不改机制侧任何数字，逐条对齐如下 `[已定]`：

- **3 幕×8 关、每幕第 8 关守关、第三幕末最终 Boss**：即三片水域、每片泊八站、第三片主人当季涨潮为最终关。数字以 `run-loop.md` 为准，本文只给叙事解释。
- **门 2–3 扇、奖励前置可见、事件门不连续、商店固定插入每幕两次**：即瞭望手报去向、货郎船每片水两回；货郎（＝商店）售装备与遗物（真源 `run-loop.md` 行 185）。
- **Prep（恢复 / Convoy / 情报 / 技能 / 建筑）**：即泊夜拖滩。恢复只随开局难度档、run 内恒定、可拒绝——世界内读作「烤船底养伤的火候只看整轮出航时定的底子」。
- **敌人五层阶梯（Normal→…→Act Boss 传奇 tier），机制无宇宙级 apex tier**：与量级钳制自洽——水域主人半神以下、英雄可击；「传奇」只是 tier 名，填塞壬 / 波吕斐摩斯 / 美杜莎皆凡人英雄制得住的对象。奥林匹斯主神、创世级绝不登场（基石第 11 节，`[已定]`）。
- **Settlement（团灭回元层）**：即沉船重铸——港口把团灭当天气，打捞队重新立船、图房重新落墨。
- **词条制两池（基础 / 特殊，进房前特殊可见）**：叙事上读作「这片水的执给敌人染上的脾性」；具体登记归机制轮与 `legendary-and-enemies.md`，本文不锁。

**下游同步待办（机制层，本文不实施）** `[待定，机制层]`：`run-loop.md` 的 world-map / 抽幕生成逻辑若采纳 §3 账簿式机理作叙事皮，无需改动机制（机理只解释、不改数），但幕池扩写（§4）与水域集登记（§5）需与 `map_pool` / `battle_pools` 的数据组织对齐——登记册的每片水域最终要能落成一组 map / wave / boss 配置。
