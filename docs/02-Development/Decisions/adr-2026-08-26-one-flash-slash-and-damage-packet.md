# ADR：一闪、斩击与伤害包的当前设计边界

- 日期：2026-08-26
- 状态：已接受
- 相关范围：一闪的两张回忆升级、入身、斩击及两张回忆升级、双刀追加攻击、伤害提升、附伤、伤害包与副手武器特效

## 背景

一闪与斩击的回忆升级改变了移动、目标、伤害段和资源结算单位。双刀体系又让同一次攻击动作中出现主手直接伤害、副手追加攻击、附伤和后续追加链。若不先固定这些层级，今后的增伤与附伤天赋会退化为难以区分的数值加法，多段技能也会因触发次数含混而失去构筑意义。

本 ADR 保存已经接受的定性边界。具体卡面文案、数值、结构字段与状态链接以设计库当前记录为准。

## 裁决

### 一闪的两个升级方向

〔浮光掠影〕把〔一闪〕升级为〔掠水〕。〔掠水〕由同一技能的两次连续独立使用构成：第一次完整结算后才能决定是否继续，期间不能插入其他行动；两次分别判定命中、暴击、伤害与触发事件，适用于一闪使用时的效果也可以在两次使用中分别触发。具体射程、伤害、消耗与冷却以设计库当前卡面为准。

〔如影随形〕把〔一闪〕升级为〔踏影〕。〔踏影〕先选择敌人，再选择其完整占据区域外正交相邻的合法空格并直接位移。合法落点取决于使用者自身的可站立规则，且不能被其他单位占据；大型目标的选择读取其任一占据格，落点则以完整占据区域为基准。直接位移忽略路径；该技能有位移标签，但不视为移动，不触发移动后事件。具体射程、伤害、消耗与冷却以设计库当前卡面为准。

### 〔入身〕由同名 State 承载

天赋达到移动条件后给予同名〔入身〕State，由该状态统一承载下一次攻击动作的强化与移除规则。同一攻击动作中的自身直接伤害段共享强化，附伤与其他效果产生的追加攻击默认不继承。

重复达到条件时由 State 自身的不可叠加规则处理，不再为天赋增加额外的每回合次数限制。状态的数值、抗性、驱散、免疫与持续字段以设计库当前记录为准。

### 斩击组按真实结算单位处理资源与触发

技能和普通攻击默认使用主手武器；只有效果明确说明时才使用副手。

〔斩击〕先完成直接伤害，再按卡面顺序结算印记与剑气。致命伤害不会取消这个伤害段已经成立的资源与击杀结算。

〔裂空〕在发动时锁定剑气区间，不能让多目标结算途中取得的剑气改变本次分支。需要支付的剑气先于伤害扣除；逐目标收益随对应主手伤害立即结算，固定收益则等待所有目标以及相关副手和追加链收束后统一结算。目标按由近到远的顺序处理；每次发动只取得一枚印记，范围覆盖多格单位时每个伤害段仍只结算该单位一次。具体数值以设计库为准。

〔连斩〕的每一刀都是独立直接伤害段，后续刀读取当时的当前状态并承受逐刀累积的命中降低。命中、暴击、造成伤害与资源按实际发生的每刀结算，但整次技能仍是一次动作。主手连段结束且目标仍存活后，整次攻击只产生一次基础副手追加攻击；任一主手刀暴击即可让这次基础副手追加攻击获得一次〔剑气回荡〕强化，多次暴击不会重复放大。

### 直接伤害段与附伤组成原子伤害包

每个直接伤害段与依附于该段的全部附伤共同组成一个伤害包。包内所有组成部分读取同一份结算前状态，各自保留伤害类型、来源、公式和对应减伤，但没有先后顺序；全部计算完成后统一改变护盾与生命并判断死亡。

一个伤害包至多产生一次击杀事件，归属于来源攻击者和本次动作。即使来源直接伤害没有造成实际伤害，只要包内附伤致死，仍正常产生击杀事件。需要来源先压低生命、击破护盾或改变状态后才生效的内容不是附伤，应作为后续独立效果。

每个独立直接伤害段及其直接触发完整结束后才判断死亡。目标死亡后，不再结算针对它的后续独立伤害段或效果；致命段自身应有的资源、状态和击杀结算不被撤销。

### 伤害提升、附伤与追加攻击必须保持差异

伤害提升只修改技能或攻击自身的原始伤害，不自动提高附伤或追加攻击。

附伤依附于每个符合条件的直接伤害段，沿用来源命中，默认不能暴击，也不继承来源暴击。附伤不另行产生命中、暴击或造成伤害事件，但可以与来源伤害共同产生一次击杀事件。附伤默认不能继续触发其他附伤或追加攻击；具体效果系数由设计库中的作用对象明确声明。

追加攻击是新的独立攻击，独立判定命中与暴击，并正常产生自身的命中、暴击、造成伤害和击杀事件。它是否携带附伤、触发武器特效或继续产生其他追加攻击，必须由产生它的效果明确声明。

### 双刀体系的开放节点与副手版本

〔二天一流〕开放副手槽和基础副手追加攻击。它按攻击动作而不是按主手伤害段触发，对每个攻击目标分别产生一次基础副手追加攻击；主手未命中不取消追加，目标已经死亡则停止。基础副手追加攻击正常产生自身的造成伤害事件，但默认不携带附伤，也不触发副手武器特效。

学习〔二刀开刃〕后，〔二天一流〕与〔燕返〕产生的副手追加攻击才可以携带附伤并触发副手武器特效。每把剑的武器特效必须另行声明副手版本，装备在剑圣副手时显示该版本；实际折算值与概率以设计库当前规则和各武器记录为准。附伤不能触发〔燕返〕，只有实际副手追加攻击的命中可以继续追加链。

### 数值组合校准暂缓

当前天赋数量不足以完成可靠的组合强度评估，因此本批只锁定结算关系，不以预防数值膨胀为由提前削弱已成立的联动。待样本充分后，以〔二天一流〕代表的双刀体系和〔连斩〕代表的多段体系作为两条基线，校准其他路线的天赋与回忆天赋。

## 依据

- 高频攻击若只得到普通增伤，无法体现附伤按段结算的构筑差异；相反，附伤若重复产生完整命中和造成伤害事件，会被多种附伤和事件天赋乘法放大。
- 原子伤害包消除包内虚构顺序，使来源伤害与附伤共享包前快照，同时保留伤害类型与减伤的独立处理。
- 追加攻击保持完整事件链，才能与普通数值增伤和附伤形成真正不同的设计空间。
- 多目标、多段、攻击动作与伤害段必须分别计数，不能依赖技能名字或玩家文案推断。

外部机制只用于验证风险，不替代本项目裁决：高频攻击的附伤折算可参考 [League of Legends 11.2 更新说明](https://www.leagueoflegends.com/en-gb/news/game-updates/patch-11-2-notes/) 与 [11.4 更新说明](https://www.leagueoflegends.com/en-au/news/game-updates/patch-11-4-notes/)；伤害效用的显式声明可参考 [Path of Exile：Damage effectiveness](https://www.poewiki.net/wiki/Damage_effectiveness)；同时伤害与统一死亡判断可参考 [Magic: The Gathering 规则变更说明](https://magic.wizards.com/en/news/feature/rules-changes-2009-06-10)。

## 权威边界

结构化技能、天赋、State、State 效果类型、状态链接和规则正文以设计库生产记录为准。本文只保存裁决理由、跨对象关系与后续校准方法，不描述 Ship 当前实现状态，不建立衍生技能关系，也不保存任务进度。
