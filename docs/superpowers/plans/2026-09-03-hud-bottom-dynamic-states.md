# 底部 HUD 运行时状态矩阵 Implementation Plan

> **Milestone：** `GHV-5-BOTTOM-HUD-DYNAMIC-STATES`
>
> **目标：** 复用 GHV-4 已通过的完整底部 HUD 组合，以三个 1280×720 状态验证长名称、极大数值、零护盾、行动资源容量与消耗、移动失效、数字冷却、次数和快捷键；不重复技能数量或三档缩放，不生成正式内容图标。

## 完成条件

- 三个状态覆盖容量 1／2／3、零护盾、保留剩余移动但失效、移动完全耗尽为 0、标准与迅捷行动的部分或全部消耗。
- 长职业名与玩家名保持单行省略，tooltip 保存完整运行时文字。
- 普通 `ValueText` 使用 8px；`999999/999999` 使用 7px 回退；同一组件从长值恢复短值时回到 8px。
- 冷却数字保持运行时文字，暗层 alpha 为 0.5；仅用无文件路径的运行时 mock 色块验证暗层下内容仍可辨认。
- 单字符、双字符和 `F1` 快捷键居中；次数按运行时状态显示或隐藏；不显示主动／被动文字或图形分类。
- 仅生成三张 1280×720 状态图，继续使用 20×20 压力棋盘、正式准入剑圣比例锚点和 GHV-4 五区组合。
- 不修改 GHV-4 的几何、九张既有截图、正式 `BottomDashboard`／`SkillBar`／`ActionResourceBar`、行动规则或遗物容量。
- 新增测试、受影响回归、截图、静态检查和独立只读审查通过。

## 三个状态

1. `capacity_1_ready_zero_shield`：剑圣 · fyc，Lv.12，XP 125/500，HP 78/120，SH 0/40；移动 6 可用；标准 1/1、迅捷 1/1；六个技能快捷键为 1、2、Q、E、R、F1，无冷却与次数。
2. `capacity_2_early_move_lock_long_values`：长职业名与长玩家名，Lv.999，XP／HP／SH 均为 999999/999999；移动剩余 7 但已失效；标准 1/2、迅捷 0/2；槽 1 冷却 2 且底层为 runtime mock 色块，槽 2 次数 3，槽 3 为可主动触发的被动且保留快捷键 Q。
3. `capacity_3_move_exhausted`：剑士 · 归航者，Lv.20，XP 450/1000，HP 34/100，SH 12/40；移动 0 且失效；标准 2/3、迅捷 1/3；槽 1 使用同一 runtime mock 色块但冷却归零，槽 2 隐藏次数。
