# 底部 HUD 整体组合纵向切片 Implementation Plan

> **Milestone：** `GHV-4-BOTTOM-HUD-COMPOSITION`
>
> **目标：** 在开发专用 Godot 画廊中，把已经通过结构与原子表面检查的角色、装备、技能、遗物、行动资源和结束回合组件组合成完整底部 HUD；验证 5／6／7 个技能、20×20 棋盘压力背景和 1×／1.5×／2×等比画面，不连接正式战斗状态。

## 完成条件

- 固定 476×108 的可复用技能栏组件只显示实际提供的 5、6 或 7 个技能：5、6 个为 64×64，7 个为 56×56，间距 8，整体居中。
- 五区按角色 226、装备 128、技能 476、遗物 278、结束 76 的顺序组合，区间距 8，总宽 1216；1280×720 基准位置为 `(32,596)`，底边距 16。
- 行动资源条保持 274×40，与技能栏和画面中线同为 x=640；其底边与底栏顶边间隔 6，因此基准位置为 `(503,550)`。
- 画廊背景绘制 20×20 个 64×32 菱形压力格，并延伸到 HUD 后方；这只是显示压力参数，不改变玩法地图上限。
- 1280×720、1920×1080、2560×1440 分别以同一 1280×720 逻辑画布的 1×、1.5×、2×输出；每种分辨率均覆盖 5、6、7 技能布局。
- 角色文字、等级、经验、HP、SH、快捷键、冷却和资源数值全部是运行时节点；不生成或烘焙技能、装备、血瓶、遗物内容图标。
- 不出现职业资源、道具面板、普通攻击、移动按钮、右下独立技能按钮或地图人物血条下 Buff／Debuff。
- 现有生产 `BottomDashboard`、`SkillBar`、`ActionResourceBar`、战斗刷新链、行动规则和 `RunState.RELIC_SLOT_MAX = 6` 不变。
- 新增测试与既有 GHV-1／2／3、GHA-1／2／3、准备流程回归通过；三档截图经人工检查和独立只读审查。

## 已确认勘误

`SPEC-AR-VERTICAL-001`：现行规格同时写了行动条 y=556、高 40、底栏 y=596、间隔 6，四者无法同时成立。底栏 y=596 由 `720 - 16 - 108` 唯一推出；保留已验收的 40 高行动条和 6 像素间隔时，行动条必须为 y=550。实现与测试采用 y=550，并同步修正规格文本。

## 边界

- 本 Milestone 是 Godot 开发画廊和组件组合证明，不是正式战斗 HUD 接线。
- 不生成新的视觉素材，不购买素材，不调用外部 API key。
- 不修改技能、行动经济、遗物容量或职业资源玩法事实。
- 用户视觉批准是后续正式生产接线的准入条件；技术验证通过不等于用户已经批准最终同屏效果。
