# 失效上下文泄漏与失效内容污染治理设计

日期：2026-08-23
状态：待用户审阅
范围：用户级 Codex 规则、Ship、SoT 设计库、SoT KB

## 1. 问题定义

本项目把以下两种现象定义为工程缺陷：

- **失效上下文泄漏**：已经被后续裁决取代、否决或删除的内容，仍进入作者代理、子代理、审查者或新会话的默认上下文。
- **失效内容污染**：上述内容被写入现行设计、玩家文案、代码注释、运行说明、测试说明、canonical、handoff 或活跃记忆，并继续影响后续判断。

“dangling negation”可以作为问题发现阶段的临时工作名，但不是已确认的通用研究术语。本设计使用上面两个项目术语。

治理对象是**完整命题的有效性**，不是单个否定词。旧名称、旧数值和旧流程即使用肯定句书写，也可能构成污染；“不可驱散”“没有合法目标时无法发动”等当前有效约束即使使用否定句，也必须保留。

## 2. 研究依据

1. OpenAI Model Spec 把较晚的同级修正视为对较早指令的取代；被取代的指令不再属于当前适用集合：<https://model-spec.openai.com/2025-02-12.html>。
2. RefuteBench 发现模型会随对话增长逐渐忘记用户反驳并恢复旧答案：<https://aclanthology.org/2024.findings-acl.818/>。
3. Belief-R 显示模型普遍难以根据新证据准确撤回旧推论，也可能发生过度更新：<https://aclanthology.org/2024.emnlp-main.586/>。
4. 无关上下文会降低模型准确率，提示模型忽略无关内容只能缓解问题：<https://proceedings.mlr.press/v202/shi23a.html>。
5. 长任务需要持续筛选上下文，默认上下文应保留最少且信息密度最高的内容：<https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents>。
6. 复杂要求拆成独立检查项比总体印象评分更可靠：<https://aclanthology.org/2024.findings-acl.772/>。

这些证据支持分层治理；它们不支持仅靠提示词或否定词扫描解决问题。

## 3. 目标与非目标

### 3.1 目标

- 用户修正后，后续输出和持久内容只使用当前有效结论。
- 当前任务无关的纠错经过不进入最终答复。
- 玩家文案、现行设计和执行说明不携带变更史。
- 历史裁决可以追溯，但不进入默认作者上下文。
- handoff 只传递当前结论、真实未决问题、必要证据与下一步。
- 检查流程保持有界，不能因审查意见无限扩大任务。

### 3.2 非目标

- 不建设通用知识图谱或全项目命题数据库。
- 不用关键词批量删除否定句。
- 不把 Git 历史、ADR、Research 或迁移夹具改写成现行文档。
- 不在每个任务中重复加载完整的历史否决清单。
- 不借清晰度维护重新评价玩法数值或设计方向。

## 4. 完整命题检查

检查单位由以下最小信息组成：

| 项 | 含义 |
|---|---|
| 主体 | 被描述的技能、天赋、状态、流程、字段或任务 |
| 断言 | 当前声称成立的行为、关系或约束 |
| 适用范围 | 玩家文案、设计说明、运行实现、历史记录或交接 |
| 当前依据 | 用户最新裁决、结构化权威、当前代码或有效合同 |
| 状态 | 当前有效、真实未决、仅历史 |

作者产物只允许“当前有效”和“真实未决”进入现行内容。“仅历史”只能进入明确隔离的历史载体。

## 5. 产物分区

| 产物类型 | 允许内容 | 历史内容处理 |
|---|---|---|
| 玩家文案、设计库现行字段 | 当前玩法事实与玩家必须知道的约束 | 禁止写入 |
| canonical、AGENTS、Skills、操作说明 | 当前执行合同与必要边界 | 指向 ADR 或 Git，不复述过程 |
| handoff、活跃记忆、任务卡 | 当前结论、真实未决项、下一步、必要证据链接 | 禁止携带已取代内容 |
| 代码注释、运行说明 | 当前不变量、失败语义、字段用途 | 删除改版经过和旧方案说明 |
| 测试 | 当前行为断言；兼容测试可保留明确标记的旧输入 | 只保留完成测试所必需的旧值 |
| ADR、Research、明确归档区 | 候选、否决理由、变更过程、证据 | 允许保留，但不进入默认读取链 |

一个否定性命题是否保留，使用单一判据：**删除它是否会改变当前行为、边界或用户理解**。会改变则保留；不会改变且只解释旧内容，则移出当前产物。

## 6. 三层治理

### 6.1 全局生成规则

用户级 Codex 规则保存简短的普遍行为：

1. 后续用户修正取代同范围内的旧结论。
2. 当前答复只包含完成本次目标所需的信息。
3. 已取代内容不得通过纠错回顾、对比说明或自我辩解重新进入输出。
4. 每句话必须承担当前事实、必要约束、真实未决问题、证据或下一步之一。
5. 持久化前按完整命题核对当前依据。

这组规则适用于新会话，不保存具体项目的旧方案文本。

### 6.2 项目产物合同

- Ship 项目入口保存简短的当前产物规则，不复制本设计全文。
- 设计库 canonical 保存结构化设计字段、生产写入和设计审计所需的专门边界。
- KB handoff 规则保存跨会话过滤要求和历史载体路由。
- 每处只保存自身需要执行的部分，避免 Spec Kit、Mercury 和项目规则重复堆叠。

### 6.3 持久化前语义闸门

每批变更只检查以下四类失败：

1. **旧结论复活**：产物声称已经被取代的命题仍然成立。
2. **历史混入现行内容**：旧名称、旧机制、旧流程或变更经过进入当前产物。
3. **无关纠错回顾**：文字与当前交付无关，只是在解释过去哪里错了。
4. **当前约束丢失**：清理历史内容时一并删掉了仍有效的行为边界。

闸门不评价风格偏好、玩法强度、架构优劣或任务范围外的其他问题。

## 7. 审查收束合同

### 7.1 冻结输入

审查开始前冻结：

- 本批允许修改的产物列表；
- 本批实际改动；
- 这些改动直接引用的当前权威；
- 本批已经识别的失效命题或旧名称 ID。

审查者不得扩展到全库搜索，也不得因为发现相邻问题而追加交付物。

### 7.2 固定检查规模

- 每批最多 12 个待处理命题，超过时必须在实现前拆批。
- 只安排一名独立审查者。
- 只进行一轮独立审查和一轮集中修正。
- 集中修正只处理该轮中违反四类闸门的发现。
- 修正后运行同一检查集确认关闭，不重新发起开放式审计。

如果一轮审查发现超过 12 个高置信问题，结果记为“任务拆分不足”，本批停止；主代理重新拆分后再派发，不允许审查者继续展开。

### 7.3 范围外发现

范围外问题只记录：位置、缺陷类别、需要的权威来源。记录中不复制旧方案正文，不在本批修复，也不自动形成新的阻断。

只有以下情况可以阻断本批：

- 当前改动会把失效命题写入现行产物；
- 当前改动删除了必要的现行约束；
- 当前改动依赖的权威事实无法确认；
- 当前改动超出冻结范围。

### 7.4 子代理任务卡

相关子代理必须获得相同的冻结范围和停止条件。审查者的任务卡明确写入：只核对四类失败、禁止提出范围外优化、禁止派生代理、不得把被否内容复述进修正文案。

## 8. 三库维护批次

### 批次 A：上下文入口

- 用户级 Codex 规则；
- Ship 项目入口；
- 设计库 canonical；
- KB handoff 指南和模板；
- 当前设计审计状态边界的冲突表述。

验收重点：新会话、子代理和 handoff 都只接收当前结论。

### 批次 B：设计库当前数据

- 仅处理已经确认的实体 ID 和字段；
- 日常对象遵守“待审阅、待优化”审计边界；
- 锁定内容只有在本规则导入形成具体矛盾时按明确 ID 进入；
- 草稿、待删除和已归档不审计、不参考；
- 生产写入执行 dry-run、逐项回读和快照流程。

验收重点：玩家字段和现行 notes 不含旧名称、旧机制或改版经过。

### 批次 C：Ship 当前实现说明

- 只处理已确认依赖旧文本的 `engine_note`、代码注释和相关测试说明；
- 当前运行行为不因清理说明而改变；
- 测试只断言当前不变量。

验收重点：实现解释能够仅依赖当前结构化事实和当前代码成立。

### 批次 D：KB 现行文档

- 从现行设计文档移除被排除方案、旧名称和墓碑提醒；
- 需要追溯的内容迁入 ADR、Research 或明确归档区；
- 默认读取链不包含历史区；
- handoff 不复制完成过程和旧纠错。

验收重点：现行文档只表达当前事实，历史仍可通过显式路径追溯。

## 9. 回归样本

固定使用六类小型样本，不建立全库语料评测：

1. 先提出方案甲，随后确认方案乙；现行产物只包含乙。
2. 经过三个无关轮次后生成同一产物，结果仍只包含当前结论。
3. 当前任务与旧纠错无关，最终答复不主动回顾纠错过程。
4. 当前有效的禁止性规则继续生效，但不被复制到无关产物。
5. ADR 可保存历史过程，玩家数据和现行设计不携带该过程。
6. 会话压缩、handoff 和子代理转发后重复上述边界。

每类只保留一个代表样本。失败时修正规则或模板，不追加相似样本堆积测试规模。

## 10. 验收标准

1. 新会话能够从用户级规则得到普遍清晰度要求。
2. 三库各自的默认入口只保存当前执行所需规则。
3. 已确认的高置信污染点按四个批次完成修正。
4. 正常的否定性玩法约束和输入防护没有被误删。
5. 六类回归样本全部通过。
6. 每批审查均满足 12 命题上限、单审查者、单轮审查和单轮集中修正。
7. 范围外发现没有扩大当前批次。
8. 三库提交、PR、合并和必要的设计库生产回读证据完整。

## 11. 当前只读盘点形成的首批候选

以下仅定义后续计划的输入，不在本规格阶段修改：

- 设计库：现行天赋中的旧技能显示名、改版前机制 notes、纯改名史；
- Ship：与上述实体对应的 `engine_note`、依赖旧文案的代码注释和测试说明；
- 设计库 canonical：失效协作流程和历史裁决正文；
- KB：斩击回忆升级、天赋体系、内容设计通则、handoff 指南与模板中的现行/历史混合内容。

每个实现批次仍需重新核对目标 HEAD、当前权威和冻结实体 ID，不能把本次只读结果当作未来永久事实。
