# 剑圣战棋棋子正式导入设计

日期：2026-08-28
状态：已批准
Milestone：VA-4
范围：将已确认的剑圣 `clean_v2` 静态棋子导入真实 `TacticalScene`

## 1. 阶段成果

剑圣在真实战棋场景中使用已批准的正式棋子素材，能够按四个菱形格方向显示单武器或双武器静态状态；人物脚底中心落在所在格中心，单位之间按脚底纵向位置正确遮挡。其他职业继续使用现有占位显示。

Milestone 只有在实现、自动验证、Godot 实机截图、独立审查、用户视觉验收、PR 合并和合并后核验全部完成后才算完成。

## 2. 决策边界

以下事项由用户裁决：

- 美术方向与最终视觉验收；
- 素材购买、使用权与正式生产准入；
- 游戏体验、玩法意图和范围变化。

以下事项由 Agent 依据仓库约束、一般游戏项目实践、Godot 官方文档和独立审查自主决定：

- 文件结构、组件边界和数据格式；
- Godot 节点、图集切帧、加载、降级和测试方式；
- 不改变体验且不扩大范围的兼容处理。

只有技术选择会改变游戏体验、素材身份、权利范围或 Milestone 范围时，才交回用户裁决。

## 3. 已确认素材合同

正式导入对象只包含以下精确文件身份：

| 项 | 当前事实 |
|---|---|
| 原型源文件 | `assets/prototype/visual_style/samples/map_token_source_transparent_clean_v2.png` |
| 正式文件 | `assets/units/kensei/map_token_clean_v2.png` |
| SHA256 | `e6f33324c52929769d4698ed75e969470ec45748788503f4637fcb3223dc5415` |
| 图像 | `1536×1024` RGBA，真实透明 |
| 图集 | 4 列 × 2 行；每帧 `384×512` |
| 行顺序 | `single_weapon`、`dual_weapon` |
| 列顺序 | `NW`、`NE`、`SW`、`SE` |
| 显示比例 | `0.15625` |
| 纹理过滤 | `Linear` |
| 目标格 | `64×32` 菱形格 |

八组人物中心点按行优先顺序记录：

| 变体 | NW | NE | SW | SE |
|---|---:|---:|---:|---:|
| 单武器 | `(205.9, 397.0)` | `(194.0, 398.5)` | `(178.5, 408.5)` | `(178.0, 407.5)` |
| 双武器 | `(203.4, 350.0)` | `(198.8, 347.5)` | `(173.5, 365.5)` | `(182.2, 364.0)` |

中心点的横向依据是忽略武器、刀鞘和披风延伸后的人体轴线；纵向依据是双脚接地点中点。正式导入必须复制原字节，不裁切、不缩放、不重新编码。用户已批准该精确 SHA256 文件进入正式人物素材目录并仅绑定 `kensei`。

当前来源证据为：

- Ship 原型清单 `assets/prototype/visual_style/sample_manifest.json`；
- 固定 KB vault 的 `04-Assets/visual-style-decisions.md`，读取版本 `d4185e`；
- 2026-08-28 用户对正式生产准入、仅绑定 `kensei` 和初始朝向规则的确认。

原型清单继续承担来源审计，不作为正式运行时依赖。实施时更新其中该精确文件的生产准入记录，使其与当前用户裁决一致。

## 5. 架构

### 5.1 正式显示配置

新增 `data/visual_profiles/kensei_map_token.json`，以 `id` 注册到 `DataLoader.visual_profiles`。配置保存：

- 正式纹理路径和 SHA256；
- 原图尺寸、图集行列和帧尺寸；
- 变体顺序、方向顺序和八组人物中心点；
- 显示比例、纹理过滤方式和目标格尺寸；
- 固定的血条与弹出信息锚点。

本素材八帧在人物中心点对齐并缩放后的不透明像素联合上沿为 `-51.484375`。配置中的 `overhead_layout` 固定记录：

| 字段 | 值 | 用途 |
|---|---:|---|
| `opaque_union_top_y` | `-51.484375` | 自动测试核对素材透明边界 |
| `health_bar_bottom_y` | `-58.0` | 血条底边；等于联合上沿向负方向取整后再留 6 像素间距 |
| `popup_anchor_y` | `-82.0` | 正式棋子的伤害飘字与预估数字锚点 |

血条高度保持现有 16 像素，因此其顶边为 `-74.0`。行动资源徽记继续使用现有脚下位置，不属于头顶布局。

`data/classes/kensei.json` 只新增 `map_token_profile_id` 引用，不内嵌纹理路径和坐标。这样职业数据声明使用哪套显示，显示配置独立维护机械参数。当前只有 `kensei` 获得该字段。

`DataLoader` 只增加一个与现有 JSON 目录加载模式一致的 `visual_profiles` 字典，不增加编辑器、热加载或批量素材管理能力。

### 5.2 棋子显示组件

新增 `scripts/units/map_token_view.gd`，挂载到 `Unit.tscn` 内独立的 `Sprite2D` 子节点。该组件只负责：

- 校验并载入显示配置和纹理；
- 按 `facing × dual_wielding` 选择图集帧；
- 将当前帧记录的人物中心点对齐到 `Unit` 原点；
- 应用显示比例和 `Linear` 过滤；
- 暴露配置成功、状态刷新和降级所需的最小接口。

现有 `AnimatedSprite2D` 继续作为占位显示。正式配置成功时隐藏占位图；配置缺失、字段非法或纹理无法载入时记录包含单位与配置 ID 的错误，隐藏正式棋子并保留占位图。加载失败不得阻止单位生成和战斗流程。

`Unit` 继续拥有玩法状态，只把当前朝向和 `is_dual_wielding()` 的即时结果传给显示组件。不得复制或改写现有双持判据。

### 5.3 朝向与装备状态

正式方向使用以下网格到屏幕映射：

| 网格移动 | 屏幕方向 |
|---|---|
| `x-` | `NW` |
| `y-` | `NE` |
| `y+` | `SW` |
| `x+` | `SE` |

`TacticalManager.spawn_unit()` 增加保持兼容的可选初始朝向参数，合法值只有 `NW / NE / SW / SE`，缺省为 `SE`。`TacticalScene` 的生成配置允许可选 `facing` 字段，当前测试场景中的剑圣明确填写 `SE`；旧配置和注入配置缺省时仍为 `SE`。

当前移动使用终点减起点得到方向差值。差值同时包含 X、Y 分量时继续沿用现有规则，固定为 Y 轴优先：先判断 `y- / y+`，只有 `y == 0` 时才判断 `x- / x+`。单位开始移动时更新朝向；移动结束后不恢复通用 `idle` 方向，而是保持最后一次非零移动方向。装备或卸下副手时立即用现有 `is_dual_wielding()` 刷新显示。初版不根据阵营、敌人位置或攻击目标自动转向。

### 5.4 对齐、单位状态界面与遮挡

`Unit` 根节点继续位于 `Grid.grid_to_world()` 返回的菱形格中心。棋子组件把每帧人物中心点平移到根节点原点，因此武器长度和披风延伸不会参与人物居中。

正式棋子不应用占位图的阵营染色，也不显示占位职业文字。回合结束造成的整单位变暗仍属于现有玩法反馈，不在本阶段移除。

`MapTokenView` 校验并暴露配置中的 `overhead_layout`，`Unit` 负责把血条和生命值文字放到对应固定坐标。不得按当前方向逐帧改变高度，以免切换方向时跳动。既有通用状态显示继续使用 `STATUS_BADGE_Y=-58` 基线；它不构成 VA-4 的视觉验收。

`Unit` 同时提供正式伤害飘字与预估数字的世界坐标锚点。正式棋子使用 `popup_anchor_y=-82.0`；占位单位继续保留原有锚点行为。`TacticalManager` 在实际伤害、未命中提示和预估目标数据中使用单位提供的锚点；`TacticalScene` 对已经提供最终锚点的预估数据不再额外减去固定 30 像素。弹出节点仍由现有独立弹出层与预估界面层负责绘制，不改变其界面层级。

`TacticalScene.tscn` 在 `HighlightLayer` 与 `PopupLayer` 之间增加 `UnitLayer: Node2D`，启用 `y_sort_enabled`。`TacticalManager` 把所有单位生成到该层，单位根节点脚底位置越靠下越显示在前面。`PopupLayer` 保持更高 `z_index`。

这一设计依据 Godot 4.6 的 `CanvasItem.y_sort_enabled` 和 `Sprite2D` 图集帧、偏移与过滤能力：

- <https://docs.godotengine.org/en/4.6/classes/class_canvasitem.html>
- <https://docs.godotengine.org/en/4.6/classes/class_sprite2d.html>

### 5.5 死亡与降级

正式棋子没有死亡动画。正式显示启用时，死亡流程直接完成现有死亡信号、网格移除和节点释放，不等待 `animation_finished`。占位显示若存在死亡动画可继续播放；任何缺失动画的路径都必须安全释放，不得挂起。

## 6. 数据流

1. `DataLoader` 加载职业与显示配置。
2. `TacticalScene` 把 `class_id`、格坐标、阵营和可选朝向交给 `TacticalManager.spawn_unit()`。
3. `TacticalManager` 在 `UnitLayer` 下实例化单位，并把职业数据与初始朝向交给 `Unit`。
4. `Unit` 根据 `map_token_profile_id` 取得显示配置。
5. `MapTokenView` 校验配置并载入正式纹理；成功则隐藏占位图，失败则保留占位图。
6. `Unit` 从已校验配置取得固定头顶布局，布置血条，并向实际伤害与预估流程提供世界坐标锚点。
7. 移动方向或副手装备状态改变时，`Unit` 通知 `MapTokenView` 刷新静态帧。
8. `Unit` 根位置始终由网格系统决定，显示组件只做帧内人物中心点偏移。

## 7. 验证设计

### 7.1 素材合同测试

新增聚焦测试，验证：

- 正式文件存在且 SHA256 精确一致；
- PNG 为 `1536×1024` RGBA 并包含透明像素；
- 配置声明 `4×2`、`384×512`、八组中心点、`0.15625` 和 `Linear`；
- `kensei` 正确引用配置，其他职业没有被批量绑定；
- 正式运行时路径不引用原型清单。

### 7.2 组件行为测试

验证：

- 四方向映射和单双武器共八种帧坐标；
- 多轴移动差值按 Y 轴优先得到唯一朝向；
- 每帧人物中心点落在组件原点；
- 初始朝向缺省为 `SE`；
- 移动后保持最后朝向；
- `equip_offhand()` 与 `unequip_offhand()` 立即切换帧；
- 正式棋子不继承阵营染色，且占位职业文字隐藏；
- `overhead_layout` 数值与八帧不透明像素联合上沿一致；
- 正式棋子的实际伤害、未命中提示和预估数字使用固定弹出锚点，且占位单位保持原行为；
- 配置或纹理失败时使用占位显示；
- 正式棋子死亡不等待不存在的动画。

### 7.3 真实场景测试

通过真实 `TacticalScene` 验证：

- 剑圣根位置与 `64×32` 菱形格中心一致；
- 相邻单位按脚底纵向位置正确遮挡；
- 血条、生命值、伤害数字和弹出信息不覆盖关键人物区域；
- 注入模式和旧三参数 `spawn_unit()` 调用保持兼容；
- 现有受影响的战棋、剑圣和运行循环测试继续通过。

### 7.4 视觉证据

从真实 `TacticalScene` 输出：

- 单武器四方向；
- 双武器四方向；
- 至少一组相邻单位遮挡；
- 至少一张包含血条和弹出信息的场景图。

审核图使用游戏实际显示尺寸与适度放大版本，不使用八倍最近邻放大。截图必须在会话中直接显示，并同时提供可访问的绝对目录。

若当前 Godot 安装版本与项目要求不兼容，先升级到兼容的 Godot 4.6 版本，再运行验证。
