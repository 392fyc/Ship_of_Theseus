# 批量战斗模拟

用引擎无界面批量跑完整战斗，双方都由 AI 行动（用户 2026-10-31）。目的是检查 AI 是否合理、技能机制是否符合预期、有没有自叠加或矛盾、资源循环怎么构成；数值只作参考。

## 运行

```bash
<Godot 4.6 控制台版> --headless --path <worktree> --script res://tools/sim/battle_sim.gd -- --out=<输出目录> [--seeds=N] [--only=<阵容 id>] [--memory=<回忆 id 或 base>] > <输出目录>/godot.log 2>&1
python tools/sim/analyze.py <输出目录>
```

- 场景配置在 `scenarios.json`：地图、玩家单位、4 套哥布林阵容、每种配置的种子数、回合上限与几个检测阈值。
- 回忆覆盖：`memory_target` 的玩家单位先跑一次不兑现（`base`），再把 `memory_class` 的每张回忆各单独兑现一次。
- 输出目录放在被忽略的 lane 工作区（`.sot/lane-work/<lane>/sim/`），不进版本库。

## 输出

- `battles.jsonl`：每场一行。结果（victory、defeat、stalemate、timeout）、回合数、种子、回忆是否真的兑现，以及每个单位的伤害、反击伤害、承伤、成功与失败的动作次数、剑气按来源的增减、被上限截掉的剑气、持有状态顶到上限的回合数、额外回合数、空闲回合。
- `actions.jsonl`：每个 AI 动作一行。回合、行动单位、动作、目标与目标剩余生命、目标是否〔影〕、是否成功、这个动作期间造成的伤害与反击伤害、剑气变动次数。
- `events.jsonl`：异常事件。
  - 越界：生命、护盾、剑气、印记、持有状态层数、冷却。剑气、印记、层数、不可叠加的状态在写入时就会被截断，所以这几项多半查不出问题；叠加和溢出要看「被截掉的剑气」「顶到上限的回合」和下一条。
  - 重复触发：同一个动作里同一来源的剑气变动超过 `repeat_trigger_threshold` 次。
  - 单回合动作过多、同一轮额外回合超过 `max_extra_turns_per_round`、回忆没有兑现。
  - 回合结束时普攻射程内有非〔影〕敌人却没有出手（被眩晕、冰冻的回合不算）。
- `summary.json`：`analyze.py` 的汇总；另把 `godot.log` 里的 Godot 报错与警告归到具体战斗。

## 口径与局限

- 双方用同一套敌人 AI（`EnemyAI`）。它不会用位移技能和先选敌人再选落点的技能（一闪、踏影等），不会刻意规划迅捷动作或形态切换。统计反映的是「这套 AI 能打出的循环」，不是设计上限；依赖这些技能的回忆记录为 0 次，不代表回忆没有效果。
- 伤害归属：动作进行中打到对方的算行动单位；打到行动单位一方的算反击，记给这次动作的目标；不在任何动作里的伤害（持续伤害等）只记承伤。〔影〕照做的伤害算主人的。伤害量含被护盾吸收和打死后溢出的部分。
- 空闲判定在回合结束信号里同步完成；顶到上限的持有状态与越界检查推迟到同一帧末尾，在引擎的回合结束处理之后。
- 「被截掉的剑气」是近似值：按拦截器与阴阳调和改写之前的请求量计算，阴阳调和额外加的部分被截掉时不计入，拦截器把请求改小的部分会被误算成截掉。
- 「重复触发」只看动作进行中的剑气变动，阈值至少取这次动作里受伤的单位数（范围技能每命中一个可以各触发一次）；回合开始、回合结束时的连锁不在检查范围内。
- 「顶到上限的回合」只统计上限大于 1 的持有状态。
- 只有一张地图、一组固定站位，每种配置默认 5 个种子，样本量小。
- 演出等待按 `time_scale` 加速，不影响结算；同一种子与配置可以复现同一场战斗。
