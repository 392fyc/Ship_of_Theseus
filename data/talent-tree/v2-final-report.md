## 3. 推荐排名

### 第一推荐: Version C — Resource Cycle

**理由:**
1. **最直觉**: "打攒资源放技能"是最容易理解的游戏循环
2. **最低实现风险**: 不需要新的状态机(Overwatch)或标签系统(on-hit)，主要是数值调整
3. **最佳节奏控制**: 3-5回合的充放循环自然创造战斗节奏感
4. **普攻永远有价值**: 资源不足时普攻是唯一选择，资源充足时高资源增益让普攻也很强
5. **与现有量谱系统最兼容**: 只需调整获取/消耗数值，不需要新的游戏机制

**风险:**
- 数值平衡敏感(回充过快→技能spam；过慢→空转)
- 击杀退款机制可能破坏循环
- "纯充能回合"可能感觉无聊(需要高资源阈值奖励来补偿)

### 第二推荐: Version A — On-Hit Engine

**理由:**
1. **普攻体验最丰富**: on-hit链让每次普攻都有大量视觉/数值反馈
2. **最深的build深度**: on-hit效果叠加组合创造多样化build
3. **追击系统发挥最大**: 追击=完整on-hit链，高SPD角色价值最大化

**风险:**
- on-hit链的视觉表现需要额外开发
- 多重on-hit效果的优先级/叠加规则需要严格定义
- 双刀×2 on-hit可能数值过强

### 第三推荐: Version B — Overwatch/Stance

**理由:**
1. **最独特的战术体验**: 待机+反应式攻击在战棋RPG中少见
2. **居合架势设计最佳**: 不动→超强Overwatch的风险收益抉择最有深度
3. **与战棋地图互动最强**: Overwatch让位置选择更有意义

**风险:**
- Overwatch触发时机实现复杂(需要在敌方移动中插入判定)
- 多次Overwatch的性能开销
- 被动等待可能让玩家感觉"不够爽"
- 与现有反击系统可能冲突

## 4. 混合方案建议

如果不采用单一版本，推荐以 **Version C 为基础**，融合 Version A 的部分设计：

| 融合点 | 来源 | 具体做法 |
|--------|------|---------|
| 资源循环骨架 | C | 普攻=主要回复，技能=消耗 |
| on-hit标签 | A | 部分关键被动节点标注on-hit触发条件 |
| 居合蓄势 | B | 保留为swift技能，但效果改为"资源回复+50%" |
| 高资源阈值 | C | >50/70/80/90各有被动加成 |
| 技能不触发追击 | A | 保护普攻的追击独占优势 |
